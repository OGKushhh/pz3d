    35→    35→    35→## Grammar at a glance
    36→    36→    36→
    37→    37→    37→A `.mog` file is a sequence of nodes. Every node shares the same shape:
    38→    38→    38→
    39→    39→    39→```
    40→    40→    40→kind ["optional name"] [(attr=value, ...)] [{ child_nodes... }]
    41→    41→    41→```
    42→    42→    42→
    43→    43→    43→- `kind` is an identifier like `box`, `cylinder`, `group`, `scene`, `material`, `joint`, …
    44→    44→    44→- `name` is a quoted string. Some kinds require it (`material`, `module`, `joint`, `clip`, `connector`); most geometry kinds treat it as optional — when omitted the node's name defaults to its kind.
    45→    45→    45→- `attr_list` is a comma-separated `key=value` sequence in parentheses.
    46→    46→    46→- `block` is a brace-delimited list of child nodes.
    47→    47→    47→
    48→    48→    48→Comments run from `//` to the end of the line. Whitespace between tokens is
    49→    49→    49→insignificant. The top of the file may contain `import`, `material`,
    50→    50→    50→`module`, `joint`, and `clip` declarations; `scene { ... }` holds the
    51→    51→    51→geometry itself.
    52→    52→    52→
    53→    53→    53→---
    54→    54→    54→
    55→    55→    55→## File metadata: `meta`
    56→    56→    56→
    57→    57→    57→An optional top-of-file block recording author-facing metadata about the
    58→    58→    58→asset. Place at most once, before `material` / `scene` / `module`.
    59→    59→    59→
    60→    60→    60→```
    61→    61→    61→meta (
    62→    62→    62→  name = "wooden_chair",
    63→    63→    63→  version = "1.2.0",
    64→    64→    64→  description = "A simple four-legged dining chair.",
    65→    65→    65→  tags = ["furniture", "chair", "wood"],
    66→    66→    66→)
    67→    67→    67→```
    68→    68→    68→
    69→    69→    69→| attr | type | source | notes |
    70→    70→    70→|---|---|---|---|
    71→    71→    71→| `name` | string | author | human-readable asset name |
    72→    72→    72→| `version` | string | author | semver-style is conventional but not enforced |
    73→    73→    73→| `mogen_version` | string | **toolchain** | auto-stamped on every save. Don't write it yourself. |
    74→    74→    74→| `description` | string | author | one-line summary |
    75→    75→    75→| `tags` | list of string | author | free-form labels |
    76→    76→    76→| `style` | string | toolchain | visual-style hint from `mogen generate --style …`. Suggested values: `ps1`, `n64`, `low_poly`, `high_detail`, `arcade`, `voxel`, `cel_shaded`, `stylized_fantasy`, `cyberpunk`, `pixel_art`. Validator accepts any string; survives `modify`/`animate`/`repair` |
    77→    77→    77→| `seed` | string | toolchain | random seed from `mogen generate`/`modify`; round-trips through edits |
    78→    78→    78→| `thinking` | string | toolchain | per-file Gemini thinking budget stamped with `seed`; survives `modify` |
    79→    79→    79→| `prompt` | string | toolchain | original NL prompt; round-trips through `modify` so the LLM can revise against original intent |
    80→    80→    80→| `moghub_model_id` | string | toolchain | stamped by Studio's Publish after a successful MoGHub upload |
    81→    81→    81→| `moghub_slug` | string | toolchain | MoGHub slug, paired with `moghub_model_id` |
    82→    82→    82→| `moghub_version` | string | toolchain | last-published MoGHub version, paired with `moghub_model_id` |
    83→    83→    83→
    84→    84→    84→The block is informational — not consumed by the geometry pipeline. It
    85→    85→    85→survives lowering on `SceneGraph::meta` for downstream tooling. Old files
    86→    86→    86→without `meta` keep building; the toolchain inserts a fresh
    87→    87→    87→`meta (mogen_version = "...")` line on next save.
    88→    88→    88→
    89→    89→    89→Diagnostics: `E0310` (no body block), `E0311` (no quoted name — use
    90→    90→    90→`name=`), `E0312` (duplicate), `E0313` (must be top level), `W0107`
    91→    91→    91→(`mogen_version` mismatch).
    92→    92→    92→

    95→    95→    95→## Global settings
    96→    96→    96→
    97→    97→    97→Top-level directives that tune the build itself.
    98→    98→    98→
    99→    99→    99→| directive | value | effect |
   100→   100→   100→|---|---|---|
   101→   101→   101→| `lod_scale (value=N)` | number, default `1.0` | multiplies every primitive `segments`/`rings`/`samples` (implicit defaults *and* explicit values like `segments_u=64`) and `blob` `resolution`. `icosphere` `subdivisions` and any `subdivide=` post-pass step by `round(log2(N))` instead. Counts clamp to a per-primitive minimum |
   102→   102→   102→
   103→   103→   103→```
   104→   104→   104→lod_scale (value=0.5)
   105→   105→   105→
   106→   106→   106→scene {
   107→   107→   107→  sphere "head" (radius=0.5)         // 8 rings, 12 segments (default 16/24 halved)
   108→   108→   108→  sphere "lod0" (radius=0.5, segments=48, rings=32)  // 16 rings, 24 segments (48/32 halved)
   109→   109→   109→}
   110→   110→   110→```
   111→   111→   111→
   112→   112→   112→Studio's "LOD scale" slider edits this directive in place; it clears the
   113→   113→   113→directive at `1.0` so saved files stay clean.
   114→   114→   114→
   115→   115→   115→### Per-node `lod=` overrides
   116→   116→   116→
   117→   117→   117→Any geometry/group node accepts `lod=N`, which **multiplies** the active
   118→   118→   118→LOD scale for that node's subtree. RAII-scoped (doesn't leak into siblings)
   119→   119→   119→and compounds with the global setting. Per-primitive minimums still apply
   120→   120→   120→(`lod=0.1` won't collapse a cylinder below three sides).
   121→   121→   121→
   122→   122→   122→```
   123→   123→   123→scene {
   124→   124→   124→  group "hero" (lod=2) {                  // boosted detail
   125→   125→   125→    sphere "face" (radius=0.12)
   126→   126→   126→  }
   127→   127→   127→  sphere "background_rock" (radius=0.4, lod=0.5)  // halved detail
   128→   128→   128→}
   129→   129→   129→```
   130→   130→   130→

   133→   133→   133→## Values and expressions
   134→   134→   134→
   135→   135→   135→Every `value` on the right side of an attribute is one of:
   136→   136→   136→
   137→   137→   137→| form | example | notes |
   138→   138→   138→|---|---|---|
   139→   139→   139→| number | `0.5`, `-90`, `1` | parsed as `f32` |
   140→   140→   140→| length | `1.5m`, `90cm`, `18in`, `2ft` | a number with a unit suffix; normalised to metres (see [Length units](#length-units)) |
   141→   141→   141→| vec3 | `[1.0, 0.5, 0.0]` | three expressions, comma-separated |
   142→   142→   142→| list | `[0, 90]`, `[1, 2, 3, 4]` | arbitrary arity |
   143→   143→   143→| string | `"wood"` | used for names and references |
   144→   144→   144→| ident | `wood`, `y` | no quotes; used for axes and enum-like values |
   145→   145→   145→| expression | `$height * 0.5`, `$r + 0.1`, `($a - $b) / 2` | arithmetic over `$param` refs |
   146→   146→   146→| comparison | `$h > 0`, `$count == 4`, `$a != $b` | `<`, `<=`, `>`, `>=`, `==`, `!=` — used in `if` conditions and `for` ranges |
   147→   147→   147→
   148→   148→   148→Inside `module` bodies, expressions reference parameters as `$name`.
   149→   149→   149→Operators: `+ - * /` (conventional precedence + parentheses) and the six
   150→   150→   150→comparisons. Evaluated at module-expansion time; the scene graph never
   151→   151→   151→sees `$name`.
   152→   152→   152→
   153→   153→   153→### Length units
   154→   154→   154→
   155→   155→   155→mogen's base unit is the **metre** — the glTF/Godot convention — so a bare
   156→   156→   156→number is a length in metres (`size=[0.45, 0.04, 0.45]` is a 45 cm seat).
   157→   157→   157→To write real-world dimensions directly — handy for accurate blueprints —
   158→   158→   158→append a unit suffix to any number:
   159→   159→   159→
   160→   160→   160→| suffix | unit | metres |
   161→   161→   161→|---|---|---|
   162→   162→   162→| `mm` | millimetre | `0.001` |
   163→   163→   163→| `cm` | centimetre | `0.01` |
   164→   164→   164→| `m` | metre | `1.0` |
   165→   165→   165→| `km` | kilometre | `1000.0` |
   166→   166→   166→| `in` | inch | `0.0254` |
   167→   167→   167→| `ft` | foot | `0.3048` |
   168→   168→   168→| `yd` | yard | `0.9144` |
   169→   169→   169→
   170→   170→   170→```
   171→   171→   171→box "wall"  (size=[2m, 100cm, 8in], pos=[3ft, 0, 0])
   172→   172→   172→box "joist" (height=5ft + 6in)        // units compose through arithmetic
   173→   173→   173→```
   174→   174→   174→
   175→   175→   175→The suffix is resolved to metres at **parse time**, so units flow through
   176→   176→   176→every numeric position: scalars, `vec3` components, list items, and
   177→   177→   177→`$param` arithmetic. Each component carries its own unit, so metric and
   178→   178→   178→imperial can be mixed freely within one literal or expression.
   179→   179→   179→
   180→   180→   180→Length units are for **lengths only** — sizes, positions, radii, heights,
   181→   181→   181→offsets. Rotations stay in degrees, `scale` stays a unit-less multiplier, and
   182→   182→   182→counts / colours stay plain numbers; don't put a length suffix on those.
   183→   183→   183→Because everything normalises to metres, a unit literal and its metre
   184→   184→   184→equivalent lower to byte-identical geometry.
   185→   185→   185→
   186→   186→   186→### Weight units
   187→   187→   187→
   188→   188→   188→Weights follow the same scheme, normalising to the **kilogram**. A bare number
   189→   189→   189→is kilograms. Used by [`physics`](#physics) (`weight=`) and the per-node
   190→   190→   190→`weight=` override.
   191→   191→   191→
   192→   192→   192→| suffix | unit | metres → kg |
   193→   193→   193→|---|---|---|
   194→   194→   194→| `g` | gram | 0.001 |
   195→   195→   195→| `kg` | kilogram | 1.0 |
   196→   196→   196→| `t` | tonne | 1000 |
   197→   197→   197→| `lb` | pound | 0.4536 |
   198→   198→   198→| `oz` | ounce | 0.02835 |
   199→   199→   199→| `st` | stone | 6.350 |
   200→   200→   200→
   201→   201→   201→A `physics` block's `weight=` is a weight **per cubic metre** — append `/m3`
   202→   202→   202→(or `/m³`): `700kg/m3`, `0.7t/m3`. A bare `weight=` on a geometry node is a flat
   203→   203→   203→mass (`5kg`). Mass and length suffixes are disjoint, so a literal's dimension is
   204→   204→   204→never ambiguous.
   205→   205→   205→

   208→   208→   208→## Common attributes
   209→   209→   209→
   210→   210→   210→These apply to every geometry node (`box`, `cylinder`, …) and to `group`:
   211→   211→   211→
   212→   212→   212→| attribute | value | effect |
   213→   213→   213→|---|---|---|
   214→   214→   214→| `pos` | `vec3` | translation in the parent's frame; default `[0, 0, 0]` |
   215→   215→   215→| `rot` | `vec3` (Euler XYZ in **degrees**) or a list | rotation applied after translation; default identity |
   216→   216→   216→| `scale` | scalar or `vec3` | uniform/per-axis scale; default `1` |
   217→   217→   217→| `mat` | string or ident | references a declared `material` by name |
   218→   218→   218→| `phys` | string or ident | references a declared `physics` substance by name; drives auto-computed weight + centre of gravity (see [Physics](#physics)) |
   219→   219→   219→| `weight` | mass (`5kg`) | optional flat per-node weight override (a mass), for props whose weight shouldn't follow from their volume |
   220→   220→   220→| `role` | string or ident | semantic label; written into the GLB `extras` block |
   221→   221→   221→| `tags` | comma-separated string | free-form labels; also in `extras` |
   222→   222→   222→
   223→   223→   223→Transforms compose from child → parent along the scene hierarchy, exactly as
   224→   224→   224→in glTF.

   228→   228→   228→## Placement shortcuts
   229→   229→   229→
   230→   230→   230→Every node accepts ergonomic shortcuts on top of `pos`/`rot`/`size`.
   231→   231→   231→Mix and match freely — the DSL does the arithmetic.
   232→   232→   232→
   233→   233→   233→### Per-component shortcuts
   234→   234→   234→
   235→   235→   235→| shortcut | replaces / overrides | notes |
   236→   236→   236→|---|---|---|
   237→   237→   237→| `x=`, `y=`, `z=` | individual components of `pos` | missing axes default to `pos`'s value, or `0` |
   238→   238→   238→| `rx=`, `ry=`, `rz=` | individual components of `rot` (degrees) | same fallback; great for single-axis spins |
   239→   239→   239→| `w=`, `h=`, `d=` | individual components of `size` (X, Y, Z) | for 2D primitives, `w`/`d` are used on `plane`/`curved_plane` (XZ) and `w`/`h` on `quad` (XY) |
   240→   240→   240→
   241→   241→   241→```
   242→   242→   242→box (y=1.5, size=1)            // equivalent to pos=[0, 1.5, 0], size=[1,1,1]
   243→   243→   243→box (size=[2, 2, 0.1], h=3)    // h overrides the middle component — width=2, height=3, depth=0.1
   244→   244→   244→cylinder (rx=90, radius=0.2, height=1)   // lay a cylinder on its side
   245→   245→   245→```
   246→   246→   246→
   247→   247→   247→### Scalar `size` (cube shorthand)
   248→   248→   248→
   249→   249→   249→Any primitive that takes `size=[…]` also accepts `size=<number>`, which
   250→   250→   250→expands to a uniform vec3. `box (size=0.5)` is a half-metre cube.
   251→   251→   251→
   252→   252→   252→### `from` / `to` — axis-aligned box by corners
   253→   253→   253→
   254→   254→   254→On any primitive that uses `size`, `from=[x1,y1,z1]` + `to=[x2,y2,z2]` sets
   255→   255→   255→`size` to `|to − from|` and `pos` to their midpoint. No "shift by half" math:
   256→   256→   256→
   257→   257→   257→```
   258→   258→   258→box (from=[-2, 0, -1.5], to=[2, 2.8, -1.4], mat="wall")
   259→   259→   259→// equivalent to: box (pos=[0, 1.4, -1.45], size=[4.0, 2.8, 0.1])
   260→   260→   260→```
   261→   261→   261→
   262→   262→   262→### `anchor` — place by face, not centre
   263→   263→   263→
   264→   264→   264→Every primitive's `pos` controls where its **anchor point** lands, not where
   265→   265→   265→its centre lands. The default anchor is `center`; `anchor=bottom` puts the
   266→   266→   266→primitive's bottom face at `pos`, which is usually what "sit on the ground"
   267→   267→   267→means. Values are underscore-joined tokens drawn from
   268→   268→   268→`center`, `top`, `bottom`, `left`, `right`, `front`, `back`:
   269→   269→   269→
   270→   270→   270→```
   271→   271→   271→box (y=0,  size=[1, 2, 1], anchor=bottom)           // bottom face on y=0
   272→   272→   272→box (xyz, size=2,           anchor=bottom_left_front) // corner at the origin
   273→   273→   273→```
   274→   274→   274→
   275→   275→   275→The anchor shifts mesh vertices so the chosen point lands at the local
   276→   276→   276→origin; default face connectors (`top`, `bottom`, …) move with it.
   277→   277→   277→
   278→   278→   278→### Relative placement: `above`, `below`, `left_of`, `right_of`, `in_front_of`, `behind`
   279→   279→   279→
   280→   280→   280→Set one of these to the name of a **prior sibling** in the same parent; the
   281→   281→   281→node is translated so its matching face is flush against the sibling's
   282→   282→   282→opposite face, optionally plus `gap`. At most one may be set per node.
   283→   283→   283→
   284→   284→   284→```
   285→   285→   285→group "chests" {
   286→   286→   286→  box "chest_lo" (size=[0.8, 0.6, 0.5])
   287→   287→   287→  box "chest_hi" (above="chest_lo", gap=0.02, size=[0.8, 0.6, 0.5])
   288→   288→   288→}
   289→   289→   289→```
   290→   290→   290→
   291→   291→   291→Resolution happens after the target's subtree is fully lowered (nested
   292→   292→   292→geometry is in the AABB). Lookup is scoped to siblings in the same parent.
   293→   293→   293→

   296→   296→   296→## Deformation modifiers
   297→   297→   297→
   298→   298→   298→Every primitive accepts a small set of common modifier attrs that perturb the
   299→   299→   299→generated mesh between primitive construction and anchor placement. The point
   300→   300→   300→is variety without authoring extra geometry — bent beams, weathered rocks,
   301→   301→   301→melted candles, jelly blobs — using one or two extra attrs.
   302→   302→   302→
   303→   303→   303→| attribute | value | effect |
   304→   304→   304→|---|---|---|
   305→   305→   305→| `bend_x`, `bend_y`, `bend_z` | degrees | arc-length-preserving bend around the named axis. Length axis is the perpendicular one (Y for `bend_x`/`bend_z`, X for `bend_y`). |
   306→   306→   306→| `twist_y` | degrees | helical twist around Y, from 0 at `y_min` to the full angle at `y_max`. |
   307→   307→   307→| `taper` | ratio (1.0 = unchanged, 0.5 = half-width at top) | linear shrink along Y. |
   308→   308→   308→| `droop` | amount (0..1 of length) | quadratic gravity-style sag along -Y; the base stays put, the top sinks by `amount * height`. |
   309→   309→   309→| `noise` | 0..1 | coherent value-noise displacement along the vertex normal. Yields blobby "rock" texture. |
   310→   310→   310→| `jitter` | 0..1 | per-vertex random displacement along the normal. Higher-frequency than `noise`, looks "jagged". |
   311→   311→   311→| `faceted` | 0/1 | rebuild the mesh with three unique vertices per triangle and face-flat normals; reads as low-poly. |
   312→   312→   312→| `seed` | integer | RNG seed for the stochastic modifiers (`noise`, `jitter`); same seed always reproduces the same shape. |
   313→   313→   313→| `wave` | peak displacement (m) | sinusoidal displacement along the vertex normal — periodic ripples for water, jelly, ribbed metal, fabric. Pair with `wave_frequency`, `wave_axis`, `wave_phase`, `wave_range`. |
   314→   314→   314→| `wave_frequency` | cycles/unit, default `1.0` | spatial frequency along `wave_axis`. `0.5` puts a crest every 2 m. |
   315→   315→   315→| `wave_axis` | `"x"`/`"y"`/`"z"`, default `"x"` | axis the wave propagates along. |
   316→   316→   316→| `wave_phase` | radians, default `0.0` | phase offset; lets sibling waves desync without animation. |
   317→   317→   317→| `wave_range` | `[a, b]` | gates the wave to a normalised slice along `wave_axis` via smoothstep, matching `*_range` convention. |
   318→   318→   318→
   319→   319→   319→```
   320→   320→   320→icosphere "rock"   (radius=0.4, noise=0.30, jitter=0.15, faceted=1, seed=7)
   321→   321→   321→cylinder  "candle" (radius=0.18, height=0.7, droop=0.4, noise=0.05)
   322→   322→   322→box       "beam"   (size=[0.2, 0.2, 3], twist_y=20, taper=0.7)
   323→   323→   323→```
   324→   324→   324→
   325→   325→   325→Stochastic modifiers are deterministic for a given `seed`. Two unnamed
   326→   326→   326→primitives with `noise=0.3` share the default seed (1) and produce
   327→   327→   327→identical surfaces — set distinct seeds for sibling variety.
   328→   328→   328→
   329→   329→   329→Each modifier accepts `*_range=[a, b]` (`bend_x_range`, `bend_y_range`,
   330→   330→   330→`bend_z_range`, `twist_y_range`, `taper_range`, `droop_range`,
   331→   331→   331→`noise_range`, `jitter_range`) that gates the deformation along its length
   332→   332→   332→axis: vertices below `a` are unchanged, `[a, b]` ramps in via smoothstep,
   333→   333→   333→above `b` is full effect. Endpoints auto-normalise (`[1.0, 0.5]` →
   334→   334→   334→`[0.5, 1.0]`).
   335→   335→   335→
   336→   336→   336→```
   337→   337→   337→box "blade" (size=[0.06, 1.4, 0.01], bend_z=18, bend_z_range=[0.55, 1.0])
   338→   338→   338→cylinder "spire" (radius=0.4, height=4.0, twist_y=70, twist_y_range=[0.6, 1.0])
   339→   339→   339→```
   340→   340→   340→
   341→   341→   341→Default tessellation auto-bumps (×2 segments / +1 icosphere subdivision)
   342→   342→   342→when a smooth deformer is present; explicit `segments=`/`rings=`/
   343→   343→   343→`subdivisions=` always override. Modifiers don't apply to `mesh` (loaded
   344→   344→   344→glb) primitives. See `examples/nature/asteroid_field.mog`.
   345→   345→   345→
   346→   346→   346→Implicit tessellation on curved primitives is also size-aware in authored
   347→   347→   347→local units. Counts scale with the cube root of radius (or the primitive's
   348→   348→   348→equivalent local extent), relative to the default-sized primitive: tiny rivets
   349→   349→   349→and dimples no longer pay the same triangle count as a dome, while large props
   350→   350→   350→gain detail without triangle count growing linearly with size. Explicit
   351→   351→   351→`segments=`/`rings=` remains the exact author override. Placement `scale=` is
   352→   352→   352→not part of this calculation because multiple placements may share one lowered
   353→   353→   353→mesh; use explicit counts when an unusually scaled placement needs a different
   354→   354→   354→mesh.

   358→   358→   358→## Scene structure: `scene`, `group`
   359→   359→   359→
   360→   360→   360→```
   361→   361→   361→scene {
   362→   362→   362→  group "chair" (pos=[0, 0, 0]) {
   363→   363→   363→    box "seat" (pos=[0, 0.5, 0], size=[1.0, 0.1, 1.0])
   364→   364→   364→  }
   365→   365→   365→}
   366→   366→   366→```
   367→   367→   367→
   368→   368→   368→- `scene` is the root container. Exactly one per file is expected in practice; top-level nodes outside any `scene` are also lowered and become extra roots.
   369→   369→   369→- `group` is a transform-only container — no geometry of its own, used to compose children and receive `pos`/`rot`/`scale`.
   370→   370→   370→- `solid` behaves like `group` in the scene tree, but its same-material leaf children are CSG-unioned into a single mesh at export time. See [Solid groups](#solid-groups-solid) below.

   425→   425→   425→
   426→   426→   426→`plane` is XZ-aligned, `quad` is XY-aligned (UI-style panels).
   427→   427→   427→
   428→   428→   428→`curved_plane`, `lathe`, `spline_tube`, and `spline_ribbon` accept nested
   429→   429→   429→list literals: `points=[[0, 0, 0], [1, 0.5, 0]]`. Inner lists must be
   430→   430→   430→constant (no `$param`) — parameterise the whole node via a module wrapper.
   431→   431→   431→`spline_tube`/`spline_ribbon` run Catmull–Rom with a parallel-transport
   432→   432→   432→frame; `spline_ribbon` adds a `twist` that ramps roll around the path
   433→   433→   433→tangent.
   434→   434→   434→
   435→   435→   435→`slab`, `post`, and `panel` are `box` aliases that only change the default
   436→   436→   436→anchor (`bottom`/`bottom`/`back`). Override with `anchor=` if needed.
   437→   437→   437→
   438→   438→   438→`wall` is a box with rectangular cutouts along Z. Each hole is
   439→   439→   439→`[cx, cy, w, h]` in the wall's local frame (X/Y are the face plane; Z is
   440→   440→   440→cut through). Cutouts are CSG-differenced and welded at lowering, so a
   441→   441→   441→single `wall` becomes one watertight mesh:
   442→   442→   442→
   443→   443→   443→```
   444→   444→   444→wall "barracks" (size=[3, 3, 0.1], holes=[
   445→   445→   445→  [-0.75, -0.4, 0.9, 2.0],   // door
   446→   446→   446→  [ 0.9,  0.3, 0.8, 0.8],    // window
   447→   447→   447→])
   448→   448→   448→```
   449→   449→   449→
   450→   450→   450→### Per-face box materials (`faces=`)
   451→   451→   451→
   452→   452→   452→A `box` can carry a different material on each face via `faces=[…]` — exactly
   453→   453→   453→six material names in the fixed order **`+X, -X, +Y, -Y, +Z, -Z`**:
   454→   454→   454→
   455→   455→   455→```
   456→   456→   456→material "wood"  (color=[0.6, 0.4, 0.2])
   457→   457→   457→material "metal" (color=[0.7, 0.7, 0.75], metallic=0.9)
   458→   458→   458→
   459→   459→   459→box "crate" (size=[2, 1, 1], faces=[
   460→   460→   460→  "wood", "wood",   // +X, -X
   461→   461→   461→  "metal",          // +Y (lid)
   462→   462→   462→  "wood", "wood", "wood"  // -Y, +Z, -Z
   463→   463→   463→])
   464→   464→   464→```
   465→   465→   465→
   466→   466→   466→The box lowers to an editable wrapper (keeping its transform, anchor, and
   467→   467→   467→connectors) plus one **frozen** child per distinct material — each a quad group
   468→   468→   468→of just that material's faces. Faces sharing a material collapse into one child,
   469→   469→   469→so the crate above becomes two children (`wood` ×5, `metal` ×1), not six. The
   470→   470→   470→children have no AST of their own, so the Studio inspector redirects clicks to
   471→   471→   471→the wrapper.
   472→   472→   472→
   473→   473→   473→An empty entry `""` falls back to the box's own `mat=` (or inherited material),
   474→   474→   474→so you can override just the faces you care about:
   475→   475→   475→
   476→   476→   476→```
   477→   477→   477→box "panel" (mat="body", faces=["", "", "label", "", "", ""])  // only +Y differs
   478→   478→   478→```
   479→   479→   479→
   480→   480→   480→This is the migration sink for engine map blocks whose six faces each reference
   481→   481→   481→a different tile texture.
   482→   482→   482→
   483→   483→   483→#### Authored per-face UV transforms (`face(...)`)
   484→   484→   484→
   485→   485→   485→By default each face's texture coordinates follow the material's UV mode
   486→   486→   486→(`fit` = one copy per face, `tile` = 1 unit per metre). When a converter carries
   487→   487→   487→its own per-face UV mapping (atlas sub-rectangles, engine-native tile offsets),
   488→   488→   488→any entry in the `faces=` list may be a `face(...)` struct instead of a bare
   489→   489→   489→string. It sets the material **and** an explicit UV transform baked verbatim
   490→   490→   490→onto that face, bypassing the procedural projection:
   491→   491→   491→
   492→   492→   492→```
   493→   493→   493→box "wall_seg" (size=[4, 3, 1], faces=[
   494→   494→   494→  "wall", "wall", "wall", "wall",
   495→   495→   495→  face("panel", uv_scale=[0.25, 0.333], uv_offset=[0, 0], uv_swap=false),  // +Z
   496→   496→   496→  "wall"
   497→   497→   497→])
   498→   498→   498→```
   499→   499→   499→
   500→   500→   500→- **First argument** — the material name (same rules as the bare string; `""`
   501→   501→   501→  falls back to the box's own material).
   502→   502→   502→- `uv_scale=[sx, sy]` — per-axis scale; may be **negative** to mirror. Default `[1, 1]`.
   503→   503→   503→- `uv_offset=[ox, oy]` — per-axis constant added after scaling. Default `[0, 0]`.
   504→   504→   504→- `uv_swap=<bool>` — swap the two in-plane axes before scale/offset. Default `false`.
   505→   505→   505→
   506→   506→   506→All UV fields are optional; **`face("mat")` is identical to the bare `"mat"`**
   507→   507→   507→(no authored transform → keep the default Fit/Tile UVs). Authored and bare
   508→   508→   508→entries may be freely mixed in one list, and faces still group into frozen
   509→   509→   509→children by material as above.
   510→   510→   510→
   511→   511→   511→The baked coordinate is face-local. For a face whose outward normal is on axis
   512→   512→   512→*A*, the two in-plane axes are the other two in ascending index order
   513→   513→   513→(`X→(Y,Z)`, `Y→(X,Z)`, `Z→(X,Y)`); the local coordinate on each is the vertex
   514→   514→   514→offset from the box's minimum corner on that axis (`vertex + size/2`). The final
   515→   515→   515→UV is `offset + scale * (swap ? swapped : local)`. Values are emitted **exactly
   516→   516→   516→as computed** — never clamped or wrapped, so repeat/tile behaviour is left to the
   517→   517→   517→sampler.
   518→   518→   518→
   519→   519→   519→### Branch
   520→   520→   520→
   521→   521→   521→`branch` is a procedural tree builder. One node expands into a recursive
   522→   522→   522→cluster of `spline_tube` segments tapering from trunk to twigs, with
   523→   523→   523→optional `leaf_card` clusters at the tips. Inner segments are
   524→   524→   524→non-editable (deterministic function of `seed=`).
   525→   525→   525→
   526→   526→   526→| attribute | default | effect |
   527→   527→   527→|---|---|---|
   528→   528→   528→| `form` | `"decurrent"` | growth habit preset — see below. Sets sensible defaults for all attrs in this table; user attrs still win |
   529→   529→   529→| `length` | `1.0` | trunk length (m) |
   530→   530→   530→| `radius` | `0.05` | trunk base radius (m) |
   531→   531→   531→| `depth` | `4` | recursion depth (number of branching levels) |
   532→   532→   532→| `splits` | `2` | child branches per parent at each split |
   533→   533→   533→| `length_falloff` | `0.7` | per-level length multiplier |
   534→   534→   534→| `radius_falloff` | `0.6` | per-level radius multiplier |
   535→   535→   535→| `branch_angle` | `35` | angle (degrees) child branches lean off the parent tangent |
   536→   536→   536→| `roll` | `137.5` | roll (degrees) between successive children — the golden angle by default, breaks bilateral symmetry |
   537→   537→   537→| `tropism` | `0.0` | bias toward +Y per segment (positive = upright trees, negative = drooping) |
   538→   538→   538→| `bend` | `10` | random bend (degrees) added to each segment frame |
   539→   539→   539→| `leader_bias` | `0.0` | `0.0`–`1.0` strength of central-leader behaviour. At `1.0` child 0 of every fork continues straight up at full length/radius (pine-like silhouette); at `0.0` all forks are equal (default broadleaf habit) |
   540→   540→   540→| `multi_stem` | `1` | number of trunks emerging from the base. Only honoured by `form="shrub"`; ignored otherwise |
   541→   541→   541→| `segments` | `8` | radial segments per spline_tube |
   542→   542→   542→| `samples` | `4` | samples per spline segment |
   543→   543→   543→| `seed` | `1` | RNG seed; same seed = identical tree |
   544→   544→   544→| `jitter` | `0.2` | `0.0`–`1.0` random perturbation amount on lengths/angles |
   545→   545→   545→| `leaves` | `1` | emit `leaf_card` clusters at terminal tips (`0` to disable) |
   546→   546→   546→| `leaf_size` | `0.35` | leaf-card height (m) |
   547→   547→   547→| `leaf_aspect` | `1.0` | leaf width / height ratio. `<1` for needle/willow leaves, `>1` for wide flat leaves |
   548→   548→   548→| `leaf_cards` | `2` | crossed cards per leaf cluster (or fronds in the palm rosette) |
   549→   549→   549→| `leaf_mat` | — | material name for leaves; defaults to inherited `mat=` |
   550→   550→   550→
   551→   551→   551→`form` values:
   552→   552→   552→
   553→   553→   553→| value | habit | distinctive defaults |
   554→   554→   554→|---|---|---|
   555→   555→   555→| `"decurrent"` | broadleaf tree (default — oak, maple) | equal forks, square leaves |
   556→   556→   556→| `"excurrent"` | conifer (pine, spruce) | strong central leader, near-horizontal side branches, narrow needle leaves |
   557→   557→   557→| `"weeping"` | willow | long branches with strong negative tropism (drooping), long narrow leaves |
   558→   558→   558→| `"shrub"` | bush | several short trunks at the base (`multi_stem=4` by default), no leader |
   559→   559→   559→| `"palm"` | palm | single straight trunk with a fan of frond-shaped cards at the tip; no recursive branching |
   560→   560→   560→
   561→   561→   561→Wrap a `branch` in a `group` with `scale=`/`rot=` for forests, antlers,
   562→   562→   562→vines, root systems. Pair with stdlib `branch`/`leaf` for hand-tuned shapes.
   563→   563→   563→
   564→   564→   564→### Building
   565→   565→   565→
   566→   566→   566→`building` is a procedural building-interior generator. One node expands
   567→   567→   567→into floor/ceiling slabs, perimeter walls with windows and entrance
   568→   568→   568→cutouts, interior walls with door cutouts, and stamped door/window/skylight
   569→   569→   569→modules. The generated subtree is stamped non-editable (pure function of
   570→   570→   570→`seed=` plus the declared attrs). See `docs/building.md` for the full
   571→   571→   571→spec, supported styles/roof shapes, and tranche status.
   572→   572→   572→
   573→   573→   573→| attribute | default | effect |
   574→   574→   574→|---|---|---|
   575→   575→   575→| `seed` | `1` | RNG seed; same seed = identical layout + geometry. |
   576→   576→   576→| `style` | `"grid"` | Layout algorithm. T1-T2: `grid`, `apartment-block`. |
   577→   577→   577→| `mat_style` | `""` | Free-text style hint forwarded to material/texture generation. |
   578→   578→   578→| `floor_area` | `120` | Target floorplate area in m² (per floor). |
   579→   579→   579→| `rooms` | `4` | Total rooms across all floors; distributed proportionally. |
   580→   580→   580→| `floors_above` | `1` | Storeys above ground (incl. ground floor). |
   581→   581→   581→| `floors_below` | `0` | Basement storeys. |
