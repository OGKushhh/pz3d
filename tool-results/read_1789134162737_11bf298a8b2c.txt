    27→#Grammar at a glance
    28→A .mog file is a sequence of nodes. Every node shares the same shape:
    29→
    30→kind ["optional name"] [(attr=value, ...)] [{ child_nodes... }]
    31→kind is an identifier like box, cylinder, group, scene, material, joint, …
    32→name is a quoted string. Some kinds require it (material, module, joint, clip, connector); most geometry kinds treat it as optional — when omitted the node's name defaults to its kind.
    33→attr_list is a comma-separated key=value sequence in parentheses.
    34→block is a brace-delimited list of child nodes.
    35→Comments run from // to the end of the line. Whitespace between tokens is insignificant. The top of the file may contain import, material, module, joint, and clip declarations; scene { ... } holds the geometry itself.
    36→
    37→#File metadata: meta
    38→An optional top-of-file block recording author-facing metadata about the asset. Place at most once, before material / scene / module.
    39→
    40→meta (
    41→  name = "wooden_chair",
    42→  version = "1.2.0",
    43→  description = "A simple four-legged dining chair.",
    44→  tags = ["furniture", "chair", "wood"],
    45→)
    46→attr    type    source  notes
    47→name    string  author  human-readable asset name
    48→version string  author  author-controlled (semver-style is conventional but not enforced)
    49→mogen_version   string  toolchain       auto-stamped from the running mogen version on every save (mogen generate/modify/animate/repair/textures and Studio Save). Don't write it yourself.
    50→description     string  author  one-line summary
    51→tags    list of string  author  free-form labels
    52→The block is purely informational — it's not consumed by the geometry pipeline. It survives lowering on SceneGraph::meta so tooling (Studio, exporters) can read it without re-parsing. Old files without a meta block keep building; on the next save the toolchain inserts a fresh meta (mogen_version = "...") line.
    53→
    54→Diagnostic codes for meta:
    55→
    56→E0310 — meta cannot have a { … } body block.
    57→E0311 — meta cannot take a quoted name (meta "x" (...)); use name= instead.
    58→E0312 — duplicate meta block.
    59→E0313 — meta only allowed at the top level.
    60→W0107 — file's mogen_version doesn't match the running toolchain (will be re-stamped on next save).
    61→#Global settings
    62→Top-level directives that tune the build itself rather than describing geometry. They sit at the file level (alongside material / module) and are consumed during lowering.
    63→
    64→directive       value   effect
    65→lod_scale (value=N)     number, default 1.0     multiplies primitive default segments / rings / samples. 0.5 halves them, 2.0 doubles them. icosphere subdivisions step by round(log2(N)) instead, since each step quadruples its triangle count. Per-primitive values (segments=24, rings=16, …) are absolute and are not scaled.
    66→lod_scale (value=0.5)
    67→
    68→scene {
    69→  sphere "head" (radius=0.5)         // 12 rings, 12 segments (default 16/24 halved)
    70→  sphere "lod0" (radius=0.5, segments=48, rings=32)  // explicit values keep 48/32
    71→}
    72→The studio's "LOD scale" slider (under the build summary) edits this directive in place — drag it down to iterate quickly on big scenes, then drag back to 1.0 for export. The slider clears the directive when it returns to 1.0 so saved files stay clean by default.

    74→#Values and expressions
    75→Every value on the right side of an attribute is one of:
    76→
    77→form    example notes
    78→number  0.5, -90, 1     parsed as f32
    79→vec3    [1.0, 0.5, 0.0] three expressions, comma-separated
    80→list    [0, 90], [1, 2, 3, 4]   arbitrary arity
    81→string  "wood"  used for names and references
    82→ident   wood, y no quotes; used for axes and enum-like values
    83→expression      $height * 0.5, $r + 0.1, ($a - $b) / 2  arithmetic over $param refs
    84→Inside module bodies, any expression may reference a declared parameter as $name. Expressions support + - * / with conventional precedence and parentheses. An expression is evaluated at module-expansion time — by the time the scene graph is built, every $name has been replaced with a concrete number.
    85→
    86→#Common attributes
    87→These apply to every geometry node (box, cylinder, …) and to group:
    88→
    89→attribute       value   effect
    90→pos     vec3    translation in the parent's frame; default [0, 0, 0]
    91→rot     vec3 (Euler XYZ in degrees) or a list   rotation applied after translation; default identity
    92→scale   scalar or vec3  uniform/per-axis scale; default 1
    93→mat     string or ident references a declared material by name
    94→role    string or ident semantic label; written into the GLB extras block
    95→tags    comma-separated string  free-form labels; also in extras
    96→Transforms compose from child → parent along the scene hierarchy, exactly as in glTF.
    97→
    98→#Placement shortcuts
    99→Every node accepts a family of ergonomic shortcuts on top of the classic pos/rot/size vec3s. They exist for one reason: an LLM should never need to do arithmetic that the DSL can do for it. Mix and match freely.
   100→
   101→#Per-component shortcuts
   102→shortcut        replaces / overrides    notes
   103→x=, y=, z=      individual components of pos    missing axes default to pos's value, or 0
   104→rx=, ry=, rz=   individual components of rot (degrees)  same fallback; great for single-axis spins
   105→w=, h=, d=      individual components of size (X, Y, Z) for 2D primitives, w/d are used on plane/curved_plane (XZ) and w/h on quad (XY)
   106→box (y=1.5, size=1)            // equivalent to pos=[0, 1.5, 0], size=[1,1,1]
   107→box (size=[2, 2, 0.1], h=3)    // h overrides the middle component — width=2, height=3, depth=0.1
   108→cylinder (rx=90, radius=0.2, height=1)   // lay a cylinder on its side
   109→#Scalar size (cube shorthand)
   110→Any primitive that takes size=[…] also accepts size=<number>, which expands to a uniform vec3. box (size=0.5) is a half-metre cube.
   111→
   112→#from / to — axis-aligned box by corners
   113→On any primitive that uses size, from=[x1,y1,z1] + to=[x2,y2,z2] sets size to |to − from| and pos to their midpoint. No "shift by half" math:
   114→
   115→box (from=[-2, 0, -1.5], to=[2, 2.8, -1.4], mat="wall")
   116→// equivalent to: box (pos=[0, 1.4, -1.45], size=[4.0, 2.8, 0.1])
   117→#anchor — place by face, not centre
   118→Every primitive's pos controls where its anchor point lands, not where its centre lands. The default anchor is center; anchor=bottom puts the primitive's bottom face at pos, which is usually what "sit on the ground" means. Values are underscore-joined tokens drawn from center, top, bottom, left, right, front, back:
   119→
   120→box (y=0,  size=[1, 2, 1], anchor=bottom)           // bottom face on y=0
   121→box (xyz, size=2,           anchor=bottom_left_front) // corner at the origin
   122→Internally the anchor shifts the mesh vertices so the chosen point is at the local origin. The six default face connectors (top, bottom, left, …) move with the shift, so attach/connector math stays correct.
   123→
   124→#Relative placement: above, below, left_of, right_of, in_front_of, behind
   125→Set one of these to the name of a prior sibling in the same parent; the node is translated so its matching face is flush against the sibling's opposite face, optionally plus gap. At most one may be set per node.
   126→
   127→group "chests" {
   128→  box "chest_lo" (size=[0.8, 0.6, 0.5])
   129→  box "chest_hi" (above="chest_lo", gap=0.02, size=[0.8, 0.6, 0.5])
   130→}
   131→Resolution happens after the target's subtree is fully lowered, so nested geometry is included in the AABB. Lookup is scoped to siblings in the same parent, so replicated subtrees (array, grid) don't collide with identically named nodes elsewhere.
   132→
   133→#Deformation modifiers
   134→Every primitive accepts a small set of common modifier attrs that perturb the generated mesh between primitive construction and anchor placement. The point is variety without authoring extra geometry — bent beams, weathered rocks, melted candles, jelly blobs — using one or two extra attrs.
   135→
   136→attribute       value   effect
   137→bend_x, bend_y, bend_z  degrees arc-length-preserving bend around the named axis. Length axis is the perpendicular one (Y for bend_x/bend_z, X for bend_y).
   138→twist_y degrees helical twist around Y, from 0 at y_min to the full angle at y_max.
   139→taper   ratio (1.0 = unchanged, 0.5 = half-width at top)        linear shrink along Y.
   140→droop   amount (0..1 of length) quadratic gravity-style sag along -Y; the base stays put, the top sinks by amount * height.
   141→noise   0..1    coherent value-noise displacement along the vertex normal. Yields blobby "rock" texture.
   142→jitter  0..1    per-vertex random displacement along the normal. Higher-frequency than noise, looks "jagged".
   143→faceted 0/1     rebuild the mesh with three unique vertices per triangle and face-flat normals; reads as low-poly.
   144→seed    integer RNG seed for the stochastic modifiers (noise, jitter); same seed always reproduces the same shape.
   145→Common combinations:
   146→
   147→// Asteroid / rock — coherent bumps + per-vertex jitter + flat shading.
   148→icosphere "rock"   (radius=0.4, noise=0.30, jitter=0.15, faceted=1, seed=7)
   149→// Bent timber / pipe — single-axis bend with light surface noise.
   150→cylinder  "post"   (radius=0.05, height=2.0, bend_z=12, noise=0.04)
   151→// Melted wax / jelly — gravity-sagged top with soft surface texture.
   152→cylinder  "candle" (radius=0.18, height=0.7, droop=0.4, noise=0.05)
   153→// Twisted, tapered beam — combine deterministic deformations freely.
   154→box       "beam"   (size=[0.2, 0.2, 3], twist_y=20, taper=0.7)
   155→Stochastic modifiers are deterministic for a given seed so rebuilds are reproducible. Two unnamed primitives with noise=0.3 and no seed share the same seed default (1) and therefore the same surface — set distinct seeds when you want sibling rocks to differ.
   156→
   157→Default tessellation auto-bumps (×2 segments / +1 icosphere subdivision) when a smooth deformer (bend_*, twist_y, noise, droop) is present so a bent cylinder doesn't read as faceted. Author's explicit segments=, rings=, subdivisions= always override.
   158→
   159→Modifiers are not applied to mesh (loaded glb) primitives — their joints, UVs, and skinning contract are wider than what the deform pass preserves.
   160→
   161→See examples/asteroid_field.mog for a runnable showcase.

   163→#Scene structure: scene, group
   164→scene {
   165→  group "chair" (pos=[0, 0, 0]) {
   166→    box "seat" (pos=[0, 0.5, 0], size=[1.0, 0.1, 1.0])
   167→  }
   168→}
   169→scene is the root container. Exactly one per file is expected in practice; top-level nodes outside any scene are also lowered and become extra roots.
   170→group is a transform-only container — no geometry of its own, used to compose children and receive pos/rot/scale.
   171→solid behaves like group in the scene tree, but its same-material leaf children are CSG-unioned into a single mesh at export time. See Solid groups below.
   172→#Primitives
   173→All primitives accept the common attributes above (pos, rot, scale, mat, role, tags) plus the kind-specific attributes below.
   174→
   175→kind    required attrs  other attrs
   176→box     size=[x,y,z]    —
   177→plane   size=[x,_,z] (Y ignored)        —
   178→quad    size=[w,h] or vec3 (w,h,_)      —
   179→cylinder        radius, height  segments (default 24)
   180→cone    radius, height  segments (default 24)
   181→sphere  radius  rings (16), segments (24)
   182→capsule radius, height  rings (8), segments (24)
   183→torus   major, minor    major_segments (24), minor_segments (12)
   184→prism   size=[x,y,z]    triangular prism along +Z
   185→pyramid radius, height, sides   N-sided pyramid base
   186→disc    radius  segments (24)
   187→icosphere       radius  subdivisions (2)
   188→rounded_box     size=[x,y,z], radius    segments per corner (4)
   189→wedge   size=[x,y,z]    right-triangle prism — flat bottom on -Y, hypotenuse climbing toward +Y/+Z. Useful for ramps, roof pitches, doorstops
   190→frustum bottom=[w,d], top=[w,d], height truncated rectangular pyramid (defaults bottom=[1,1], top=[0.5,0.5], height=1)
   191→tube    outer, inner, height    hollow cylinder (pipe / ring); segments (24)
   192→hemisphere      radius  half-sphere, flat side on -Y; rings (8), segments (24)
   193→half_cylinder   radius, height  D-profile half-cylinder, flat side facing -Z; segments (24)
   194→torus_arc       major, minor    partial torus; arc (degrees, default 90) sweeps around +Y; major_segments (24), minor_segments (12). Useful for arches and handles
   195→ellipsoid       size=[x,y,z]    rings (16), segments (24); independent radii per axis
   196→superellipsoid  size=[x,y,z]    ew, ns (1 = sphere, > 1 boxy, < 1 pinched), rings (16), segments (24)
   197→curved_plane    size=[x,z] or vec3      bend_u, bend_v (degrees; arc angle along X/Z), segments_u/segments_v (12)
   198→lathe   profile=[[r,y], …]      segments (24), cap_ends (1 = capped); profile authored bottom-to-top in (radius, y) pairs
   199→spline_tube     points=[[x,y,z], …]     radius (scalar) or radii=[…] (per-point), segments (12), samples (8), cap_ends (1)
   200→spline_ribbon   points=[[x,y,z], …]     width (scalar) or widths=[…] (per-point), samples (8), twist (degrees, default 0); flat strip along a Catmull–Rom curve
   201→leaf_card       size=[w,h]      cards (default 2); alpha-cutout foliage card cluster — one quad plus cards-1 rotated copies sharing the same XY plane. Pair with a mat="…" whose alpha_mode="mask" and double_sided=1
   202→mesh    src="path.glb"  load and embed an external glTF binary as a single mesh. Path is relative to the calling .mog. Materials, skinning, and animations on the source GLB are dropped — set them in the DSL instead
   203→branch  —       procedural tree / vine / antler. See Branch below
   204→slab    size=[x,y,z]    box alias; default anchor bottom (sits on ground)
   205→post    size=[x,y,z]    box alias; default anchor bottom (pillar/leg)
   206→panel   size=[x,y,z]    box alias; default anchor back (flat panel flush to a surface)
   207→wall    size=[x,y,z]    holes=[[x,y,w,h], …] — rectangular cutouts through the Z axis
   208→plane and quad are both flat single-quad meshes; plane is XZ-aligned, quad is XY-aligned (useful for UI-style panels).
   209→
   210→superellipsoid is the workhorse for smooth organic bodies (eggs, pears, bullet shapes) and stylised soft boxes — pick ew/ns together for a symmetric shape, or split them for asymmetric profiles like an apple (ew=1.2, ns=0.8).
   211→
   212→curved_plane, lathe, spline_tube, and spline_ribbon accept nested list literals: points=[[0, 0, 0], [1, 0.5, 0]], profile=[[0.2, 0], [0.5, 0.4]]. Inner lists must be constant (no $param) — parameterise the whole node via a module wrapper instead. spline_tube and spline_ribbon both run a Catmull–Rom curve through their control points and use a parallel-transport frame so the cross section doesn't flip at inflection points; spline_ribbon adds a twist that ramps a roll around the path tangent.
   213→
   214→tube, hemisphere, half_cylinder, and torus_arc are the open / hollow / partial counterparts of the canonical round primitives. They give you ring tops, bowls, columns with a flat back, arches, and handles without an extra CSG step.
   215→
   216→leaf_card is the workhorse for foliage and feathers: it builds a small cluster of crossed quads that sit on top of an alpha-cutout texture, so an entire bush or pine sprig reads as one mesh.
   217→
   218→slab, post, and panel are box aliases that exist only to change the default anchor — their geometry is identical to box. Use them to make "this sits on the ground" or "this is a wall-hung panel" the one-line thing it should be, without anchor=… on every row. You can still override anchor= explicitly if you need something different.
   219→
   220→wall is a box with rectangular cutouts along Z. Each hole is a 4-element sublist [cx, cy, w, h] in the wall's local frame (X/Y are the face plane; the Z thickness axis is cut all the way through). Cutouts are applied via CSG difference at lowering time and the result is welded/cleaned, so a single wall node becomes one watertight mesh — no nested difference idiom needed:
   221→
   222→wall "barracks" (size=[3, 3, 0.1], holes=[
   223→  [-0.75, -0.4, 0.9, 2.0],   // door
   224→  [ 0.9,  0.3, 0.8, 0.8],    // window
   225→])
   226→#Branch
   227→branch is a self-contained procedural tree builder. One node expands into a recursive cluster of spline_tube segments tapering from a thick trunk down to twigs, with optional leaf_card clusters at the tips. The result reads as one editable wrapper in the scene graph; the inner segments are stamped non-editable because their geometry is a deterministic function of seed=.
   228→
   229→attribute       default effect
   230→form    "decurrent"     growth habit preset — see below. Sets sensible defaults for all attrs in this table; user attrs still win
   231→length  1.0     trunk length (m)
   232→radius  0.05    trunk base radius (m)
   233→depth   4       recursion depth (number of branching levels)
   234→splits  2       child branches per parent at each split
   235→length_falloff  0.7     per-level length multiplier
   236→radius_falloff  0.6     per-level radius multiplier
   237→branch_angle    35      angle (degrees) child branches lean off the parent tangent
   238→roll    137.5   roll (degrees) between successive children — the golden angle by default, breaks bilateral symmetry
   239→tropism 0.0     bias toward +Y per segment (positive = upright trees, negative = drooping)
   240→bend    10      random bend (degrees) added to each segment frame
   241→leader_bias     0.0     0.0–1.0 strength of central-leader behaviour. At 1.0 child 0 of every fork continues straight up at full length/radius (pine-like silhouette); at 0.0 all forks are equal (default broadleaf habit)
   242→multi_stem      1       number of trunks emerging from the base. Only honoured by form="shrub"; ignored otherwise
   243→segments        8       radial segments per spline_tube
   244→samples 4       samples per spline segment
   245→seed    1       RNG seed; same seed = identical tree
   246→jitter  0.2     0.0–1.0 random perturbation amount on lengths/angles
   247→leaves  1       emit leaf_card clusters at terminal tips (0 to disable)
   248→leaf_size       0.35    leaf-card height (m)
   249→leaf_aspect     1.0     leaf width / height ratio. <1 for needle/willow leaves, >1 for wide flat leaves
   250→leaf_cards      2       crossed cards per leaf cluster (or fronds in the palm rosette)
   251→leaf_mat        —       material name for leaves; defaults to inherited mat=
   252→form values:
   253→
   254→value   habit   distinctive defaults
   255→"decurrent"     broadleaf tree (default — oak, maple)   equal forks, square leaves
   256→"excurrent"     conifer (pine, spruce)  strong central leader, near-horizontal side branches, narrow needle leaves
   257→"weeping"       willow  long branches with strong negative tropism (drooping), long narrow leaves
   258→"shrub" bush    several short trunks at the base (multi_stem=4 by default), no leader
   259→"palm"  palm    single straight trunk with a fan of frond-shaped cards at the tip; no recursive branching
   260→Wrap a branch in a group and apply scale= / rot= to compose forests, antlers, vines, or root systems out of the same generator. Pair it with the stdlib branch and leaf modules for hand-tuned shapes.
   261→
   262→Default values mean that cylinder "leg" with no attrs is a 1 m unit-radius cylinder centered on the origin. Every primitive is authored in its local frame and then positioned via pos/rot/scale.
   263→
   264→#Materials
   265→material "wood"  (color=[0.55, 0.35, 0.18], metallic=0.0, roughness=0.8)
   266→material "glass" (color=[0.9, 0.95, 1.0], alpha=0.3, roughness=0.05, transmission=0.9)
   267→material "neon"  (color=[1, 0.2, 1], emissive=[1, 0.2, 1], emissive_strength=8.0)
   268→material "leaf"  (color=[0.25, 0.6, 0.2], alpha_mode="mask", alpha_cutoff=0.5)
   269→Declared at the top of the file or inside scene { ... }. Attributes:
   270→
   271→color — vec3 [r, g, b] in linear space; alpha defaults to 1.0.
   272→alpha — optional alpha override for transparency. Setting alpha < 1 without an explicit alpha_mode auto-selects "blend".
   273→metallic — 0.0–1.0, default 0.0.
   274→roughness — 0.0–1.0, default 0.9.
   275→normal_strength — slope multiplier baked into the derived normal map by mogen textures. Larger = more pronounced bumps. Range ~0..8, default 1.5. Has no effect if normal_texture is authored directly.
   276→occlusion_strength — 0.0–1.0 ceiling on how dark the derived AO map can get. 0 emits flat white (no darkening), 1 lets cavities reach black. Default 0.7. Has no effect if occlusion_texture is authored directly.
   277→alpha_mode — "opaque" (default), "blend" (translucent), or "mask" (1-bit cutout, e.g. foliage).
   278→alpha_cutoff — threshold for alpha_mode="mask", default 0.5.
   279→emissive — vec3 glow colour added on top of PBR shading. Use this for screens, embers, lava. Default [0, 0, 0].
   280→emissive_strength — HDR multiplier on emissive (KHR_materials_emissive_strength). Values > 1.0 drive bloom and produce the saturated, "fluorescent paint" look. Default 1.0.
   281→transmission — 0.0–1.0 fraction of light that passes through the surface (KHR_materials_transmission). 0 is opaque PBR, 1 is perfectly clear glass. Orthogonal to alpha_mode — use this for glass and water, alpha/alpha_mode for gels, tints, and smoke.
   282→double_sided — 0 (default) or 1. When 1, the renderer draws both faces of the triangle (glTF doubleSided). Use for leaves, fins, flags, cloth, and any thin curved_plane/plane/disc/quad whose underside can be seen. This is the correct fix for tilted or bent single-sided geometry — mirroring a bent curved_plane along its bend axis does not produce a double-sided surface; it produces two sheets curling away from each other.
   283→uv_mode — "tile" (default) or "fit". Controls how textures map onto the geometry. "tile" emits world-space UVs so 1 world unit = 1 texture tile (scaled by uv_scale). Texel density is identical across every primitive that uses the material — the right choice for repeating surfaces like stone walls, wood planks, fabric, ground, and roof shingles. "fit" falls back to per-face [0, 1]² UVs so every face of the primitive shows the full image once — the right choice when the texture is the picture: signs, paintings, decals, stained-glass panes, anything whose image must land at a specific place on a specific face. Pick "fit" for image-as-texture; leave the default for material-as-texture.
   284→uv_scale — 1.0 (default), a scalar (uv_scale=2), or a vec2 (uv_scale=[2, 1]). In tile mode this is "tiles per world unit": 2 doubles the tiling density (smaller bricks), 0.5 halves it (bigger bricks). In fit mode it multiplies the [0, 1] coords — > 1 repeats the image inside a face, < 1 zooms into a sub-region. Per-axis vec2 form lets you stretch a texture asymmetrically (planks on a floor, bands on a column).
   285→base_color_texture — string path to an .png/.jpg file on disk, resolved relative to the .mog file. Multiplied against color. sRGB.
   286→metallic_roughness_texture — packed metal/rough map (glTF convention: green = roughness, blue = metallic). Linear.
   287→normal_texture — tangent-space normal map. Linear.
   288→occlusion_texture — ambient occlusion (red channel). Linear.
   289→emissive_texture — emissive colour map, multiplied against emissive. sRGB.
   290→prompt — optional free-form description of the surface, used by mogen textures as the subject hint when generating an albedo image. Lets you steer the model away from the auto-derived "material name + colour" framing — useful when the material name is generic (fabric_main) or when the default phrasing trips Gemini's recitation filter. Example: prompt="navy nylon ripstop weave". The texture pipeline rephrases this on retry if the image generator rejects the request for recitation, so a literal brand-adjacent phrasing won't permanently jam a build.
   291→shader — "standard" (default) or "water". Selects a per-material shader override in MoGen Studio's preview only — the exported .glb always uses standard PBR, since glTF 2.0 cannot carry custom shader code. "water" swaps the live preview for animated ripples + fresnel-driven body/sky mix + sun glints. The water branch reads the standard material knobs:
   292→color is the absorbed body tint when looking straight down ([0.12, 0.55, 0.62] reads as a lagoon, [0.02, 0.05, 0.15] as deep ocean).
   293→uv_scale controls ripple density: 1.0 ≈ pool-scale chop, raise it for choppier small ponds, lower it for lazy ocean swells.
   294→roughness ties together chop, sky-reflection blur, sun-glint sharpness, and foam. 0.05 is glassy mirror, 0.4 is a calm pool, 0.9 (the default) is ocean-style ripples, 1.0 adds whitecaps.
   295→metallic lerps the Fresnel base from clean dielectric water (0) toward liquid metal at 1 — mercury / molten silver, where the body tint becomes the reflection colour at all angles.
   296→transmission makes the body absorption recede so the sky reflection and what's behind the surface dominate. Combine with alpha_mode="blend" to actually see the pool floor through the water.
   297→emissive / emissive_strength light the water from within (lava, magic potion, bioluminescent surf).
   298→normal_strength multiplies the wave-slope (default 1.5); raising it deepens the ripples without retuning chop.
   299→normal_texture and base_color_texture are blended into the procedural waves and body tint respectively so authors can paint in high-frequency detail or shallow/deep variation.
   300→Example:
   301→
   302→material "oak" (
   303→  color=[1, 1, 1],
   304→  roughness=0.8,
   305→  base_color_texture="textures/oak_albedo.png",
   306→  normal_texture="textures/oak_normal.png"
   307→)
   308→
   309→material "lake" (color=[0.05, 0.32, 0.45], shader="water")
   310→Texture files are embedded in the output GLB, so the resulting .glb is self-contained and can be moved without the source images. Missing files are a hard error at export.
   311→
   312→Reference a material on any geometry or group via mat="wood". The lookup is by exact string match; unknown names are a hard error at lowering.
   313→
   314→#Decals
   315→A decal is a transparent image (logo, label, sticker, scribble, seal, handwritten note) projected onto a surface. It lowers to a thin double-sided quad floating slightly off the parent surface, with an auto-synthesized alpha_mode="blend" material whose albedo is an RGBA PNG.
   316→
   317→decal "logo" (
   318→  pos = [0, 0.1, 0.101],
   319→  size = [0.25, 0.12],
   320→  prompt = "embroidered MoGen logo, white thread on dark fabric"
   321→)
   322→Attributes:
   323→
   324→size — [w, h] in local units. Default [0.5, 0.5]. The decal is a flat XY quad whose normal points along its local +Z; rotate the decal with rot= / rx/ry/rz to point its face wherever you need.
   325→prompt — image description handed to Gemini when running mogen textures. Asks for an RGBA PNG with a fully transparent background; the resolved file path is spliced back into the source as image="…" for reproducibility.
   326→image — explicit path to an existing RGBA PNG (relative to the .mog file). Wins over prompt=; skips the LLM call entirely.
   327→tint — vec3 [r, g, b] multiplied against the decal's albedo. Default [1, 1, 1] (no tint).
   328→roughness — 0.0–1.0. Default 0.6.
   329→offset — +Z gap from the surface, in local units, to avoid z-fighting against the underlying mesh. Default 0.001 reads flush at typical scales; raise on coarse geometry.
   330→#Curved surfaces: on= / at=
   331→For flat surfaces, place the decal as a child of the surface and let pos= handle alignment. For curved surfaces, write the decal once with on= and at= and the lowering pass synthesizes a conform patch behind the scenes — the decal's vertices are bent onto the target's surface so it actually hugs the curvature.
   332→
   333→ellipsoid "bag" (size=[1.0, 0.5, 0.5], mat="leather") {
   334→  connector "front_spot" (at=[0.0, 0.0, 0.25], dir=[0, 0, 1])
   335→}
   336→decal "bag_logo" (
   337→  size = [0.18, 0.10],
   338→  on   = "bag",
   339→  at   = "front_spot",
   340→  prompt = "embroidered MoGen wordmark, cream thread on dark leather"
   341→)
   342→on — name of the target node to conform onto. Triggers the shortcut.
   343→at — required when on= is set; names the connector on the target that acts as the patch anchor.
   344→up — optional x|y|z; which local axis points along the surface normal. Defaults to z (the decal quad's face direction).
   345→lift — optional outward offset along the surface normal, applied during conform. Layered on top of the per-mesh offset= value, so use lift= on coarse target geometry where you need extra separation. Defaults to 0.
   346→When on= is used the decal is reparented under the target. Its pos= is dropped (positioning comes from at=, not user transforms), but rot= and scale= are baked into the artwork before projection — so rot=[0, 0, 90] spins the logo 90° in the tangent plane (the useful "rotate the artwork around the surface normal" case), and scale=[2, 1, 1] makes it twice as wide. Off-plane rotations like rot=[90, 0, 0] tilt the artwork off the surface; the conform kernel reproduces them faithfully but the result is rarely what authors want — reach for rz= / rot=[0, 0, deg] for the common "spin the logo" case.
   347→
   348→If neither prompt= nor image= is set, the decal's name is used as the prompt. That makes the compact form decal "embroidered logo, white thread" (size=[0.2, 0.1], pos=[0, 0.1, 0.101]) valid — handy when you want to keep the description and the node identity in one place.
   349→
   350→A few rules that aren't optional:
   351→
   352→mat= is rejected on decals — they own their material outright. Use tint=/roughness= to influence shading.
   353→Each decal gets its own auto-named material (__decal_<name>) and is never merged into adjacent same-material siblings by the export-time merge pass.
   354→The mogen textures pipeline asks Gemini for transparent-background RGBA directly. There is no chroma-key step: the alpha_mode="mask" foliage path is for foliage, not decals.
   355→at=, up=, and lift= are inert without on= — the validator rejects them so a typo doesn't silently disappear.
   356→Example: a logo on the front of a shirt, plus an authored handwriting overlay on a paper card.
   357→
   358→material "shirt" (color=[0.1, 0.2, 0.6])
   359→material "paper" (color=[0.96, 0.94, 0.88], roughness=0.95)
   360→
   361→scene {
   362→  box "shirt" (size=[0.6, 0.8, 0.2], mat="shirt")
   363→  decal "shirt_logo" (
   364→    pos = [0, 0.1, 0.101],
   365→    size = [0.25, 0.12],
   366→    prompt = "embroidered MoGen logo, white thread on dark fabric"
   367→  )
   368→
   369→  panel "card" (size=[0.4, 0.3, 0.01], mat="paper", right_of="shirt", gap=0.2)
   370→  decal "note" (
   371→    pos = [0.6, 0.0, 0.0061],
   372→    size = [0.30, 0.20],
   373→    rot = [0, 0, 0],
   374→    image = "textures/notes/handwritten_thanks.png"
   375→  )
   376→}
   377→#Connectors
   378→Connectors are oriented frames that a node exposes so other nodes can attach to it. They do not produce geometry.
   379→
   380→box "seat" (pos=[0, 0.5, 0], size=[1.0, 0.1, 1.0]) {
   381→  connector "top"    (at=[0,  0.05, 0], dir=[0,  1, 0], tag=seat_top)
   382→  connector "bottom" (at=[0, -0.05, 0], dir=[0, -1, 0], tag=seat_bottom)
   383→}
   384→Attributes:
   385→
   386→attribute       value   default
   387→at      vec3    [0, 0, 0]
   388→dir     vec3 (any nonzero)      [0, 1, 0]
   389→tag     string or ident empty
   390→radius  number  — (unset)
   391→Internally a connector is stored as a position plus a quaternion that rotates canonical +Y onto dir. tag groups compatible attach points (e.g. every leg top shares tag=leg_top) so downstream fitting logic can pair them.
   392→
   393→When a node is the child of an attach, its pos / rot are still honoured as a local offset on top of the alignment — pos shifts the anchor in the parent's frame and rot rotates the aligned node around its anchor — so a Studio gizmo drag persists across rebuilds.
   394→
   395→#Attach: rigid alignment of two connector frames
   396→attach is the rigid counterpart to conform: it sets a child node's transform so its plug connector lines up exactly with a socket connector on a parent, then reparents the child under the parent. No deformation, no per-vertex work — just a clean alignment with optional roll.
   397→
   398→scene {
   399→  cylinder "trunk"  (radius=0.2, height=1.0) {
   400→    connector "top" (at=[0, 0.5, 0], dir=[0, 1, 0], tag=trunk_top)
   401→  }
   402→  sphere   "canopy" (radius=0.5) {
   403→    connector "stem" (at=[0, -0.5, 0], dir=[0, -1, 0], tag=canopy_stem)
   404→  }
   405→  attach (parent="trunk", child="canopy", socket="top", plug="stem")
   406→}
   407→attribute       required        default effect
   408→parent  yes     —       name of the node carrying the socket connector
   409→child   yes     —       name of the node carrying the plug connector
   410→socket  no      "top"   connector name on parent
   411→plug    no      "bottom"        connector name on child
   412→offset  no      0.0     gap (m) along the socket's outward direction; positive lifts the child away from the parent
   413→twist   no      0.0     roll (degrees) around the socket's axis after alignment
   414→After lowering, the child is reparented under the parent and its local TRS is recomputed so the two connector frames are coincident (+offset along the socket normal, plus twist around it). Any pos= / rot= declared on the child stays as an additive local offset on top of the alignment — that's what lets a Studio gizmo drag survive a rebuild.
   415→
   416→attach also runs per-instance inside array and mirror replicators: when you write the attach inside the body of an array (count=4), each of the four expanded copies resolves its own pair of connectors, so a single declaration glues every copy.
   417→
   418→#Conform: moulding a primitive onto a target surface
   419→conform deforms a child primitive's vertex positions so it lies on a target mesh's surface. It has two modes:
   420→
   421→Path mode (from= / to=) — stretches a strip or tube between two connectors on the target. The canonical case is a zip on a curved sports bag; covers labels wrapped around bottles, gold trim along a shield's edge, hoses lying on a chassis, ribbons spiralling around a vase, stitched seams.
   422→Patch mode (at=) — lays a flat / disc-shaped child down at a single anchor connector and bends it to follow surface curvature locally. The canonical case is a round pocket on the side of the bag; covers brand decals, plates, lids, eye spots, leather patches.
   423→Conform is the deforming counterpart to attach: where attach sets a rigid transform aligning two connector frames, conform mutates the child's mesh. Pick the mode by which attrs you provide — mixing at= with from=/to= is an error, and so is omitting both.
   424→
   425→// Path mode — strip stretched along a curve.
   426→conform (target="bag", child="zip", from="zip_a", to="zip_b",
   427→         along=x, lift=0.005)
   428→
   429→// Patch mode — disc anchored at a single point.
   430→conform (target="bag", child="pocket", at="pocket_spot", lift=0.002)
   431→#Shared attributes
   432→attribute       required        default effect
   433→target  yes     —       name of the surface mesh node to mould onto
   434→child   yes     —       name of the primitive whose vertices get deformed
   435→lift    no      0.0     outward offset along the surface normal (m) — typically a fraction of a millimetre to avoid z-fighting
   436→reparent        no      1       reparent child under target after conform; pass 0 to keep its original parent
   437→#Path mode — from= / to=
   438→Each child vertex's coordinate on the along axis becomes a position along the surface path; the perpendicular axes lie tangent / normal to the surface at each sample.
   439→
   440→attribute       required        default effect
   441→from    yes     —       connector name on target — start of the path
   442→to      yes     —       connector name on target — end of the path
   443→along   no      x (flat strips) / y (tubes)     which child-local axis is the path axis
   444→width   no      inferred from along     child-local axis perpendicular to path, tangent to surface
   445→height  no      inferred from along     child-local "thickness" axis (along surface normal)
   446→samples no      64      path subdivisions (clamped to ≥ 2). Increase for high-curvature surfaces
   447→twist   no      0       total roll (degrees) around the path tangent across the strip
   448→Compatible primitives (path mode):
   449→
   450→Flat strips: box, plane, quad, curved_plane, slab, post, panel, wall, spline_ribbon
   451→Tubes: cylinder, capsule, tube, spline_tube (cross-section ring rotates with the surface frame)
   452→Imported meshes via mesh "..." (src="..."): accepted, but along= is required
   453→#Patch mode — at=
   454→Each child vertex is independently snapped to its closest point on the target surface; the child's up axis becomes the surface-outward direction at every vertex. This makes flat decals (a disc, a quad) bend to follow curvature locally without forcing the author to pick a path or supply two endpoints.
   455→
   456→attribute       required        default effect
   457→at      yes     —       connector name on target — patch centre
   458→up      no      y (most flat primitives) / z (quad, leaf_card)  which child-local axis aligns with the surface outward normal
   459→Compatible primitives (patch mode):
   460→
   461→Flat decals: disc, plane, quad, curved_plane, leaf_card
   462→Box-likes used as thin patches: box, slab, panel, wall — give them a small extent on the up axis
   463→Round primitives with a flat side: cylinder, hemisphere, half_cylinder (a thin cylinder makes a perfect round disc)
   464→Imported meshes: accepted, but up= is required
   465→#Rejected primitives
   466→Closed shapes with no canonical surface axis (sphere, ellipsoid, icosphere, torus, torus_arc, superellipsoid, pyramid, cone, frustum, lathe, prism, rounded_box, wedge) and CSG result nodes (union/difference/intersect) are rejected in both modes. The error message names the kind and points to the other mode if it would have worked there (e.g. disc rejected in path mode → suggests patch mode).
   467→
   468→#Tessellation
   469→The deformation reads each child vertex's coordinate on the along axis as its position along the path. A bare box only has two distinct values per axis (the eight corners), so an un-subdivided box can't bend — every interior path frame is skipped and the strip stays straight no matter how curved the target surface is.
   470→
   471→conform therefore inserts planar cuts perpendicular to along whenever the child's tessellation is coarser than samples / 4 segments (clamped to 8–64). Author-controlled subdivision still wins: pass a primitive that's already dense (curved_plane (segments_u=48), cylinder (segments=64), spline_ribbon (samples=64)) and the auto-subdivision is a no-op.
   472→
   473→#Examples
   474→// Zip on a sports bag.
   475→material "leather" (color=[0.18, 0.16, 0.14], roughness=0.85)
   476→material "rubber"  (color=[0.08, 0.08, 0.08], roughness=0.7)
   477→
   478→scene {
   479→  ellipsoid "bag" (size=[1.0, 0.5, 0.5], mat="leather") {
   480→    connector "zip_a" (at=[-0.4, 0.20, 0.22], dir=[0, 0, 1])
   481→    connector "zip_b" (at=[ 0.4, 0.20, 0.22], dir=[0, 0, 1])
   482→  }
   483→  box "zip" (size=[0.8, 0.012, 0.04], mat="rubber")
   484→  conform (target="bag", child="zip", from="zip_a", to="zip_b",
   485→           along=x, lift=0.005)
   486→}
   487→// Wine-bottle label wrapped around a cylindrical bottle.
   488→scene {
   489→  cylinder "bottle" (radius=0.04, height=0.3, mat="glass") {
   490→    connector "label_l" (at=[-0.04, 0.12, 0],  dir=[-1, 0, 0])
   491→    connector "label_r" (at=[ 0.04, 0.12, 0],  dir=[ 1, 0, 0])
   492→  }
   493→  curved_plane "label" (size=[0.25, 0.06], segments_u=48, mat="paper")
   494→  conform (target="bottle", child="label", from="label_l", to="label_r",
   495→           along=x, lift=0.0005)
   496→}
   497→// Hose draped along a chassis: tube child, along=y matches cylinder's long axis.
   498→scene {
   499→  superellipsoid "chassis" (size=[1.6, 0.4, 0.7], ew=2.0, ns=2.0, mat="metal") {
   500→    connector "port_a" (at=[-0.7, 0.20, 0.30], dir=[0, 1, 0])
   501→    connector "port_b" (at=[ 0.7, 0.20, 0.30], dir=[0, 1, 0])
   502→  }
   503→  cylinder "hose" (radius=0.03, height=1.4, mat="rubber")
   504→  conform (target="chassis", child="hose", from="port_a", to="port_b",
   505→           along=y, samples=96, lift=0.005)
   506→}
   507→// Patch mode — round pocket decals on the sides of a sports bag.
   508→scene {
   509→  superellipsoid "body" (size=[0.6, 0.3, 0.3], ew=1.5, ns=1.2, mat="fabric") {
   510→    connector "left_spot"  (at=[-0.3, 0, 0], dir=[-1, 0, 0])
   511→    connector "right_spot" (at=[ 0.3, 0, 0], dir=[ 1, 0, 0])
   512→  }
   513→  disc "pocket_l" (radius=0.08, segments=32, mat="accent")
   514→  disc "pocket_r" (radius=0.08, segments=32, mat="accent")
   515→  conform (target="body", child="pocket_l", at="left_spot",  lift=0.002)
   516→  conform (target="body", child="pocket_r", at="right_spot", lift=0.002)
   517→}
   518→#Pass ordering and reparenting
   519→Conform runs after attach and before skin binding, so an attached child can also be conformed and bind-pose world matrices reflect the deformed geometry.
   520→
   521→By default (reparent=1) the child is moved under the target with an identity local transform — its deformed vertices already live in the target's local frame, so this keeps the scene tree clean. Any user pos= / rot= declared on the child is intentionally discarded once the conform fires. Pass reparent=0 to keep the child's original parent; the deformed mesh is transformed back into the child's local frame and the child's location in the hierarchy is untouched.
   522→
   523→#Path generation
   524→The path is built by chord-and-snap: each sample's chord-interpolated point is projected onto the target surface via closest-point query. This is not a true geodesic, but for the typical conform use cases (smoothly curving surfaces between two connectors), it is visually indistinguishable. Crank samples= up for high-curvature paths.
   525→
   526→twist ramps a roll around the path tangent linearly from 0 at the first sample to twist degrees at the last — useful for spiralling ribbons or bandages where the strip rotates around the path as it walks.
   527→
   528→#Reserved (not yet implemented)
   529→The validator accepts but lowering rejects, with a clear message: direction (projection mode — decal splat from a direction), curve (only "geodesic_lerp" is supported in v1), and via (multi-segment paths).
   530→
   531→#Replicators: mirror, array, stack, grid
   532→Wrapper nodes that create one parent group and either replicate or lay out their children. All four accept the usual transform attributes so the whole cluster can be positioned as a unit.
   533→
   534→#mirror
   535→mirror "pair" (axis=x) {
   536→  sphere "ball" (pos=[0.5, 0.5, 0], radius=0.25)
   537→}
   538→axis is x, y, or z (ident or string). The body is emitted twice — once unchanged and once with the named axis negated. Use it for left/right symmetry where only one side is authored by hand.
   539→
   540→#array
   541→array "legs" (count=4, around=y) {
   542→  group "offset" (pos=[0.45, 0, 0.45]) {
   543→    cylinder "leg" (radius=0.05, height=0.5)
   544→  }
   545→}
   546→Attributes:
   547→
   548→count — number of copies (integer); default 1.
   549→around — x / y / z ident; the rotation axis. Default y.
   550→start_angle — degrees offset of the first copy; default 0.
   551→The children are cloned count times; the i-th copy is rotated by start_angle + 360° * i / count around around. Combine with an offset group (as above) to place the first copy off the rotation axis; the array then fans it into a ring.
   552→
   553→#stack
   554→Lay children out along one axis, using each child's computed AABB as its "slot". No half-size math, no accumulated offsets to maintain by hand.
   555→
   556→stack "cake" (axis=y, gap=0.02) {
   557→  slab "tier_a" (size=[1.4, 0.25, 1.4])
   558→  slab "tier_b" (size=[1.0, 0.20, 1.0])
   559→  slab "tier_c" (size=[0.6, 0.15, 0.6])
   560→}
   561→Attributes:
   562→
   563→attribute       value   default effect
   564→axis    x, y, z y       stacking direction
   565→gap     number  0       spacing between consecutive children
   566→align   center, start, end      center  alignment on the two perpendicular axes
   567→pack    start, center, end      start   where the whole stack sits along axis: start keeps the first child at origin; center centres the stack; end puts the last child's far face at origin
   568→Each child keeps its own declared pos/x/y/z as an additive offset inside its slot — stack computes the slot position, your pos nudges within it.
   569→
   570→#grid
   571→N-dimensional replicator. Creates count[0] × count[1] × count[2] copies of the body, each offset by step[0..3] * [i, j, k]:
   572→
   573→grid "tiles" (count=[5, 1, 3], step=[0.6, 0, 0.6], center=1) {
   574→  slab "tile" (size=[0.55, 0.05, 0.55])
   575→}
   576→Attributes:
   577→
   578→attribute       value   default
   579→count   vec3, list, or scalar   [1, 1, 1]
   580→step    vec3, list, or scalar   [0, 0, 0]
   581→center  0 / 1   0 — when 1, the grid is centred on the wrapper origin
   582→A scalar count/step applies to X only (useful for 1D rows); a 2-element list applies to X/Z (floor patterns). For 3D, pass a vec3.
   583→
   584→#CSG: union / difference / intersect
   585→CSG ops fold their children into a single mesh that hangs off the op node itself — the operand children do not become separate scene nodes.
   586→
   587→difference "wall_with_door" (mat="concrete") {
   588→  box "wall"    (size=[4.0, 3.0, 0.2])
   589→  box "doorway" (pos=[0, -0.5, 0], size=[0.9, 2.0, 0.5])
   590→}
   591→union — N ≥ 1 operands; the union of all. Accepts an optional smooth=<radius> attribute that swaps the boolean union for a smooth minimum (smin) blend with that radius. Used by the humanoid stdlib modules to fillet limb-to-torso seams; values of a few centimetres are typical at human scale. smooth=0 (the default) is identical to the hard boolean.
   592→difference — the first operand minus every subsequent operand.
   593→intersect — N ≥ 2 operands; the shared volume.
   594→Operand transforms are baked into the vertices at evaluation time, so each operand lives in the parent's frame regardless of its local pos/rot. Connectors and material children declared directly on the CSG node still apply; any on operand children are ignored.
   595→
   596→The output is cleaned (vertex welding, degenerate-tri cull, normal recompute) to give the exporter a watertight mesh.
   597→
   598→#Solid groups: solid
   599→solid { … } is a group-like container that defers CSG union to export time. Its same-material, non-skinned leaf children are merged into a single mesh, so overlapping or touching primitives of the same material read as one hollow shape — interior faces where pieces meet get eliminated.
   600→
   601→solid "shell" (mat="stone", cleanup="coplanar") {
   602→  box "floor"   (pos=[0, 0.1, 0],   size=[6.2, 0.2, 4.2])
   603→  box "north"   (pos=[0, 1.7, 2.0], size=[6.0, 3.0, 0.2])
   604→  box "south"   (pos=[0, 1.7,-2.0], size=[6.0, 3.0, 0.2])
   605→  box "east"    (pos=[ 3.0, 1.7, 0], size=[0.2, 3.0, 4.0])
   606→  box "west"    (pos=[-3.0, 1.7, 0], size=[0.2, 3.0, 4.0])
   607→}
   608→Children lower as normal scene nodes — you can still attach to them, put modules inside, author connectors, and so on. The merge is export-time, scoped to that subtree. The in-memory scene graph the editor sees keeps every child as a distinct, editable node.
   609→Only same-material leaf siblings merge together. Different-material children (mat="glass" next to mat="stone") stay as separate nodes so textures and PBR factors are preserved.
   610→Skinned meshes, joint-referenced nodes, and groups are never merged; they pass through unchanged.
   611→#cleanup="coplanar"
   612→When set, the merged output gets one extra pass that drops triangle pairs which share a plane and have opposite-facing normals. This catches the case CSG union can't resolve on its own: two boxes that touch along a face without overlapping — e.g. perpendicular walls meeting at a corner. Without the cleanup, both sides of the seam survive; with it, they cancel.
   613→
   614→Values: "coplanar" (enable) or "none" (default).
   615→
   616→#Modules: module and use
   617→Modules are parametric sub-graphs. A declaration lives at the top level of the file:
   618→
   619→module "leg" (height=0.5, radius=0.05) {
   620→  cylinder "leg" (pos=[0, $height * 0.5, 0],
   621→                  radius=$radius, height=$height, mat="wood") {
   622→    connector "top" (at=[0, $height * 0.5, 0], dir=[0, 1, 0], tag=leg_top)
   623→  }
   624→}
   625→Parameters:
   626→
   627→Each parameter has a scalar default (number or expression). vec3, list, string, or ident defaults are rejected — $param substitution is numeric.
   628→Parameters are referenced inside the body as $name. They participate in pos, rot, scale, radius, height, etc., and inside nested vec3 expressions like [0, $h * 0.5, 0].
   629→Invoke a module with use:
   630→
   631→scene {
   632→  group "chair" {
   633→    use "leg" (height=0.6, radius=0.04)
   634→    array "legs" (count=4, around=y) {
   635→      group "offset" (pos=[0.45, 0, 0.45]) {
   636→        use "leg" (height=0.5, radius=0.05)
   637→      }
   638→    }
   639→  }
   640→}
   641→Rules:
   642→
   643→use takes the module's declared name. Unknown names fail with a clear error.
   644→Omitted arguments fall back to declared defaults. Unknown argument names are a hard error (catches typos).
   645→Modules may call other modules. Recursion is detected and rejected.
   646→Expansion is lexically scoped — $param references outside a module body are rejected.
   647→#Imports: import
   648→Pull module declarations, material declarations, and the entire scene { … } of another .mog file into the current file. Two use cases:
   649→
   650→Module libraries — share parameterised modules across files:
   651→
   652→import "shared/legs.mog"
   653→
   654→scene {
   655→  use "leg" (h=0.6)
   656→}
   657→Scene composition — assemble a scene out of object .mog files. Each imported file's top-level scene { … } becomes an implicit module named after the file stem, so import "chair.mog" lets you use "chair" ():
   658→
   659→import "objects/chair.mog"
   660→import "objects/table.mog"
   661→
   662→scene {
   663→  use "chair" (pos=[ 1, 0, 0])
   664→  use "table" (pos=[ 0, 0, 0])
   665→  use "chair" (pos=[-1, 0, 0], rot=[0, 180, 0])
   666→}
   667→use accepts the same translation/rotation/scale shortcuts as every other node kind — pos, rot, scale, x / y / z, rx / ry / rz, and from / to — and applies them as an implicit wrapping group around the expanded body. Equivalent to group (pos=…) { use "x" () } but without the ceremony. If the module declares a parameter with one of those names (e.g. a scalar pos param), the caller's value binds to the parameter instead.
   668→
   669→import is a top-level directive — declare it alongside material and module, before or after them. It takes a quoted file path and an optional (as=<ident>) to override the synthesised module name (handy when two files share a stem, since stem collisions are a hard error).
   670→
   671→Path resolution:
   672→
   673→Relative paths are joined onto the importing file's directory. So import "shared/legs.mog" from /proj/scenes/chair.mog reads /proj/scenes/shared/legs.mog.
   674→Absolute paths are used verbatim.
   675→Paths are canonicalised before deduplication, so import "lib.mog" and import "./lib.mog" resolve to the same file and load only once.
   676→What gets lifted from an imported file:
   677→
   678→module declarations — added to the importer's module registry.
   679→material declarations (top-level or inside the imported scene { … }) — added to the importer's material registry. Texture paths are rooted at the defining file's directory: material "wood" (base_color_texture = "textures/wood.png") inside objects/chair.mog resolves to objects/textures/wood.png regardless of where the composing scene lives.
   680→Top-level scene { … } — synthesised as module "<stem>" () { … }. Use (as=<ident>) on the import to give it a different name.
   681→Rules:
   682→
   683→Imports are transitive: an imported file can import another file, and every transitively-imported module / material / synthesised scene is visible to the original importer.
   684→Cycles (A imports B imports A) are detected and rejected with the full chain in the error message.
   685→Importing the same file twice — directly or via a chain — is a no-op.
   686→Module name shadowing follows precedence: stdlib < imports < user declarations. A user module "leg" { … } in the importing file overrides any leg pulled in by import; an imported leg overrides the stdlib's leg.
   687→Synthesised scene-as-module collisions are a hard error. If two imports both default to chair (one in a/chair.mog, one in b/chair.mog), rename one with (as=chair_a).
   688→Material name collisions across imports are a hard error. Re-declare the material in the importing file to shadow it.
   689→An imported file may contain only import, module, material, and a single top-level scene { … }. Other top-level forms (joints, clips, skeletons) aren't composable yet and are rejected.
   690→Failures surface as errors at mogen check / mogen build time, pointing at the offending import.
   691→
   692→#Animation: joint, clip, templates
   693→Animation lowers to glTF node-transform tracks. Every clip animates one or more scene nodes (or joints, which are scene-node aliases with a typed DOF) — there is no separate animation graph or state machine. Clips are top-level declarations alongside material/module/joint. Skinning is additive: see Skeletons and skinning below for the skeleton/bone/skin= half of the story.
   694→
   695→#Joints
   696→A joint names an articulation, picks a DOF type, and points at the scene node that rotates/translates when the joint moves.
   697→
   698→joint "door_hinge" (type=hinge, axis=[0, 1, 0], limits=[0, 100], pivot="door")
   699→attribute       value   notes
   700→type    hinge, slider, ball, rotor      DOF kind
   701→pivot   string — a node name    required
   702→axis    vec3    default [0, 1, 0]
   703→limits  [lo, hi] list   optional; degrees (rotary) or meters (slider)
   704→#Authored clips
   705→clip "open" (seconds=1.0) {
   706→  track "door_hinge" (from=0, to=90)
   707→}
   708→clip holds a single duration and an ordered list of track children.
   709→track targets a joint (by name) or a scene node directly. When targeting a node, add prop="translation"|"rotation"|"scale" to pick the channel (pos / rot are accepted aliases).
   710→from / to are scalars. For rotation they're degrees around the joint's axis (or the track's axis= when targeting a plain node); for translation they're distance along the axis; for scale they're the uniform factor. Two keyframes are emitted at 0 and seconds and linearly interpolated.
   711→For multi-keyframe authored curves, pass keys=[[t, v], …] instead of from/to. Times must be strictly ascending and span any subset of [0, seconds] — the exporter emits one glTF keyframe per pair and interpolates linearly between them. This is what the stdlib walk / run / jump clips use to drive bones with hand-tuned curves.
   712→#Procedural templates
   713→One-line declarations that expand into a full clip. They all take a target="name" pointing at a joint or a scene node.
   714→
   715→template        extra attrs     effect
   716→spin    axis, rpm (60)  continuous rotation
   717→open_close      axis, angle (90), seconds (1.0) 0° → angle → 0° swing
   718→wave    axis, amplitude (15°), hz (1.0) sinusoidal wobble
   719→flap    axis, amplitude (30°), hz (2.0) faster wobble, bigger amplitude
   720→idle    amplitude (0.02 m), hz (0.5)    tiny translation breathe
   721→When the target is a joint, its axis is used by default; when it's a node, pass axis explicitly.
   722→
   723→spin "rotor_spin" (target="rotor", axis=[0, 0, 1], rpm=30)
   724→open_close "door_swing" (target="door_hinge", angle=90, seconds=1.2)
   725→#Skeletons and skinning: skeleton, bone, skin=, bind=
   726→A skeleton is a hierarchy of named bone nodes that drives skinning weights on procedural meshes. Bones are ordinary scene nodes (kind="bone"); the skeleton block produces a Skin whose joints list captures every descendant bone in depth-first order. Bind-pose inverse matrices are computed automatically from the bones' world transforms at lower time, so the author never writes a Mat4.
   727→
   728→scene {
   729→  skeleton "rig" {
   730→    bone "hip"      (pos=[0, 0.95, 0], envelope=0.25) {
   731→      bone "spine"  (pos=[0, 0.30, 0], envelope=0.25) {
   732→        bone "neck" (pos=[0, 0.30, 0], envelope=0.10)
   733→      }
   734→      bone "thigh_l" (pos=[ 0.10, -0.05, 0], envelope=0.25)
   735→      bone "thigh_r" (pos=[-0.10, -0.05, 0], envelope=0.25)
   736→    }
   737→  }
   738→
   739→  capsule "torso" (pos=[0, 1.25, 0], radius=0.18, height=0.6,
   740→                   mat="cloth", skin="rig")
   741→  sphere  "head"  (pos=[0, 1.7,  0], radius=0.12, mat="skin",
   742→                   skin="rig", bind="neck")
   743→}
   744→#skeleton and bone
   745→skeleton "name" { … } declares the rig. Inside, every child must be a bone. Bones may nest arbitrarily — each bone becomes a scene node parented under the previous one, so its pos/rot/scale are parent-relative.
   746→bone "name" (pos=…, rot=…, scale=…, envelope=…) declares a joint. envelope= (default 0.75) controls how far the bone's influence reaches when the auto-skinner assigns weights to nearby vertices — smaller envelopes are tighter, larger envelopes blend more across joints. Adjacent bones should overlap in envelope so vertices near a shared joint receive weight from both sides.
   747→Skeletons are top-level or scene-level declarations. They place themselves in the scene tree (so they animate alongside other nodes), but they don't carry geometry of their own.
   748→
   749→#Binding meshes: skin="rig"
   750→Any mesh-bearing node (primitive or import) with skin="<skel name>" becomes a skinned mesh: the lowering pass walks the skeleton, computes per-vertex weights against the four nearest bones (capped by each bone's envelope), and writes them into the GLB as JOINTS_0 / WEIGHTS_0 accessors. Group-like containers (group, solid, stack, grid, array, mirror, module, use) propagate skin= to every mesh descendant, so wrapping a sub-tree in group (skin="rig") { … } skins the whole thing in one line.
   751→
   752→#Rigid pinning: bind="bone_name"
   753→Add bind="bone" alongside skin= to pin every vertex of that mesh rigidly to a single bone — weight 1.0, no envelope blend. Used for accessories that should track a joint without deforming: heads (bound to the neck), helmets, backpacks, hand-held props. bind propagates from a group to its descendants the same way skin= does, so a face cluster parented under a group (bind="neck") follows the head as one rigid piece.
   754→
   755→#Animating bones
   756→Bones are scene nodes, so the regular clip { track … } machinery drives them: track "thigh_l" (prop=rotation, axis=[1, 0, 0], keys=[…]). The stdlib humanoid_walk / humanoid_run / humanoid_idle / humanoid_jump modules expand into clips of exactly this shape, targeting the bones declared by humanoid_full. There is no separate "animation rig" — if you can drive a node, you can drive a bone.
   757→
   758→CSG operands (union/difference/intersect children) are fused into the parent's mesh during lowering, so a stray skin= on an operand never survives. Put skin= on the CSG node itself (or on a wrapping group) instead.
   759→
   760→#Lights: light
   761→mogen exports lights via the standard glTF KHR_lights_punctual extension. A light is a transform-only scene node — it carries pos / rot like any other node, has no mesh, and never accepts children. Direction is implicit: the light points along its local -Z axis.
   762→
   763→light "sun"  (kind=directional, dir=[-0.4, -1, -0.3], color=[1, 0.95, 0.85], intensity=3)
   764→light "lamp" (kind=point, pos=[0, 2, 0], color=[1, 0.9, 0.7], intensity=10, range=8)
   765→light "spot" (kind=spot,  pos=[0, 3, 0], dir=[0, -1, 0], intensity=20,
   766→              range=10, inner_cone=20, outer_cone=35)
   767→attribute       value   notes
   768→kind    directional, point, spot        required
   769→color   vec3    linear-space RGB; default [1, 1, 1]
   770→intensity       number  candela for point/spot, lux for directional; default 1.0
   771→range   number  distance cutoff for point/spot; rejected on directional
   772→dir     vec3    optional shortcut: rotates the node so -Z points along dir (overrides rot=)
   773→inner_cone      number  spot only; degrees, default 0
   774→outer_cone      number  spot only; degrees, default 45
   775→Lights ignore mat, anchor, from/to, and the relative-placement shortcuts (above/below/…) — only transforms (pos, rot, scale, x/y/z, rx/ry/rz), role, and tags apply.
   776→
   777→mogen does not emit an ambient term: the glTF core spec has no ambient light, and Godot derives ambient from a WorldEnvironment node downstream. For low-intensity fill, use a dim directional light (e.g. intensity=0.5, dir=[0, -1, 0]) or set up an environment in your engine.
   778→
   779→#Colliders
   780→Annotate any geometry, group, solid, or use with collider="aabb" to mark it as a collision volume:
   781→
   782→slab "floor"     (size=[18.4, 0.1, 10.4], mat="wood", collider="aabb")
   783→slab "wall_back" (size=[18.4, 3, 0.2], z=-5.1, mat="plaster", collider="aabb")
   784→use  "desk"      (pos=[0, 0, 0.4], collider="aabb")
   785→The bounding box is derived at compile time from the node's subtree mesh extents in node-local space, after attach / conform / skin binding have finished — so a collider on use "desk" encloses the whole desk, and a collider on a conform-deformed plank reflects the bent vertices, not the straight ones.
   786→
   787→"aabb" is the only accepted value in v1; anything else raises a build error. A collider on a node whose subtree carries no mesh is silently dropped (the attribute lives on, but the box is omitted from the output).
   788→
   789→The export writes one entry per collider'd node into glTF node.extras.collider:
   790→
   791→json"extras": {
   792→  "collider": {
   793→    "type": "aabb",
   794→    "min": [-9.2, -0.05, -5.2],
   795→    "max": [ 9.2,  0.05,  5.2]
   796→  }
   797→}
   798→mogen does not run a physics simulation — this is metadata for the downstream importer to convert into a CollisionShape3D (or equivalent). MoGen Studio renders an off-by-default wireframe gizmo at each collider'd node; toggle it from View → Show Colliders or the viewport context menu.
   799→
   800→#Shadow casting
   801→Every node casts shadows by default. Add cast_shadow=0 to opt a node — and its entire subtree — out of the realtime shadow pre-pass and the exported shadow hint:
   802→
   803→plane "ground" (size=20, mat="grass", cast_shadow=0)
   804→group "filler" (cast_shadow=0) {
   805→  box (size=[1, 1, 1])     # inherits cast_shadow=0
   806→  use  "rocks"             # inherits too
   807→}
   808→The flag propagates monotonically: an ancestor's cast_shadow=0 overrides a descendant default. Setting it on a child while a parent already disabled it is a no-op (the descendant stays opted out).
   809→
   810→The export writes extras.cast_shadow=false only on opted-out nodes; the typical "casts shadow" case omits the key entirely so the JSON chunk stays lean. Downstream importers that don't recognise the key fall back to the glTF default (casts shadow), matching the spec.
   811→
   812→The right-sidebar inspector exposes the toggle as a checkbox under Shadow.
   813→
   814→#Full example
   815→A door in a wall, with a swinging-open animation, built end-to-end:
   816→
   817→material "wood"     (color=[0.55, 0.35, 0.18], roughness=0.8)
   818→material "concrete" (color=[0.78, 0.78, 0.78], roughness=0.85)
   819→
   820→scene {
   821→  difference "wall_with_door" (mat="concrete", role="wall") {
   822→    box "wall"       (size=[4.0, 3.0, 0.2])
   823→    box "door_gap"   (pos=[0, -0.5, 0], size=[0.9, 2.0, 0.5])
   824→  }
   825→
   826→  // Hinge at the left edge: offset the panel by half-width inside the group.
   827→  group "door" (pos=[-0.45, 1.0, 0]) {
   828→    box "panel" (pos=[0.45, 0, 0], size=[0.9, 2.0, 0.04], mat="wood")
   829→  }
   830→}
   831→
   832→joint "door_hinge" (type=hinge, axis=[0, 1, 0], limits=[0, 100], pivot="door")
   833→clip "open" (seconds=1.2) {
   834→  track "door_hinge" (from=0, to=90)
   835→}
   836→Compile with mogen build examples/<file>.mog -o out.glb and open in any glTF-2.0 viewer or game engine.

   869→#Common flags and conventions
   870→A few flag patterns repeat across every LLM-driven subcommand (generate, modify, animate, repair, textures, bench):
   871→
   872→flag    meaning
   873→--api-key <KEY> Override GEMINI_API_KEY for this invocation.
   874→--model <NAME>  Gemini model id. Default gemini-pro-latest for text. For textures, the default depends on credentials: gemini-3-pro-image-preview when authenticated via OAuth (paid plan), otherwise gemini-2.5-flash-image. Pass gemini-3.1-flash-image-preview (or any other image model) to override.
   875→--temperature <N>       Sampling temperature. Library default is 0.3 when omitted.
   876→--thinking <low|medium|high|xhigh>      Cap server-side reasoning. low = 512 tokens, medium = 2048, high = 8192 (default), xhigh = 24576 (slowest, most careful).
   877→--budget_tokens <N>     Abort if total prompt + response token count exceeds this limit.
   878→--max-repair-iters <N>  Repair attempts after the first try. Default 2.
   879→--cached-content <NAME> Reuse an existing cachedContents/... resource for the system instruction (skips re-uploading the grammar/stdlib reference).
   880→--no-cache      Disable the automatic system-instruction cache. By default mogen creates and reuses a cachedContents resource per-binary so repeated calls skip re-upload.
   881→--seed <U64>    Seed embedded in the DSL header for reproducibility. Defaults to the seed parsed from an existing .mog's header, or a random one if absent.
   882→--dry-run       Skip GLB compilation and disk writes — print the generated/edited DSL only.
   883→The seed, the thinking budget, and the original prompt are stamped into the top-level meta(...) block of every generated .mog:
   884→
   885→mogmeta (
   886→  mogen_version = "0.1.1",
   887→  seed = "1777210527637284168",
   888→  thinking = "high",
   889→  prompt = "A simple four-legged chair.",
   890→)
   891→#auth
   892→Sign in / out for every credential mogen persists under ~/.mogen/. The command is target-aware: mogen auth <target> <verb> where <target> is one of gemini-cli, antigravity, or moghub. The top-level mogen auth status (no target) prints a one-line summary for every target at a glance.
   893→
   894→shmogen auth status                          # one-line summary per target
   895→mogen auth gemini-cli  {login,status,logout}
   896→mogen auth antigravity {login,status,logout}
   897→mogen auth moghub      {login,status,logout}
   898→target  what it authenticates   on-disk file
   899→gemini-cli      Google OAuth for text gen via Cloud Code Assist ~/.mogen/google_auth.json
   900→antigravity     Google OAuth for image gen via Cloud Code Assist        ~/.mogen/antigravity_auth.json
   901→moghub  MoGHub session UUID for community publishing + browsing ~/.mogen/moghub_auth.json
   902→All three login flows use a loopback browser handshake — gemini-cli and antigravity go through Google's OAuth consent screen on a fixed loopback port (51121); moghub opens <server>/api/auth/desktop/start and waits for the redirect back. On Unix the resulting files are written with mode 0600.
   903→
   904→flag    applies to      meaning
   905→--force every target's login    re-authenticate even if a valid token is already on disk.
   906→--no-browser    gemini-cli, antigravity print the authorize URL instead of opening a browser (useful over SSH).
   907→--timeout <SECS>        gemini-cli, antigravity how long to wait for the OAuth callback. Clamped to [10, 3600]. Default 300.
   908→--server <URL>  moghub  sign in against a self-hosted MoGHub instance. The URL round-trips into the on-disk session.
   909→--verbose       every target's status   extra detail — token-store path, OAuth scopes, the chosen cloudcode-pa endpoint, and (for moghub) a live whoami round-trip.
   910→shmogen auth gemini-cli login                         # zero-config, opens browser
   911→mogen auth antigravity login                        # required for OAuth-driven `mogen textures`
   912→mogen auth moghub login --server https://staging.moghub.org
   913→
   914→mogen auth status --verbose                         # show every target with full detail
   915→mogen auth gemini-cli logout                        # scope sign-out per target
   916→mogen generate / modify / animate / repair automatically use the gemini-cli OAuth bundle whenever GEMINI_API_KEY is unset; mogen textures prefers the antigravity bundle when present (set MOGEN_IMAGE_PROVIDER=antigravity to force it). The MoGHub session file is shared with Studio, so signing in once via the CLI surfaces the session in the desktop's Community window and vice versa.
   917→
   918→logout walks every legacy path (~/.cache/mogen/, %LOCALAPPDATA%\mogen\) so a half-cleaned upgrade can't silently re-authenticate. None of the logout commands call the upstream revoke endpoint — refresh tokens stay valid server-side until the user explicitly revokes consent at https://myaccount.google.com or signs out of MoGHub on the web.
   919→
   920→#build
   921→Compile a DSL file to a GLB.
   922→
   923→shmogen build <input.mog> [--out <output.glb>]
   924→flag    meaning
   925→--out, -o       Output GLB path. Defaults to <input>.glb alongside the source file.
   926→Pipeline. build runs the canonical front-to-back pipeline:
   927→
   928→Parse the DSL (pest grammar).
   929→AST validation — referential and typing errors with source spans.
   930→Lower to SceneGraph — module expansion, placement shortcuts, attach solver, animation/skinning lowering.
   931→Graph validation — topological invariants (skeleton ancestry, weight sums, …).
   932→Export GLB — PBR materials, embedded textures, animation channels, optional skin data, optional sibling-mesh merge.
   933→generate, modify, animate, repair, and textures all converge on this command at the end of their flows. If you've already authored a .mog, build is what you run.
   934→
   935→shmogen build examples/chair.mog --out chair.glb
   936→#parse
   937→Parse a DSL file and print the AST. Useful when debugging grammar errors or checking how a tricky source string lowers.
   938→
   939→shmogen parse <input.mog>
   940→No GLB is produced. Lowering and validation are skipped.
   941→
   942→#check
   943→Validate a DSL file. Exits non-zero on any error.
   944→
   945→shmogen check <input.mog> [--json]
   946→flag    meaning
   947→--json  Emit diagnostics as line-delimited JSON instead of human-readable carets.
   948→Validation is dual: AST-level (typing, references, unknown attributes) and graph-level (topology, weights, skeleton roots). The two phases produce a unified diagnostic list. Human mode renders via codespan-reporting; JSON mode emits one diagnostic per line in the format the LLM repair loop consumes.
   949→
   950→shmogen check examples/chair.mog                          # human-readable
   951→mogen check examples/chair.mog --json | jq .            # machine-readable
   952→#dump-scene
   953→Lower a DSL file and print the resulting scene graph. Useful for inspecting what an LLM actually emitted, or for diffing two .mog files post-lowering.
   954→
   955→shmogen dump-scene <input.mog> [--json]
   956→flag    meaning
   957→--json  Emit the graph as JSON instead of an indented summary.
   958→#inspect
   959→Read a GLB and print its top-level structure: scenes, meshes, materials, animations, skins, extensions, embedded image sizes.
   960→
   961→shmogen inspect <output.glb>
   962→The same machinery that powers MoGen Studio's "GLB summary" panel; useful for verifying what actually landed in a release artifact.
   963→
   964→#generate
   965→Generate a .mog from a natural-language prompt via Gemini, validate it, repair JSON diagnostics in a loop, then compile it to a GLB.
   966→
   967→shmogen generate "<prompt>" [--out <out.glb>] [--dsl-out <out.mog>] [common LLM flags]
   968→flag    meaning
   969→--out, -o       Output GLB path. Ignored with --dry-run.
   970→--dsl-out       Where to stash the generated DSL. Defaults to the sibling of --out with a .mog extension. Required with --dry-run if you want to keep the DSL on disk.
   971→--seed  Embedded seed; randomised if omitted.
   972→--model Gemini model id. Default gemini-pro-latest.
   973→--dry-run       Print the generated DSL but skip compilation and GLB output.
   974→Plus all common LLM flags above.        
   975→Repair loop. If the generated DSL fails validation, generate re-feeds the JSON diagnostics back to Gemini up to --max-repair-iters times. On the final failure it prints the unfixed diagnostics and exits non-zero, leaving the broken .mog on disk for inspection.
   976→
   977→shmogen generate "a wooden stool" --out stool.glb
   978→mogen generate "a clockwork dragon" --thinking xhigh --out dragon.glb

  1012→#textures
  1013→Generate PBR textures for every material in a .mog. The albedo is LLM-drawn via Gemini 2.5 Flash Image, then locally derived normal, metallic-roughness, and occlusion maps are computed from the albedo (Sobel-from-luminance, variance-based, cavity-based). PNGs are written next to the .mog and the matching *_texture="…" attrs are spliced back into the source via spans (no reformatting).
  1014→
  1015→shmogen textures <input.mog> [--style "<hint>"] [--texture-size <N>]
  1016→flag    meaning
  1017→--out   Where to write the modified .mog. Defaults to in-place.
  1018→--glb   GLB output path. Defaults to <input>.glb.
  1019→--textures-dir  Where PNGs are written. Defaults to textures/<mog-stem>/ so sibling assets don't collide on shared material names.
  1020→--style Style hint appended to each image prompt. Default photorealistic.
  1021→--model Gemini image model id. Default depends on credentials: gemini-3-pro-image-preview when authenticated via OAuth, otherwise gemini-2.5-flash-image. Pass gemini-3.1-flash-image-preview (or any other image model) to override.
  1022→--force Regenerate slots whose attr is already declared in the .mog or whose PNG already exists at the planned path.
  1023→--dry-run       Print the plan and skip all API calls and file writes.
  1024→--no-build      Stop after rewriting the .mog; don't run build.
  1025→--no-pbr        Skip every derived PBR map (normal / MR / AO). Albedo is still generated.
  1026→--no-normal / --no-metallic-roughness / --no-occlusion  Skip a specific derived map.
  1027→--texture-size <N>      Cap (in pixels) on the longer side of every generated albedo. Derived PBR maps inherit this size — the single lever for embedded-texture footprint. 0 keeps the model's native resolution (typically 1024²).
  1028→--api-key       Override GEMINI_API_KEY.
  1029→Idempotency. Per slot, materials that already declare a given *_texture attr — or whose target PNG already exists at the planned path — are skipped unless --force is passed. Existing on-disk PNGs still get their *_texture attr spliced into the source, just without an API call or a local re-derivation.

  1032→mogen textures examples/drone.mog --no-occlusion --texture-size 512
  1033→mogen textures examples/chair.mog --dry-run                          # see the plan first

  1103→#moghub publish
  1104→Publish a .mog to MoGHub. Bundles the entry .mog plus every locally-imported .mog and every referenced PNG / JPG / JPEG / WebP texture into a single submission. Requires login.
  1105→
  1106→shmogen moghub publish <input.mog> [flags]
  1107→flag    meaning
  1108→--title Override meta(name=…) for this publish. Required if the source has no meta(name=…).
  1109→--description   Override meta(description=…).
  1110→--tags "a,b,c"  Comma-separated tag list. Lowercased and capped at 8. Overrides meta(tags=[…]).
  1111→--license       SPDX-style license id. Defaults to CC0-1.0.
  1112→--visibility    public, unlisted, or private. Defaults to public.
  1113→--message, -m   Version changelog message.
  1114→--thumbnail     Path to a PNG to attach as the model thumbnail.
  1115→--filename      Override the published filename. Defaults to the input file's basename.
  1116→--module        Publish as a registry-importable module. Mutually exclusive with --scene.
  1117→--scene Publish as a scene. Mutually exclusive with --module.
  1118→--new   Force creation of a new model even if the source carries a prior MoGHub stamp.
  1119→--server        Target a self-hosted MoGHub instance.
  1120→Defaults from meta(...). When --title, --description, or --tags are omitted, publish reads the corresponding key from the source's top-level meta(...) block. Any locally-imported .mog (via use "file.mog") is bundled automatically; their filenames must not collide with the entry filename.
  1121→
  1122→Scene vs. module. If neither --module nor --scene is passed, the source is published as a module when it has no import declarations and as a scene when it does. Pass an explicit flag to override.
  1123→
  1124→Updates round-trip. On success, publish writes three keys back into the source's meta(...) block:
  1125→
  1126→mogmeta (
  1127→  ...
  1128→  moghub_model_id = "…",
  1129→  moghub_slug     = "…",
  1130→  moghub_version  = "2",
  1131→)
  1132→Subsequent moghub publish runs read those keys and append a new version (moghub_version + 1) to the same model. Pass --new to ignore the stamp and create a fresh model instead.
  1133→
  1134→Texture bundling. Every string attribute that ends in .png, .jpg, .jpeg, or .webp is resolved relative to the .mog it appears in (entry or import) and uploaded. All texture paths must resolve inside the entry's directory — references that point to a parent directory are rejected so the upload bundle stays self-contained.

  1137→mogen moghub publish examples/chair.mog -m "added armrests"          # appends a new version
  1138→mogen moghub publish examples/chair.mog --new --visibility unlisted  # forks off a fresh model
  1139→#mcp
  1140→Run mogen as an MCP (Model Context Protocol) server over stdio. Every other CLI subcommand is exposed as a tool the connected LLM client can invoke, so an MCP-aware client can drive the full mogen pipeline — compile, validate, inspect, generate, publish — without shelling out manually.
  1141→
  1142→shmogen mcp
  1143→Speaks JSON-RPC on stdin/stdout — don't run it interactively. Launch it from an MCP client (Claude Desktop, a custom client, etc.). Tracing logs are routed to stderr so they never corrupt the protocol stream; set RUST_LOG to tune verbosity (defaults to warn).
  1144→
  1145→How it works. Each tool call spawns the same mogen binary as a subprocess with the equivalent CLI arguments, captures stdout and stderr, and returns them as the tool result. Behaviour is identical to running the command from a terminal — same auth files (~/.mogen/…), same env vars (GEMINI_API_KEY, MOGEN_CACHE_DIR, …), same exit semantics. Non-zero exits surface as MCP tool errors with stderr bundled in so the calling LLM can repair from the diagnostics.
  1146→
  1147→Paths are server-relative. Every <input.mog> / --out path passed to a tool is resolved against the working directory mogen mcp was launched from, not the LLM client's notion of cwd. Configure your MCP client to launch the server in the project directory you want it to operate on.
  1148→
  1149→Tool catalog. Tool names mirror the CLI subcommands with hyphens replaced by underscores (e.g. dump-scene → dump_scene); MoGHub verbs are prefixed with moghub_ (moghub_whoami, moghub_discover, moghub_info, moghub_download, moghub_comments, moghub_comment, moghub_like, moghub_unlike, moghub_notifications, moghub_publish). The full set: build, parse, check, dump_scene, inspect, thumbnail, generate, modify, animate, repair, textures, update, bench, plus the moghub_* family.

  1173→Module catalog
  1174→How `module` and `use` work, plus the stdlib module catalog (humanoid, animals, foliage).
  1175→
  1176→Modules are parametric sub-graphs: reusable snippets of DSL that take scalar parameters, expand to a tree of primitives, and can expose connectors for downstream composition. The full language is documented in dsl.md; this page is a catalog of the modules shipped in the stdlib and a recipe for adding more.
  1177→
  1178→How modules resolve
  1179→Authoring a new module
  1180→Stdlib catalog
  1181→Humanoid — body, head, limbs, hands, feet, face, hair
  1182→Humanoid animations — idle, walk, run, jump
  1183→Animals — quadruped torso/leg, tail, ear, eye
  1184→Foliage — leaf, branch
  1185→#How modules resolve
  1186→Given a call use "leg" (height=0.5):
  1187→
  1188→Look up "leg" in the module registry — a flat map populated from three sources, in this precedence order: **user declarations > imports
  1189→stdlib**. A user module "leg" { … } shadows any imported leg, and an imported leg shadows the stdlib's leg.
  1190→
  1191→Bind caller arguments (height=0.5) against the declared parameter list. Unknown argument names are a hard error (catches typos).
  1192→Fill declared defaults for any parameter the caller omitted.
  1193→Expand the module body, substituting every $name with its bound numeric value. vec3, list, string, or ident defaults are not accepted — every parameter is scalar.
  1194→Recurse: module bodies may themselves call use, up to a recursion- depth check that prevents accidental loops.
  1195→Expansion happens before the scene graph is built — by the time lowering runs, every $name has been replaced and every use node has been replaced with its expanded body. See dsl.md §Modules and §Imports for the full resolution rules.
  1196→
  1197→#Authoring a new module
  1198→Three rules cover almost everything:
  1199→
  1200→All parameters are scalars. Numeric defaults are required (height=0.5, count=4); vec3 / list / string / ident defaults are rejected. If you want a positioned pose, pass the three components as separate scalars.
  1201→
  1202→Reference parameters as $name inside the body. They compose into expressions in any numeric attribute position — pos=[0, $h * 0.5, 0], radius=$r, height=$h + 0.1, and so on.
  1203→
  1204→Expose connectors where the caller will join you. A leg that the seat attaches on top of should emit connector "top" (...) inside its mesh node. Tagging them (tag=leg_top) lets downstream fitting logic pair compatible anchors without hard-coded positions.
  1205→
  1206→Stdlib modules also include a // summary: <one-liner> comment on the first line. The CLI's stdlib index reads this to inject a single-line doc for each module into LLM prompts, so write a description that says what the module is and what its connectors are called — the LLM consumes it verbatim.
  1207→
  1208→A skeleton:
  1209→
  1210→// summary: A box-shaped part with top/bottom connectors. Caller declares mat=part.
  1211→module "my_part" (width=1.0, height=1.0, depth=1.0) {
  1212→  box "body" (size=[$width, $height, $depth]) {
  1213→    connector "top"    (at=[0,  $height * 0.5, 0], dir=[0,  1, 0], tag=part_top)
  1214→    connector "bottom" (at=[0, -$height * 0.5, 0], dir=[0, -1, 0], tag=part_bottom)
  1215→  }
  1216→}
  1217→Drop the file in crates/mogen-dsl/stdlib/<name>.mog and add an entry to the STDLIB_FILES table in crates/mogen-dsl/src/stdlib.rs. The all_stdlib_modules_parse_and_load test enforces that every entry parses and carries a // summary: line; each_stdlib_module_lowers_in_isolation checks that defaults produce a valid scene graph.
  1218→
  1219→#Stdlib catalog
  1220→Every module below lives at crates/mogen-dsl/stdlib/<name>.mog and is registered in stdlib.rs. All stdlib content is shadowed by user declarations and imports, so a project can override any module by re-declaring it in the importing file.

  1364→For a fully procedural recursive tree (multiple levels of splits and auto-emitted leaves), use the branch primitive instead — see dsl.md §Branch.
  1365→---------------------------------------------------
  1366→MoGen Studio
  1367→The desktop GUI: editor, viewer, gizmos, inspector, diagnostics, LLM tools, themes.
  1368→
  1369→A desktop editor for .mog scenes. Studio is a thin GUI on top of the same compile pipeline the CLI uses — every feature you can run from mogen <subcommand> is also available as a button or menu item. It adds a live 3D preview, a span-aware inspector, viewport gizmos, syntax highlighting, and a settings store so per-project knobs stick across sessions.
  1370→
  1371→Window title is MoGen Studio. Settings live at ~/.config/mogen/settings.json on Linux (%APPDATA%\mogen\settings.json on Windows; ~/Library/Application Support/mogen/settings.json on macOS).

  1388→
  1389→# Or from a release artifact:
  1390→mogen-studio                                 # Linux tarball
  1391→open "/Applications/MoGen Studio.app"        # macOS .dmg
  1392→# On Windows: launch from the Start menu after running the .msi installer.
  1393→On first launch, Studio shows an onboarding dialog asking for a Gemini API key. You can skip it — every non-LLM feature still works without one — or paste a key in. The key is stored in the settings file and is the same value GEMINI_API_KEY would supply to the CLI.
  1394→
  1395→#The window at a glance
  1396→Studio's main view is a four-region layout:
  1397→
  1398→region  what it does
  1399→menu bar        File / Edit / View / Generate / Options / Help, plus the active-tab strip just below
  1400→editor pane     .mog source with live syntax highlighting, autocomplete, error squiggles, and a per-file diagnostics footer
  1401→3D viewer       Live preview of the most recently built .mog, with translate/rotate/scale gizmos and click-to-select picking
  1402→inspector       Selected-node attribute editor, material editor, texture roster, and per-file build options
  1403→The editor and viewer are separated by a draggable splitter; the inspector is a collapsible side panel.
  1404→
  1405→#Tabs and recent files
  1406→Multiple .mog files can be open simultaneously, one per tab.
  1407→
  1408→The tab strip remembers order across sessions — closing Studio with three tabs open reopens all three on the next launch, with the last active tab focused.
  1409→Untitled buffers (no path yet) are not persisted across restarts, but they survive accidental re-runs of Studio because every change is held in memory.
  1410→File → Open Recent shows the last 12 opened paths, newest first. Items are removed automatically if the file no longer exists at that path.
  1411→Save / Save As use a native file dialog. New tabs default to "Untitled" and prompt for a path on first save.
  1412→#The editor pane
  1413→The editor is a custom egui-based text view tuned for .mog. It does NOT use a pest-driven highlighter on every keystroke — instead, a loose tokeniser in highlight.rs colours kinds, strings, numbers, comments, and $param references, so mid-edit source still highlights even when the parser would reject it.
  1414→
  1415→Features:
  1416→
  1417→Syntax highlighting — kinds, attributes, strings, numbers, comments, $param references.
  1418→Autocomplete — typing a kind, attribute, or material name pops a fuzzy list. Tab / Enter accepts; Esc cancels; ↑/↓ moves the selection.
  1419→Indent on enter — opening a { block bumps the indent; closing brace de-indents in place.
  1420→Error squiggles — every diagnostic from the AST or graph validator gets an underline at the exact span the validator emitted. Hover for the message.
  1421→Find — Ctrl+F / ⌘F opens a find bar.
  1422→External-edit detection — if the file changes on disk while a tab is open, Studio prompts to reload (or keep your in-memory copy if you have unsaved changes).
  1423→#The 3D viewer
  1424→A live preview built on eframe's wgpu backend. Loaded directly from the in-memory SceneGraph after each successful build — there's no intermediate GLB on disk for the preview.
  1425→
  1426→Camera:
  1427→
  1428→Left-drag orbits the focus point.
  1429→Middle-drag (or Shift+left-drag) pans.
  1430→Mouse wheel zooms.
  1431→⌘0 / Ctrl+0 frames the whole scene.
  1432→Selection:
  1433→
  1434→Left-click picks the node under the cursor (Möller–Trumbore ray cast against the rendered meshes). The selected node highlights both in the viewer and in the inspector.
  1435→Esc clears the selection.
  1436→Gizmos:
  1437→
  1438→When a node is selected, a translate / rotate / scale gizmo handle floats over its origin in world space. The mode toggles in the View menu (or the gizmo widget itself).
  1439→Dragging a handle modifies pos / rot / scale on the selected node and writes the change back into the source .mog as a span-preserving edit. Other formatting in the file is left alone.
  1440→#The inspector
  1441→The inspector binds the currently selected node to its attributes:
  1442→
  1443→Per-attribute fields — drag-numeric inputs, vec3 spinners, colour pickers for material colours, dropdowns for enum-like attrs (anchor, axis, alpha_mode).
  1444→Material editor — every authored material gets a collapsing section. Edit base color, roughness, metallic, alpha mode, transmission, emissive, etc.; changes flow back to the source material "…" declaration via the same span-preserving edit machinery.
  1445→Texture roster — each material's texture slots show ✓ / ✗ markers based on whether the referenced PNG actually exists at the resolved path. Missing textures are visible before you try to build.
  1446→LOD scale slider — edits the top-level lod_scale (value=N) directive in place. Drag down to iterate quickly on big scenes; drag back to 1.0 and Studio removes the directive entirely so saved files stay clean.
  1447→Per-file export options — include_animations, include_textures, merge_sibling_meshes (sticky per file).
  1448→Edits made in the inspector and via gizmos are persisted into the source file the next time you save. They are reflected in the editor text immediately, and they preserve every comment, blank line, and whitespace style elsewhere in the source.
  1449→
  1450→#Diagnostics
  1451→Every build runs the same dual validator the CLI uses (AST-level + graph-level). The diagnostics show up in three places:
  1452→
  1453→Error squiggles in the editor at the exact source span.
  1454→Diagnostics footer under the editor — collapsible; auto-hides when there are no errors or warnings.
  1455→Tab badges — a tab with errors gets a red dot; a tab with only info-level diagnostics looks clean.
  1456→mogen check --json and the studio share the same diagnostic format — the studio is a viewer for that JSON, dressed up as a UI.
  1457→
  1458→#Building
  1459→The Build button (or ⌘B / Ctrl+B) compiles the current tab to GLB and refreshes the 3D viewer. The output GLB lands at <file>.glb next to the source by default.
  1460→
  1461→The build pipeline is the same one mogen build runs:
  1462→
  1463→Parse → AST → AST validation
  1464→Lower → SceneGraph
  1465→Graph validation
  1466→Optional sibling-mesh merge (per-file merge_sibling_meshes setting)
  1467→GLB export
  1468→Validation errors abort the build and surface in the diagnostics footer without writing a GLB.
  1469→
  1470→F5 re-runs the validator only, without re-emitting a GLB. Useful when you've edited a .mog from outside Studio and want a quick diagnostic refresh.
  1471→
  1472→#LLM tools
  1473→The Generate menu mirrors the LLM-driven CLI subcommands. Each opens a small modal that collects a prompt and the relevant flags.
  1474→
  1475→menu item       CLI equivalent
  1476→New from prompt… (⌘⇧N)  mogen generate
  1477→Modify… mogen modify
  1478→Animate…        mogen animate
  1479→Repair  mogen repair
  1480→Generate textures…      mogen textures
  1481→Behaviour matches the CLI:
  1482→
  1483→The repair loop runs in the background; progress is shown in the status line.
  1484→The generated .mog opens in a new tab (Generate) or replaces the current tab's contents (Modify / Animate / Repair).
  1485→Seeds are embedded in the DSL header so the same prompt + same seed re-emits the same scene. The seed field in each modal is pre-filled with the input file's existing seed when present.
  1486→Thinking level, model, temperature, and max_repair_iters come from Options → Models. Per-modal overrides live next to the prompt field for one-off tuning.
  1487→If gemini_api_key is empty in the settings, every LLM action prompts for a key first (the same onboarding dialog as on first launch).
  1488→
  1489→#Themes and preview shaders
  1490→UI themes (Options → Theme):
  1491→
  1492→key     label   use
  1493→dark    Dark    classic dark editor
  1494→light   Light   bright office mode
  1495→sunset  Sunset (warm)   warm-toned
  1496→nord    Nord (cool)     cool-toned blue/grey — default
  1497→high-contrast   High Contrast   accessibility / projector
  1498→The theme name is stored in settings.json as a lowercase label so new variants can land without breaking older settings files. Empty / unknown labels fall back to Nord.
  1499→
  1500→Preview shaders (View → Preview shader) control the 3D viewer only — they don't affect the exported GLB.
  1501→
  1502→key     label   what it shows
  1503→standard        Standard (PBR)  full PBR with embedded textures — default
  1504→toon    Toon (cel-shaded)       hard-shaded NPR look
  1505→crt     CRT (scanlines) post-process scanlines + bloom
  1506→matcap  Matcap (clay)   unlit material capture for sculpt-style review
  1507→wireframe       Wireframe       edges only, ignores materials
  1508→Wireframe is useful for inspecting topology after CSG or sibling-mesh merge. CRT is for vibes.

  1510→#Settings
  1511→The settings file is a JSON document stored at the OS-appropriate config path. It's safe to edit by hand — Studio reloads on next launch.
  1512→
  1513→key     meaning
  1514→gemini_api_key  API key used by every LLM action.
  1515→gemini_model    Heavy model id. Empty → gemini-pro-latest.
  1516→gemini_fast_model       Fast model id used for low-stakes rewrites (Prompt Enhancer). Empty → gemini-flash-latest.
  1517→gemini_temperature      Sampling temperature. null → library default (0.3).
  1518→thinking_level  low / medium / high / xhigh. Empty → library default (high).
  1519→max_repair_iters        LLM repair budget. null → library default (2).
  1520→seed_override   Optional deterministic seed. null → derive from DSL header or random per call.
  1521→theme   UI theme key (see above).
  1522→preview_shader  Viewer shader key (see above).
  1523→last_opened     Absolute path of the last .mog opened.
  1524→open_tabs       Absolute paths of every titled tab open at last persist time.
  1525→recent_files    Most-recently-opened paths, newest first. Capped at 12.
  1526→onboarded       Set once the first-launch onboarding has been dismissed.
  1527→Untitled buffers are deliberately not persisted — there's nothing to key off — so a fresh Studio launch with only-untitled tabs comes up empty. Save first if you want them back.

  1529→#Keyboard shortcuts
  1530→COMMAND is ⌘ on macOS and Ctrl elsewhere. All shortcuts work globally; egui consumes them before the menu or editor see the key.
  1531→
  1532→shortcut        action
  1533→⌘N      New untitled tab
  1534→⌘⇧N     New from prompt (Gemini generate)
  1535→⌘O      Open file…
  1536→⌘S      Save active tab
  1537→⌘⇧S     Save As…
  1538→⌘B      Build active tab to GLB
  1539→F5      Re-run the validator without re-emitting the GLB
  1540→⌘W      Close active tab
  1541→⌘0      Frame the scene in the 3D viewer
  1542→⌘,      Open Options
  1543→⌘Q      Quit (with prompt-to-save for dirty tabs)
  1544→Tab / Enter     Accept autocomplete suggestion
  1545→Esc     Dismiss autocomplete; clear viewer selection
  1546→Standard editing shortcuts (⌘C, ⌘X, ⌘V, ⌘A, ⌘Z, ⌘⇧Z) work in the editor pane.

  1548→#File layout on disk
  1549→For a given project directory, Studio expects (and creates) the following layout:
  1550→
  1551→my-project/
  1552→├── chair.mog              # source
  1553→├── chair.glb              # build output (next to the .mog by default)
  1554→└── textures/
  1555→    └── chair/             # mogen textures --textures-dir default
  1556→        ├── wood_base_color.png
  1557→        ├── wood_normal.png
  1558→        ├── wood_metallic_roughness.png
  1559→        └── wood_occlusion.png
  1560→Texture paths in material "…" declarations are resolved relative to the .mog file. The textures/<mog-stem>/ subdirectory is the default output of mogen textures so sibling .mogs with shared material names don't clobber each other.
