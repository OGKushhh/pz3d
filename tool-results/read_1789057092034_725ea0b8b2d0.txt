     1→     1→# MoGen DSL reference
     2→     2→

     4→     4→and exports glTF 2.0 GLB. This document is the authoritative reference for
     5→     5→the surface language: every node kind, every attribute, and the little bits of
     6→     6→grammar that sit between them. For a conceptual overview of the whole
     7→     7→pipeline, see [`ROADMAP.md`](./ROADMAP.md); for a worked catalog of reusable
     8→     8→modules, see [`modules.md`](./modules.md).

    34→    34→
    35→    35→## Grammar at a glance
    36→    36→
    37→    37→A `.mog` file is a sequence of nodes. Every node shares the same shape:
    38→    38→
    39→    39→```
    40→    40→kind ["optional name"] [(attr=value, ...)] [{ child_nodes... }]
    41→    41→```
    42→    42→
    43→    43→- `kind` is an identifier like `box`, `cylinder`, `group`, `scene`, `material`, `joint`, …
    44→    44→- `name` is a quoted string. Some kinds require it (`material`, `module`, `joint`, `clip`, `connector`); most geometry kinds treat it as optional — when omitted the node's name defaults to its kind.
    45→    45→- `attr_list` is a comma-separated `key=value` sequence in parentheses.
    46→    46→- `block` is a brace-delimited list of child nodes.
    47→    47→
    48→    48→Comments run from `//` to the end of the line. Whitespace between tokens is
    49→    49→insignificant. The top of the file may contain `import`, `material`,
    50→    50→`module`, `joint`, and `clip` declarations; `scene { ... }` holds the
    51→    51→geometry itself.
    52→    52→
    53→    53→---
    54→    54→
    55→    55→## File metadata: `meta`
    56→    56→
    57→    57→An optional top-of-file block recording author-facing metadata about the
    58→    58→asset. Place at most once, before `material` / `scene` / `module`.
    59→    59→
    60→    60→```
    61→    61→meta (
    62→    62→  name = "wooden_chair",
    63→    63→  version = "1.2.0",
    64→    64→  description = "A simple four-legged dining chair.",
    65→    65→  tags = ["furniture", "chair", "wood"],
    66→    66→)
    67→    67→```
    68→    68→
    69→    69→| attr | type | source | notes |
    70→    70→|---|---|---|---|
    71→    71→| `name` | string | author | human-readable asset name |
    72→    72→| `version` | string | author | semver-style is conventional but not enforced |
    73→    73→| `mogen_version` | string | **toolchain** | auto-stamped on every save. Don't write it yourself. |
    74→    74→| `description` | string | author | one-line summary |
    75→    75→| `tags` | list of string | author | free-form labels |
    76→    76→| `style` | string | toolchain | visual-style hint from `mogen generate --style …`. Suggested values: `ps1`, `n64`, `low_poly`, `high_detail`, `arcade`, `voxel`, `cel_shaded`, `stylized_fantasy`, `cyberpunk`, `pixel_art`. Validator accepts any string; survives `modify`/`animate`/`repair` |
    77→    77→| `seed` | string | toolchain | random seed from `mogen generate`/`modify`; round-trips through edits |
    78→    78→| `thinking` | string | toolchain | per-file Gemini thinking budget stamped with `seed`; survives `modify` |
    79→    79→| `prompt` | string | toolchain | original NL prompt; round-trips through `modify` so the LLM can revise against original intent |
    80→    80→| `moghub_model_id` | string | toolchain | stamped by Studio's Publish after a successful MoGHub upload |
    81→    81→| `moghub_slug` | string | toolchain | MoGHub slug, paired with `moghub_model_id` |
    82→    82→| `moghub_version` | string | toolchain | last-published MoGHub version, paired with `moghub_model_id` |
    83→    83→
    84→    84→The block is informational — not consumed by the geometry pipeline. It
    85→    85→survives lowering on `SceneGraph::meta` for downstream tooling. Old files
    86→    86→without `meta` keep building; the toolchain inserts a fresh
    87→    87→`meta (mogen_version = "...")` line on next save.
    88→    88→
    89→    89→Diagnostics: `E0310` (no body block), `E0311` (no quoted name — use
    90→    90→`name=`), `E0312` (duplicate), `E0313` (must be top level), `W0107`
    91→    91→(`mogen_version` mismatch).
    92→    92→

    94→    94→
    95→    95→## Global settings
    96→    96→
    97→    97→Top-level directives that tune the build itself.
    98→    98→
    99→    99→| directive | value | effect |
   100→   100→|---|---|---|
   101→   101→| `lod_scale (value=N)` | number, default `1.0` | multiplies every primitive `segments`/`rings`/`samples` (implicit defaults *and* explicit values like `segments_u=64`) and `blob` `resolution`. `icosphere` `subdivisions` and any `subdivide=` post-pass step by `round(log2(N))` instead. Counts clamp to a per-primitive minimum |
   102→   102→
   103→   103→```
   104→   104→lod_scale (value=0.5)
   105→   105→
   106→   106→scene {
   107→   107→  sphere "head" (radius=0.5)         // 8 rings, 12 segments (default 16/24 halved)
   108→   108→  sphere "lod0" (radius=0.5, segments=48, rings=32)  // 16 rings, 24 segments (48/32 halved)
   109→   109→}
   110→   110→```
   111→   111→
   112→   112→Studio's "LOD scale" slider edits this directive in place; it clears the
   113→   113→directive at `1.0` so saved files stay clean.
   114→   114→
   115→   115→### Per-node `lod=` overrides
   116→   116→
   117→   117→Any geometry/group node accepts `lod=N`, which **multiplies** the active
   118→   118→LOD scale for that node's subtree. RAII-scoped (doesn't leak into siblings)
   119→   119→and compounds with the global setting. Per-primitive minimums still apply
   120→   120→(`lod=0.1` won't collapse a cylinder below three sides).
   121→   121→
   122→   122→```
   123→   123→scene {
   124→   124→  group "hero" (lod=2) {                  // boosted detail
   125→   125→    sphere "face" (radius=0.12)
   126→   126→  }
   127→   127→  sphere "background_rock" (radius=0.4, lod=0.5)  // halved detail
   128→   128→}
   129→   129→```
   130→   130→

   132→   132→
   133→   133→## Values and expressions
   134→   134→
   135→   135→Every `value` on the right side of an attribute is one of:
   136→   136→
   137→   137→| form | example | notes |
   138→   138→|---|---|---|
   139→   139→| number | `0.5`, `-90`, `1` | parsed as `f32` |
   140→   140→| length | `1.5m`, `90cm`, `18in`, `2ft` | a number with a unit suffix; normalised to metres (see [Length units](#length-units)) |
   141→   141→| vec3 | `[1.0, 0.5, 0.0]` | three expressions, comma-separated |
   142→   142→| list | `[0, 90]`, `[1, 2, 3, 4]` | arbitrary arity |
   143→   143→| string | `"wood"` | used for names and references |
   144→   144→| ident | `wood`, `y` | no quotes; used for axes and enum-like values |
   145→   145→| expression | `$height * 0.5`, `$r + 0.1`, `($a - $b) / 2` | arithmetic over `$param` refs |
   146→   146→| comparison | `$h > 0`, `$count == 4`, `$a != $b` | `<`, `<=`, `>`, `>=`, `==`, `!=` — used in `if` conditions and `for` ranges |
   147→   147→
   148→   148→Inside `module` bodies, expressions reference parameters as `$name`.
   149→   149→Operators: `+ - * /` (conventional precedence + parentheses) and the six
   150→   150→comparisons. Evaluated at module-expansion time; the scene graph never
   151→   151→sees `$name`.
   152→   152→
   153→   153→### Length units
   154→   154→
   155→   155→mogen's base unit is the **metre** — the glTF/Godot convention — so a bare
   156→   156→number is a length in metres (`size=[0.45, 0.04, 0.45]` is a 45 cm seat).
   157→   157→To write real-world dimensions directly — handy for accurate blueprints —
   158→   158→append a unit suffix to any number:
   159→   159→
   160→   160→| suffix | unit | metres |
   161→   161→|---|---|---|
   162→   162→| `mm` | millimetre | `0.001` |
   163→   163→| `cm` | centimetre | `0.01` |
   164→   164→| `m` | metre | `1.0` |
   165→   165→| `km` | kilometre | `1000.0` |
   166→   166→| `in` | inch | `0.0254` |
   167→   167→| `ft` | foot | `0.3048` |
   168→   168→| `yd` | yard | `0.9144` |
   169→   169→
   170→   170→```
   171→   171→box "wall"  (size=[2m, 100cm, 8in], pos=[3ft, 0, 0])
   172→   172→box "joist" (height=5ft + 6in)        // units compose through arithmetic
   173→   173→```
   174→   174→
   175→   175→The suffix is resolved to metres at **parse time**, so units flow through
   176→   176→every numeric position: scalars, `vec3` components, list items, and
   177→   177→`$param` arithmetic. Each component carries its own unit, so metric and
   178→   178→imperial can be mixed freely within one literal or expression.
   179→   179→
   180→   180→Length units are for **lengths only** — sizes, positions, radii, heights,
   181→   181→offsets. Rotations stay in degrees, `scale` stays a unit-less multiplier, and
   182→   182→counts / colours stay plain numbers; don't put a length suffix on those.
   183→   183→Because everything normalises to metres, a unit literal and its metre
   184→   184→equivalent lower to byte-identical geometry.
   185→   185→
   186→   186→### Weight units
   187→   187→
   188→   188→Weights follow the same scheme, normalising to the **kilogram**. A bare number
   189→   189→is kilograms. Used by [`physics`](#physics) (`weight=`) and the per-node
   190→   190→`weight=` override.
   191→   191→
   192→   192→| suffix | unit | metres → kg |
   193→   193→|---|---|---|
   194→   194→| `g` | gram | 0.001 |
   195→   195→| `kg` | kilogram | 1.0 |
   196→   196→| `t` | tonne | 1000 |
   197→   197→| `lb` | pound | 0.4536 |
   198→   198→| `oz` | ounce | 0.02835 |
   199→   199→| `st` | stone | 6.350 |
   200→   200→
   201→   201→A `physics` block's `weight=` is a weight **per cubic metre** — append `/m3`
   202→   202→(or `/m³`): `700kg/m3`, `0.7t/m3`. A bare `weight=` on a geometry node is a flat
   203→   203→mass (`5kg`). Mass and length suffixes are disjoint, so a literal's dimension is
   204→   204→never ambiguous.
   205→   205→
   206→   206→---
   207→   207→
   208→   208→## Common attributes
   209→   209→
   210→   210→These apply to every geometry node (`box`, `cylinder`, …) and to `group`:
   211→   211→
   212→   212→| attribute | value | effect |
   213→   213→|---|---|---|
   214→   214→| `pos` | `vec3` | translation in the parent's frame; default `[0, 0, 0]` |
   215→   215→| `rot` | `vec3` (Euler XYZ in **degrees**) or a list | rotation applied after translation; default identity |
   216→   216→| `scale` | scalar or `vec3` | uniform/per-axis scale; default `1` |
   217→   217→| `mat` | string or ident | references a declared `material` by name |
   218→   218→| `phys` | string or ident | references a declared `physics` substance by name; drives auto-computed weight + centre of gravity (see [Physics](#physics)) |
   219→   219→| `weight` | mass (`5kg`) | optional flat per-node weight override (a mass), for props whose weight shouldn't follow from their volume |
   220→   220→| `role` | string or ident | semantic label; written into the GLB `extras` block |
   221→   221→| `tags` | comma-separated string | free-form labels; also in `extras` |
   222→   222→
   223→   223→Transforms compose from child → parent along the scene hierarchy, exactly as
   224→   224→in glTF.
   225→   225→

   228→   228→## Placement shortcuts
   229→   229→
   230→   230→Every node accepts ergonomic shortcuts on top of `pos`/`rot`/`size`.
   231→   231→Mix and match freely — the DSL does the arithmetic.
   232→   232→
   233→   233→### Per-component shortcuts
   234→   234→
   235→   235→| shortcut | replaces / overrides | notes |
   236→   236→|---|---|---|
   237→   237→| `x=`, `y=`, `z=` | individual components of `pos` | missing axes default to `pos`'s value, or `0` |
   238→   238→| `rx=`, `ry=`, `rz=` | individual components of `rot` (degrees) | same fallback; great for single-axis spins |
   239→   239→| `w=`, `h=`, `d=` | individual components of `size` (X, Y, Z) | for 2D primitives, `w`/`d` are used on `plane`/`curved_plane` (XZ) and `w`/`h` on `quad` (XY) |
   240→   240→
   241→   241→```
   242→   242→box (y=1.5, size=1)            // equivalent to pos=[0, 1.5, 0], size=[1,1,1]
   243→   243→box (size=[2, 2, 0.1], h=3)    // h overrides the middle component — width=2, height=3, depth=0.1
   244→   244→cylinder (rx=90, radius=0.2, height=1)   // lay a cylinder on its side
   245→   245→```
   246→   246→
   247→   247→### Scalar `size` (cube shorthand)
   248→   248→
   249→   249→Any primitive that takes `size=[…]` also accepts `size=<number>`, which
   250→   250→expands to a uniform vec3. `box (size=0.5)` is a half-metre cube.
   251→   251→
   252→   252→### `from` / `to` — axis-aligned box by corners
   253→   253→
   254→   254→On any primitive that uses `size`, `from=[x1,y1,z1]` + `to=[x2,y2,z2]` sets
   255→   255→`size` to `|to − from|` and `pos` to their midpoint. No "shift by half" math:
   256→   256→
   257→   257→```
   258→   258→box (from=[-2, 0, -1.5], to=[2, 2.8, -1.4], mat="wall")
   259→   259→// equivalent to: box (pos=[0, 1.4, -1.45], size=[4.0, 2.8, 0.1])
   260→   260→```
   261→   261→
   262→   262→### `anchor` — place by face, not centre
   263→   263→
   264→   264→Every primitive's `pos` controls where its **anchor point** lands, not where
   265→   265→its centre lands. The default anchor is `center`; `anchor=bottom` puts the
   266→   266→primitive's bottom face at `pos`, which is usually what "sit on the ground"
   267→   267→means. Values are underscore-joined tokens drawn from
   268→   268→`center`, `top`, `bottom`, `left`, `right`, `front`, `back`:
   269→   269→
   270→   270→```
   271→   271→box (y=0,  size=[1, 2, 1], anchor=bottom)           // bottom face on y=0
   272→   272→box (xyz, size=2,           anchor=bottom_left_front) // corner at the origin
   273→   273→```
   274→   274→
   275→   275→The anchor shifts mesh vertices so the chosen point lands at the local
   276→   276→origin; default face connectors (`top`, `bottom`, …) move with it.
   277→   277→
   278→   278→### Relative placement: `above`, `below`, `left_of`, `right_of`, `in_front_of`, `behind`
   279→   279→
   280→   280→Set one of these to the name of a **prior sibling** in the same parent; the
   281→   281→node is translated so its matching face is flush against the sibling's
   282→   282→opposite face, optionally plus `gap`. At most one may be set per node.
   283→   283→
   284→   284→```
   285→   285→group "chests" {
   286→   286→  box "chest_lo" (size=[0.8, 0.6, 0.5])
   287→   287→  box "chest_hi" (above="chest_lo", gap=0.02, size=[0.8, 0.6, 0.5])
   288→   288→}
   289→   289→```
   290→   290→
   291→   291→Resolution happens after the target's subtree is fully lowered (nested
   292→   292→geometry is in the AABB). Lookup is scoped to siblings in the same parent.
   293→   293→

   296→   296→## Deformation modifiers
   297→   297→
   298→   298→Every primitive accepts a small set of common modifier attrs that perturb the
   299→   299→generated mesh between primitive construction and anchor placement. The point
   300→   300→is variety without authoring extra geometry — bent beams, weathered rocks,
   301→   301→melted candles, jelly blobs — using one or two extra attrs.
   302→   302→
   303→   303→| attribute | value | effect |
   304→   304→|---|---|---|
   305→   305→| `bend_x`, `bend_y`, `bend_z` | degrees | arc-length-preserving bend around the named axis. Length axis is the perpendicular one (Y for `bend_x`/`bend_z`, X for `bend_y`). |
   306→   306→| `twist_y` | degrees | helical twist around Y, from 0 at `y_min` to the full angle at `y_max`. |
   307→   307→| `taper` | ratio (1.0 = unchanged, 0.5 = half-width at top) | linear shrink along Y. |
   308→   308→| `droop` | amount (0..1 of length) | quadratic gravity-style sag along -Y; the base stays put, the top sinks by `amount * height`. |
   309→   309→| `noise` | 0..1 | coherent value-noise displacement along the vertex normal. Yields blobby "rock" texture. |
   310→   310→| `jitter` | 0..1 | per-vertex random displacement along the normal. Higher-frequency than `noise`, looks "jagged". |
   311→   311→| `faceted` | 0/1 | rebuild the mesh with three unique vertices per triangle and face-flat normals; reads as low-poly. |
   312→   312→| `seed` | integer | RNG seed for the stochastic modifiers (`noise`, `jitter`); same seed always reproduces the same shape. |
   313→   313→| `wave` | peak displacement (m) | sinusoidal displacement along the vertex normal — periodic ripples for water, jelly, ribbed metal, fabric. Pair with `wave_frequency`, `wave_axis`, `wave_phase`, `wave_range`. |
   314→   314→| `wave_frequency` | cycles/unit, default `1.0` | spatial frequency along `wave_axis`. `0.5` puts a crest every 2 m. |
   315→   315→| `wave_axis` | `"x"`/`"y"`/`"z"`, default `"x"` | axis the wave propagates along. |
   316→   316→| `wave_phase` | radians, default `0.0` | phase offset; lets sibling waves desync without animation. |
   317→   317→| `wave_range` | `[a, b]` | gates the wave to a normalised slice along `wave_axis` via smoothstep, matching `*_range` convention. |
   318→   318→
   319→   319→```
   320→   320→icosphere "rock"   (radius=0.4, noise=0.30, jitter=0.15, faceted=1, seed=7)
   321→   321→cylinder  "candle" (radius=0.18, height=0.7, droop=0.4, noise=0.05)
   322→   322→box       "beam"   (size=[0.2, 0.2, 3], twist_y=20, taper=0.7)
   323→   323→```
   324→   324→
   325→   325→Stochastic modifiers are deterministic for a given `seed`. Two unnamed
   326→   326→primitives with `noise=0.3` share the default seed (1) and produce
   327→   327→identical surfaces — set distinct seeds for sibling variety.
   328→   328→
   329→   329→Each modifier accepts `*_range=[a, b]` (`bend_x_range`, `bend_y_range`,
   330→   330→`bend_z_range`, `twist_y_range`, `taper_range`, `droop_range`,
   331→   331→`noise_range`, `jitter_range`) that gates the deformation along its length
   332→   332→axis: vertices below `a` are unchanged, `[a, b]` ramps in via smoothstep,
   333→   333→above `b` is full effect. Endpoints auto-normalise (`[1.0, 0.5]` →
   334→   334→`[0.5, 1.0]`).
   335→   335→
   336→   336→```
   337→   337→box "blade" (size=[0.06, 1.4, 0.01], bend_z=18, bend_z_range=[0.55, 1.0])
   338→   338→cylinder "spire" (radius=0.4, height=4.0, twist_y=70, twist_y_range=[0.6, 1.0])
   339→   339→```
   340→   340→
   341→   341→Default tessellation auto-bumps (×2 segments / +1 icosphere subdivision)
   342→   342→when a smooth deformer is present; explicit `segments=`/`rings=`/
   343→   343→`subdivisions=` always override. Modifiers don't apply to `mesh` (loaded
   344→   344→glb) primitives. See `examples/nature/asteroid_field.mog`.
   345→   345→
   346→   346→Implicit tessellation on curved primitives is also size-aware in authored
   347→   347→local units. Counts scale with the cube root of radius (or the primitive's
   348→   348→equivalent local extent), relative to the default-sized primitive: tiny rivets
   349→   349→and dimples no longer pay the same triangle count as a dome, while large props
   350→   350→gain detail without triangle count growing linearly with size. Explicit
   351→   351→`segments=`/`rings=` remains the exact author override. Placement `scale=` is
   352→   352→not part of this calculation because multiple placements may share one lowered
   353→   353→mesh; use explicit counts when an unusually scaled placement needs a different
   354→   354→mesh.

   357→   357→
   358→   358→## Scene structure: `scene`, `group`
   359→   359→
   360→   360→```
   361→   361→scene {
   362→   362→  group "chair" (pos=[0, 0, 0]) {
   363→   363→    box "seat" (pos=[0, 0.5, 0], size=[1.0, 0.1, 1.0])
   364→   364→  }
   365→   365→}
   366→   366→```
   367→   367→
   368→   368→- `scene` is the root container. Exactly one per file is expected in practice; top-level nodes outside any `scene` are also lowered and become extra roots.
   369→   369→- `group` is a transform-only container — no geometry of its own, used to compose children and receive `pos`/`rot`/`scale`.
   370→   370→- `solid` behaves like `group` in the scene tree, but its same-material leaf children are CSG-unioned into a single mesh at export time. See [Solid groups](#solid-groups-solid) below.
   371→   371→

   373→   373→
   374→   374→## Primitives
   375→   375→
   376→   376→All primitives accept the common attributes above (`pos`, `rot`, `scale`,
   377→   377→`mat`, `role`, `tags`) plus the kind-specific attributes below.
   378→   378→
   379→   379→| kind | required attrs | other attrs |
   380→   380→|---|---|---|

   426→   426→`plane` is XZ-aligned, `quad` is XY-aligned (UI-style panels).
   427→   427→
   428→   428→`curved_plane`, `lathe`, `spline_tube`, and `spline_ribbon` accept nested
   429→   429→list literals: `points=[[0, 0, 0], [1, 0.5, 0]]`. Inner lists must be
   430→   430→constant (no `$param`) — parameterise the whole node via a module wrapper.
   431→   431→`spline_tube`/`spline_ribbon` run Catmull–Rom with a parallel-transport
   432→   432→frame; `spline_ribbon` adds a `twist` that ramps roll around the path
   433→   433→tangent.
   434→   434→
   435→   435→`slab`, `post`, and `panel` are `box` aliases that only change the default
   436→   436→anchor (`bottom`/`bottom`/`back`). Override with `anchor=` if needed.
   437→   437→
   438→   438→`wall` is a box with rectangular cutouts along Z. Each hole is
   439→   439→`[cx, cy, w, h]` in the wall's local frame (X/Y are the face plane; Z is
   440→   440→cut through). Cutouts are CSG-differenced and welded at lowering, so a
   441→   441→single `wall` becomes one watertight mesh:
   442→   442→
   443→   443→```
   444→   444→wall "barracks" (size=[3, 3, 0.1], holes=[
   445→   445→  [-0.75, -0.4, 0.9, 2.0],   // door
   446→   446→  [ 0.9,  0.3, 0.8, 0.8],    // window
   447→   447→])
   448→   448→```

   450→   450→### Per-face box materials (`faces=`)
   451→   451→
   452→   452→A `box` can carry a different material on each face via `faces=[…]` — exactly
   453→   453→six material names in the fixed order **`+X, -X, +Y, -Y, +Z, -Z`**:
   454→   454→
   455→   455→```
   456→   456→material "wood"  (color=[0.6, 0.4, 0.2])
   457→   457→material "metal" (color=[0.7, 0.7, 0.75], metallic=0.9)
   458→   458→
   459→   459→box "crate" (size=[2, 1, 1], faces=[
   460→   460→  "wood", "wood",   // +X, -X
   461→   461→  "metal",          // +Y (lid)
   462→   462→  "wood", "wood", "wood"  // -Y, +Z, -Z
   463→   463→])
   464→   464→```
   465→   465→
   466→   466→The box lowers to an editable wrapper (keeping its transform, anchor, and
   467→   467→connectors) plus one **frozen** child per distinct material — each a quad group
   468→   468→of just that material's faces. Faces sharing a material collapse into one child,
   469→   469→so the crate above becomes two children (`wood` ×5, `metal` ×1), not six. The
   470→   470→children have no AST of their own, so the Studio inspector redirects clicks to
   471→   471→the wrapper.
   472→   472→
   473→   473→An empty entry `""` falls back to the box's own `mat=` (or inherited material),
   474→   474→so you can override just the faces you care about:
   475→   475→
   476→   476→```
   477→   477→box "panel" (mat="body", faces=["", "", "label", "", "", ""])  // only +Y differs
   478→   478→```
   479→   479→
   480→   480→This is the migration sink for engine map blocks whose six faces each reference
   481→   481→a different tile texture.
   482→   482→
   483→   483→#### Authored per-face UV transforms (`face(...)`)
   484→   484→
   485→   485→By default each face's texture coordinates follow the material's UV mode
   486→   486→(`fit` = one copy per face, `tile` = 1 unit per metre). When a converter carries
   487→   487→its own per-face UV mapping (atlas sub-rectangles, engine-native tile offsets),
   488→   488→any entry in the `faces=` list may be a `face(...)` struct instead of a bare
   489→   489→string. It sets the material **and** an explicit UV transform baked verbatim
   490→   490→onto that face, bypassing the procedural projection:
   491→   491→
   492→   492→```
   493→   493→box "wall_seg" (size=[4, 3, 1], faces=[
   494→   494→  "wall", "wall", "wall", "wall",
   495→   495→  face("panel", uv_scale=[0.25, 0.333], uv_offset=[0, 0], uv_swap=false),  // +Z
   496→   496→  "wall"
   497→   497→])
   498→   498→```
   499→   499→
   500→   500→- **First argument** — the material name (same rules as the bare string; `""`
   501→   501→  falls back to the box's own material).
   502→   502→- `uv_scale=[sx, sy]` — per-axis scale; may be **negative** to mirror. Default `[1, 1]`.
   503→   503→- `uv_offset=[ox, oy]` — per-axis constant added after scaling. Default `[0, 0]`.
   504→   504→- `uv_swap=<bool>` — swap the two in-plane axes before scale/offset. Default `false`.
   505→   505→
   506→   506→All UV fields are optional; **`face("mat")` is identical to the bare `"mat"`**
   507→   507→(no authored transform → keep the default Fit/Tile UVs). Authored and bare
   508→   508→entries may be freely mixed in one list, and faces still group into frozen
   509→   509→children by material as above.
   510→   510→
   511→   511→The baked coordinate is face-local. For a face whose outward normal is on axis
   512→   512→*A*, the two in-plane axes are the other two in ascending index order
   513→   513→(`X→(Y,Z)`, `Y→(X,Z)`, `Z→(X,Y)`); the local coordinate on each is the vertex
   514→   514→offset from the box's minimum corner on that axis (`vertex + size/2`). The final
   515→   515→UV is `offset + scale * (swap ? swapped : local)`. Values are emitted **exactly
   516→   516→as computed** — never clamped or wrapped, so repeat/tile behaviour is left to the
   517→   517→sampler.
   518→   518→
   519→   519→### Branch
   520→   520→
   521→   521→`branch` is a procedural tree builder. One node expands into a recursive
   522→   522→cluster of `spline_tube` segments tapering from trunk to twigs, with
   523→   523→optional `leaf_card` clusters at the tips. Inner segments are
   524→   524→non-editable (deterministic function of `seed=`).
   525→   525→
   526→   526→| attribute | default | effect |
   527→   527→|---|---|---|
   528→   528→| `form` | `"decurrent"` | growth habit preset — see below. Sets sensible defaults for all attrs in this table; user attrs still win |
   529→   529→| `length` | `1.0` | trunk length (m) |
   530→   530→| `radius` | `0.05` | trunk base radius (m) |
   531→   531→| `depth` | `4` | recursion depth (number of branching levels) |
   532→   532→| `splits` | `2` | child branches per parent at each split |
   533→   533→| `length_falloff` | `0.7` | per-level length multiplier |
   534→   534→| `radius_falloff` | `0.6` | per-level radius multiplier |
   535→   535→| `branch_angle` | `35` | angle (degrees) child branches lean off the parent tangent |
   536→   536→| `roll` | `137.5` | roll (degrees) between successive children — the golden angle by default, breaks bilateral symmetry |
   537→   537→| `tropism` | `0.0` | bias toward +Y per segment (positive = upright trees, negative = drooping) |
   538→   538→| `bend` | `10` | random bend (degrees) added to each segment frame |
   539→   539→| `leader_bias` | `0.0` | `0.0`–`1.0` strength of central-leader behaviour. At `1.0` child 0 of every fork continues straight up at full length/radius (pine-like silhouette); at `0.0` all forks are equal (default broadleaf habit) |
   540→   540→| `multi_stem` | `1` | number of trunks emerging from the base. Only honoured by `form="shrub"`; ignored otherwise |
   541→   541→| `segments` | `8` | radial segments per spline_tube |
   542→   542→| `samples` | `4` | samples per spline segment |
   543→   543→| `seed` | `1` | RNG seed; same seed = identical tree |
   544→   544→| `jitter` | `0.2` | `0.0`–`1.0` random perturbation amount on lengths/angles |
   545→   545→| `leaves` | `1` | emit `leaf_card` clusters at terminal tips (`0` to disable) |
   546→   546→| `leaf_size` | `0.35` | leaf-card height (m) |
   547→   547→| `leaf_aspect` | `1.0` | leaf width / height ratio. `<1` for needle/willow leaves, `>1` for wide flat leaves |
   548→   548→| `leaf_cards` | `2` | crossed cards per leaf cluster (or fronds in the palm rosette) |
   549→   549→| `leaf_mat` | — | material name for leaves; defaults to inherited `mat=` |
   550→   550→
   551→   551→`form` values:
   552→   552→
   553→   553→| value | habit | distinctive defaults |
   554→   554→|---|---|---|
   555→   555→| `"decurrent"` | broadleaf tree (default — oak, maple) | equal forks, square leaves |
   556→   556→| `"excurrent"` | conifer (pine, spruce) | strong central leader, near-horizontal side branches, narrow needle leaves |
   557→   557→| `"weeping"` | willow | long branches with strong negative tropism (drooping), long narrow leaves |
   558→   558→| `"shrub"` | bush | several short trunks at the base (`multi_stem=4` by default), no leader |
   559→   559→| `"palm"` | palm | single straight trunk with a fan of frond-shaped cards at the tip; no recursive branching |
   560→   560→
   561→   561→Wrap a `branch` in a `group` with `scale=`/`rot=` for forests, antlers,
   562→   562→vines, root systems. Pair with stdlib `branch`/`leaf` for hand-tuned shapes.
   563→   563→
   564→   564→### Building
   565→   565→
   566→   566→`building` is a procedural building-interior generator. One node expands
   567→   567→into floor/ceiling slabs, perimeter walls with windows and entrance
   568→   568→cutouts, interior walls with door cutouts, and stamped door/window/skylight
   569→   569→modules. The generated subtree is stamped non-editable (pure function of
   570→   570→`seed=` plus the declared attrs). See `docs/building.md` for the full
   571→   571→spec, supported styles/roof shapes, and tranche status.
   572→   572→
   573→   573→| attribute | default | effect |
   574→   574→|---|---|---|
   575→   575→| `seed` | `1` | RNG seed; same seed = identical layout + geometry. |
   576→   576→| `style` | `"grid"` | Layout algorithm. T1-T2: `grid`, `apartment-block`. |
   577→   577→| `mat_style` | `""` | Free-text style hint forwarded to material/texture generation. |
   578→   578→| `floor_area` | `120` | Target floorplate area in m² (per floor). |
   579→   579→| `rooms` | `4` | Total rooms across all floors; distributed proportionally. |
   580→   580→| `floors_above` | `1` | Storeys above ground (incl. ground floor). |
   581→   581→| `floors_below` | `0` | Basement storeys. |
   582→   582→| `windows` | `0` | Total above-ground window count; distributed across above-ground storeys. Basements get none. |
   583→   583→| `skylights` | `0` | Top-storey ceiling cutouts. |
   584→   584→| `roof` | `"flat"` | Roof shape: `flat`, `pitched`, `gabled`, `hipped`, `mansard`, `shed`. |
   585→   585→| `roof_overhang` | _unset_ | Eaves projection past the walls (m) for `gabled`/`pitched`. Unset → `gabled` flush, `pitched` modest default. |
   586→   586→| `ceiling_height` | `2.6` | Clear height per storey (m). |
   587→   587→| `door_w`, `door_h` | `0.9, 2.1` | Door opening dimensions (m). |
   588→   588→| `window_w`, `window_h` | `1.2, 1.4` | Window opening dimensions (m, medium class). Small = ×0.6, large = ×1.4. |
   589→   589→| `wall_thickness` | `0.12` | Exterior / interior wall thickness (m). |
   590→   590→| `ceiling_thickness` | `0.2` | Slab thickness (m). |
   591→   591→| `entrances` | `1` | Ground-floor external door count. |
   592→   592→| `external_door` | `"door_simple"` | Stdlib / user module ref. Stamped at each entrance. |
   593→   593→| `internal_door` | `"door_simple"` | Stamped at each interior opening. |
   594→   594→| `window_small`, `window_medium`, `window_large` | `"window_simple"` | Per-class window module refs. |
   595→   595→| `skylight` | `"skylight_simple"` | Skylight module ref; carves the top ceiling slab. |
   596→   596→| `elevators` | `0` | Vertical shafts on the east side, stamped with `elevator_shaft_simple`. |
   597→   597→| `staircases` | `0` | One straight flight per storey transition, stamped with `stair_simple`. `W1113` warns if missing on multi-storey. |
   598→   598→
   599→   599→`building` accepts only `room_type` and `adjacency` children.
   600→   600→
   601→   601→```
   602→   602→room_type "<name>" (kind=public|private|service|utility|secure|staff_only,
   603→   603→                    density=0..10, mat="<material>",
   604→   604→                    min_area=…, max_area=…)
   605→   605→adjacency "<room_type>" (adjacent_to=["a", "b"], away_from=["c"])
   606→   606→```
   607→   607→
   608→   608→`kind` is required on `room_type`; `density` weights sampling (0 disables
   609→   609→the type); `mat` overrides per-room floor/wall material. Adjacency rules
   610→   610→are **soft** — the solver runs 10 sub-seeded layouts and keeps the
   611→   611→highest-scoring (`+1`/m of shared wall for `adjacent_to`, `-1`/m for
   612→   612→`away_from`). Referencing an undeclared room-type is a validation error.
   613→   613→
   614→   614→```
   615→   615→building "house" (seed=4, style="apartment-block",
   616→   616→                  floor_area=85, rooms=6, windows=6, mat="wood") {
   617→   617→  room_type "bedroom"  (kind=private, density=4)
   618→   618→  room_type "kitchen"  (kind=service, density=1, mat="tile")
   619→   619→  room_type "living"   (kind=public,  density=2)
   620→   620→  adjacency "kitchen"  (adjacent_to=["living"])
   621→   621→}
   622→   622→```
   623→   623→
   624→   624→Beyond geometry, `building` embeds **points of interest** as empty marker
   625→   625→nodes (`role`/`tags` in glTF extras) so an engine can place its own content:
   626→   626→`entrance` / `door` / `window` opening slots, per-room furniture markers when
   627→   627→`furnish=1` (`bed`, `desk`, …), and per-floor **vertical-circulation** anchors
   628→   628→— `stair_access` (one per storey, at each floor's stair entry platform) and
   629→   629→`elevator_stop` (one per served storey, anchored at the shaft centre on the
   630→   630→floor surface where the cab stops). Each circulation marker faces its shaft
   631→   631→door and carries a `floor=<n>` tag, so you can drop your own stairwell /
   632→   632→elevator models knowing exactly where each floor connects. `debug_show_poi=1`
   633→   633→gives every marker a small bright `building_poi_<role>` sphere so the
   634→   634→otherwise geometry-free anchors show in a preview.
   635→   635→
   636→   636→### Cave
   637→   637→
   638→   638→`cave` is a procedural cave generator. One node expands into a single
   639→   639→watertight rock shell — a bounding block hollowed by a smooth-blended field of
   640→   640→chamber and passage carvers (surface-nets meshed) — plus optional scattered
   641→   641→features. Chambers are organised into `levels` stacked horizontal layers
   642→   642→(separated by `level_gap` rock, joined by `level_links` vertical ramps); within
   643→   643→a layer they mix `spacing`-separated rooms with `overlap`-merged caverns.
   644→   644→Passages steeper than `max_slope` are rebuilt as switchback ramps so no walkable
   645→   645→surface exceeds the angle cap; and
   646→   646→`entrances` punch horizontal mouths out through the nearest side face so the
   647→   647→cave is enterable. The generated subtree is stamped non-editable (pure function
   648→   648→of `seed=` plus the declared attrs). See `docs/caves.md` for the full spec.
   649→   649→
   650→   650→| attribute | default | effect |
   651→   651→|---|---|---|
   652→   652→| `seed` | `1` | RNG seed; same seed = identical cave. |
   653→   653→| `size` | `[24, 10, 24]` | Outer rock-block dimensions `[width, height, depth]` (m); base sits on `y=0`. |
   654→   654→| `chambers` | `6` | Number of chambers carved. |
   655→   655→| `levels` | `2` | Stacked horizontal layers (floors). Each is its own chamber+passage network. |
   656→   656→| `level_gap` | `1.5` | Solid rock kept between layers (m). |
   657→   657→| `level_links` | `1` | Vertical ramps carved between each adjacent layer pair (clamped ≥ 1 when `levels > 1`). |
   658→   658→| `chamber_min`, `chamber_max` | `2.5, 5.0` | Chamber radius range (m). Auto-capped to fit a layer's height. |
   659→   659→| `spacing` | `2.0` | Minimum rock gap between same-layer chambers (m); keeps rooms distinct. |
   660→   660→| `overlap` | `0.35` | Probability a chamber merges with a same-layer neighbour into a larger cavern. `0` = all separate, `1` = all clustered. |
   661→   661→| `chamber_flatten` | `0.6` | Vertical squash (height = radius × this); < 1 keeps floors gentle. |
   662→   662→| `passage_radius` | `1.1` | Tunnel radius (m). |
   663→   663→| `loops` | `1` | Extra connections beyond the spanning tree, for looping layouts. |
   664→   664→| `max_slope` | `45` | Maximum walkable slope (degrees); steeper passages switchback. |
   665→   665→| `roughness` | `0.35` | Wall-noise amount `[0, 1]` for a natural stone finish. |
   666→   666→| `blend` | `1.5` | Smooth-union radius blending chambers + passages. |
   667→   667→| `margin` | `2.0` | Rock thickness kept around the void on every face (m). |
   668→   668→| `resolution` | `96` | Voxel-grid resolution (32–224). Higher = finer + slower. |
   669→   669→| `lod_scale` | `1.0` | Mesh-quality scale `[0.1, 1.0]`; scales rock voxel grid + decoration tessellation. Lower = fewer triangles. Layout / counts / POIs unaffected. |
   670→   670→| `entrances` | `1` | Horizontal mouths punched to a side face. A scalar `N` opens `N` on the surface (top) band; an array `[b0, b1, …]` opens them per band from the bottom up (index `0` = lowest), so e.g. `entrances=[1, 0, 1]` connects a chosen storey to an adjacent dungeon. Bands past the array end get none; mouths prefer chambers nearest a wall. |
   671→   671→| `mat` | `cave_rock` | Rock material; defaults to an auto-stamped grey stone. |
   672→   672→| `water_mat` | `cave_water` | Material for pools / lakes. |
   673→   673→| `rock_piles`, `pools`, `lakes`, `stalagmites`, `stalactites`, `columns` | `0` | Decoration counts scattered on chamber floors / ceilings (`columns` span floor→ceiling). |
   674→   674→| `mushrooms` | `0` | Mushroom-spot POI markers on chamber floors (empty nodes, no geometry). |
   675→   675→| `debug_hide_shell` | `0` | Debug: slice the front (+Z) half of the rock away to see the chambers in cross-section (like `building`'s `debug_hide_roof`). |
   676→   676→| `debug_show_poi` | `0` | Debug: give every point-of-interest marker a small bright per-kind `cave_poi_<kind>` sphere (colour-coded by group) so the empty markers are visible in a preview. |
   677→   677→
   678→   678→Beyond geometry, `cave` embeds **points of interest** as empty marker nodes
   679→   679→(`role`/`tags` in glTF extras) under a `points_of_interest` group:
   680→   680→`dead_end_chamber` (single-connection rooms), `column_base`, `ladder_anchor`
   681→   681→(passages steeper than `max_slope`) and `mushroom_spot`. See `docs/caves.md`.
   682→   682→
   683→   683→Decorations are placed by querying the **real carved floor / ceiling** under
   684→   684→each feature, so drips and boulders sit flush on the surface rather than the
   685→   685→geometric chamber bound. `cave` accepts only `feature` children, which tune one
   686→   686→decoration kind:
   687→   687→
   688→   688→```
   689→   689→feature "<name>" (kind=stalagmite|stalactite|column|rock_pile|pool|lake,
   690→   690→                  count=…, min_size=…, max_size=…, mat="<material>")
   691→   691→```
   692→   692→
   693→   693→`kind` is required. `count` overrides the matching top-level count knob;
   694→   694→`min_size`/`max_size` set the size range (m); `mat` overrides the material.
   695→   695→
   696→   696→```
   697→   697→cave "hollow" (seed=12, size=[26, 12, 26], chambers=7, levels=2,
   698→   698→               max_slope=45, entrances=2, mat="limestone",
   699→   699→               stalagmites=14, stalactites=10, pools=2) {
   700→   700→  feature "spires" (kind=stalagmite, min_size=0.3, max_size=1.1)
   701→   701→}
   702→   702→```
   703→   703→
   704→   704→Every primitive is authored in its local frame and positioned via
   705→   705→`pos`/`rot`/`scale`. Defaults make bare `cylinder "leg"` a 1 m unit-radius
   706→   706→cylinder at the origin.
   707→   707→
   708→   708→### Terrain
   709→   709→
   710→   710→`terrain` is a procedural heightfield generator. One node expands into a grid of
   711→   711→independently cullable **chunk meshes** sampled from a coherent noise field, then
   712→   712→refined by an ordered chain of retouch passes (smoothing → terracing). The field
   713→   713→is normalised `0..1` and scaled by the height component of `size`; adjacent
   714→   714→chunks share boundary grid lines so seams are crack-free. `sea_level` does not
   715→   715→reshape the land — the terrain keeps its real shape underwater and the sea is a
   716→   716→flat plane laid on top. The generated subtree is stamped non-editable (a pure
   717→   717→function of `seed=` plus the declared attrs).
   718→   718→
   719→   719→| attribute | default | effect |
   720→   720→|---|---|---|
   721→   721→| `seed` | `1` | RNG seed; same seed = identical terrain. |
   722→   722→| `size` | `[40, 6, 40]` | Patch dimensions `[width, max_height, depth]` (m). `max_height` scales the normalised field; the patch is centred on the origin. |
   723→   723→| `source` | `fbm` | Noise shape: `fbm` (rolling hills), `ridged` (sharp mountain ridges), `billow` (rounded mounds), `island` (central landmass falling off to water at the edges — pair with `sea_level`), `voronoi` (cellular crater rims and cracked basins). |
   724→   724→| `octaves` | `4` | Noise octaves summed; more = finer detail. |
   725→   725→| `frequency` | `0.06` | Base noise frequency; higher = more, smaller features. |
   726→   726→| `persistence` | `0.5` | Per-octave amplitude falloff `[0, 1]`; higher = rougher. |
   727→   727→| `resolution` | `128` | Grid divisions across the patch (4–1024); rounded up to a multiple of `chunks`. |
   728→   728→| `chunks` | `4` | Splits the patch into a `chunks × chunks` grid of separately cullable meshes (1–16). |
   729→   729→| `lod_levels` | `3` | Baked render-LOD meshes per chunk (1–4). Level 0 is full detail; each higher level halves the sampling stride and takes over at a greater camera distance. `1` = full detail only, no distance swapping. |
   730→   730→| `smooth` | `0` | Box-blur passes (0–32) applied to soften the raw noise. |
   731→   731→| `terrace` | `0` | Quantise heights into this many stepped bands (0 = off, 0–64). |
   732→   732→| `sea_level` | `0.0` | Normalised waterline height `[0, 1]`; adds a flat water plane at this height and enables shoreline POIs. Land keeps its real shape underwater (basins are not flattened). |
   733→   733→| `peaks` | `0` | Number of summit POI markers placed on local maxima. |
   734→   734→| `flat_spots` | `0` | Number of buildable-flat-area POI markers (flattest neighbourhoods above sea level). |
   735→   735→| `shore_points` | `0` | Number of shoreline POI markers at the water's edge (requires `sea_level > 0`). |
   736→   736→| `colliders` | `none` | `all` adds a trimesh collider to every chunk; `none` is visual-only. |
   737→   737→| `lod_scale` | `1.0` | Mesh-quality scale `[0.1, 1.0]`; scales effective resolution. Lower = fewer triangles. POIs / sea level unaffected. |
   738→   738→| `mat` | `terrain_ground` | Ground material; defaults to an auto-stamped **white** PBR finish (the surface colour comes from the per-vertex bake below, which multiplies the base colour). A custom `mat=` tints the whole bake. |
   739→   739→| `debug_show_poi` | `0` | Debug: give every POI marker a small bright per-kind `terrain_poi_<kind>` sphere so the empty markers are visible in a preview. |
   740→   740→
   741→   741→Every chunk vertex carries a **baked surface colour** in `COLOR_0` (glTF
   742→   742→per-vertex colour, which multiplies the white ground material): a grass→rock
   743→   743→blend driven by slope (steep faces turn to bare rock) plus, when `sea_level > 0`,
   744→   744→sand hugging the waterline that fades to dark mud on the submerged floor. The
   745→   745→look therefore travels as plain glTF — no engine shader is required — and an
   746→   746→engine is still free to layer a runtime slope/height shader on top.
   747→   747→
   748→   748→Beyond geometry, `terrain` embeds **points of interest** as empty marker nodes
   749→   749→(`role`/`tags` in glTF extras) under a `points_of_interest` group: `peak`
   750→   750→(summit local maxima), `flat_spot` (buildable flat areas above sea level), and
   751→   751→`shoreline` (cells at the water's edge). Markers spread out so no two land on the
   752→   752→same feature.
   753→   753→
   754→   754→#### Carving children: `hole` and `road`
   755→   755→
   756→   756→A `terrain` body accepts only `hole` and `road` declarations (any other child is
   757→   757→an error — geometry parented here would be dropped). Both carve the same shared
   758→   758→height field, so chunk seams, skirts and POIs stay consistent with the result.
   759→   759→
   760→   760→**`hole`** drops the surface inside a footprint and walls the rim, punching a real
   761→   761→void into the baked mesh that a basement or cave mouth can slot into.
   762→   762→
   763→   763→| attribute | default | effect |
   764→   764→|---|---|---|
   765→   765→| `at` | `[0, 0]` | Footprint centre `[x, z]` in patch-local metres. |
   766→   766→| `radius` | — | Circular footprint radius (m). Give **either** `radius` **or** `size`, not both. |
   767→   767→| `size` | — | Rectangular footprint `[w, d]` (m). |
   768→   768→| `depth` | `4` | How far below the rim the floor sits (m). |
   769→   769→| `cap` | `open` | `open` = vertical rim walls drop to the floor depth, bottom left open (plug it with a basement/cave). `floor` = walls plus a flat floor quad = a fully sealed, watertight pit. |
   770→   770→
   771→   771→**`road`** flattens a corridor along a polyline to a smoothed longitudinal
   772→   772→profile (staying at the terrain's own height — no trench), and tints the corridor
   773→   773→toward a dirt/gravel colour baked into `COLOR_0`.
   774→   774→
   775→   775→| attribute | default | effect |
   776→   776→|---|---|---|
   777→   777→| `path` | — | Required centreline `[[x, z], [x, z], …]` (≥ 2 waypoints), patch-local metres. |
   778→   778→| `width` | `3` | Flattened corridor width (m). |
   779→   779→| `shoulder` | `= width/2` | Extra blend distance (m) outside the flat corridor where the road eases back into the surrounding terrain. |
   780→   780→
   781→   781→```
   782→   782→terrain "valley" (seed=2, size=[200, 12, 200], source="island", chunks=6) {
   783→   783→  hole ( at=[-30, -20], radius=14, depth=6, cap="floor" )  // sealed pit
   784→   784→  hole ( at=[40, 30], radius=10, depth=8, cap="open" )     // open shaft
   785→   785→  road ( path=[[-90, -60], [-20, -10], [30, 20], [90, 70]], width=8, shoulder=5 )
   786→   786→}
   787→   787→```
   788→   788→
   789→   789→Each chunk emits `lod_levels` overlapping mesh variants named
   790→   790→`chunk_<i>_<j>_lod<n>`, every variant tagged with a camera-distance band in glTF
   791→   791→`extras.lod` (`{ level, min_distance, max_distance }`). The bands partition
   792→   792→`[0, ∞)`, so exactly one variant is the active one at any distance: MoGen Studio's
   793→   793→viewer shows it (and frustum-culls per chunk), and an engine importer can wire the
   794→   794→same ranges into Godot `VisibilityRange`. Only the finest variant (level 0) carries
   795→   795→the trimesh collider and casts shadows; coarser variants are visual stand-ins, ringed
   796→   796→by a downward skirt so a neighbouring chunk at a different LOD can't open a crack in
   797→   797→the surface.
   798→   798→
   799→   799→```
   800→   800→terrain "valley" (seed=7, size=[80, 14, 80], source="fbm",
   801→   801→                  octaves=5, frequency=0.04, resolution=192, chunks=6,
   802→   802→                  lod_levels=3, smooth=2, sea_level=0.28,
   803→   803→                  peaks=8, flat_spots=12, shore_points=16,
   804→   804→                  colliders="all", mat="grassland")
   805→   805→```
   806→   806→

   808→   808→
   809→   809→### Dungeon
   810→   810→
   811→   811→`dungeon` is a procedural layout generator for dungeon-crawler levels. Where
   812→   812→`cave` carves an organic void from a smooth field, a dungeon is a **tile grid**:
   813→   813→axis-aligned rectangular rooms placed on a `cell`-metre lattice, joined by
   814→   814→straight/L-shaped corridors, stacked into `levels` floors that real staircase
   815→   815→geometry connects. Walls, floors and ceilings are clean **box meshes** and
   816→   816→doorways are gaps in the walls — the whole layout is watertight by construction.
   817→   817→The node takes no body block; the generated subtree is stamped non-editable (a
   818→   818→pure function of `seed=` plus the declared attrs).
   819→   819→
   820→   820→| attribute | default | effect |
   821→   821→|---|---|---|
   822→   822→| `seed` | `1` | RNG seed; same seed = identical layout. `0` is coerced to `1`. |
   823→   823→| `size` | `[48, 4, 48]` | Footprint + clearance `[width(x), room_height(y), depth(z)]` (m). `width`/`depth` set the grid footprint (÷ `cell`); `room_height` is one level's floor-to-ceiling clearance. |
   824→   824→| `cell` | `4` | Grid cell edge length (m). Rooms and corridors quantise to this lattice so walls always meet flush. |
   825→   825→| `levels` | `1` | Stacked floors. `1` is single-storey; higher values stack independent room layouts linked by staircases. |
   826→   826→| `stairs` | `1` | Staircases between each pair of adjacent levels. |
   827→   827→| `entrances` | `1` | Exterior doorways through the perimeter wall. A scalar `N` puts `N` on the ground floor; an array `[g, f1, f2, …]` sets each floor independently (index `0` = ground), so e.g. `entrances=[1, 0, 2]` opens a chosen storey onto an adjacent cave mouth or ledge. Floors past the array end get none; doors prefer dead-end rooms and the shortest border stub. |
   828→   828→| `rooms` | `6` | Target room count per level (placement is best-effort within the grid). |
   829→   829→| `room_min` | `2` | Room side length range in cells (inclusive). `room_min > room_max` is swapped. |
   830→   830→| `room_max` | `5` | — |
   831→   831→| `spacing` | `1` | Minimum rock gap kept between rooms of the same level, in cells. |
   832→   832→| `corridor_width` | `1` | Corridor width in cells. |
   833→   833→| `loops` | `1` | Extra corridor connections beyond the spanning tree, per level (creates loops). |
   834→   834→| `wall_thickness` | `0.4` | Wall thickness (m). |
   835→   835→| `floor_thickness` | `0.4` | Floor / ceiling deck thickness (m). |
   836→   836→| `ceilings` | `1` | Emit ceiling decks (each deck doubles as the next level's floor). `0` = open-topped levels. |
   837→   837→| `prop_spots` | `0` | Number of `prop_spot` POI markers scattered on room floors. |
   838→   838→| `colliders` | `all` | `all` adds a trimesh collider to every solid surface (decks, walls, steps); `none` is visual-only. |
   839→   839→| `lod_scale` | `1.0` | Mesh-quality scale `[0.1, 1.0]`; compounds with the file-global `lod_scale`. Layout, counts and POIs are unaffected. |
   840→   840→| `debug_hide_roof` | `0` | Debug: omit the topmost deck (roof) so rooms are visible from above in a preview. |
   841→   841→| `debug_render_floor` | _(unset)_ | Debug: render only this level index (`0` = ground), with no ceiling and only the staircases that touch it, to peek inside one floor. Out-of-range values render every level. |
   842→   842→| `debug_show_poi` | `0` | Debug: give every POI marker a small bright per-kind `dungeon_poi_<kind>` sphere so the empty markers show in a preview. |
   843→   843→
   844→   844→Geometry is built from **decks**: deck `k` is simultaneously the floor of level
   845→   845→`k` and the ceiling of level `k-1`, so there are no duplicate slabs. Every
   846→   846→walkable cell — including staircase landings — is covered, so the top level is
   847→   847→fully roofed and stairwells are enclosed. Staircases punch an opening through
   848→   848→the upper deck and fill it with a flight of small (~0.18 m riser) steps sized
   849→   849→for in-game use. Each **exterior doorway** is a one-cell floor stub run out to
   850→   850→the grid border with the perimeter wall there left open, so the dungeon has a
   851→   851→clear way in; `entrances` controls how many per floor (a scalar for the ground
   852→   852→floor, or a per-floor array) so a raised storey can open onto an adjacent cave
   853→   853→mouth or ledge. Walls are extended by `wall_thickness`
   854→   854→at their ends so corners always close — no holes. A single material pair
   855→   855→(`dungeon_floor`, `dungeon_stone`) is auto-stamped if you don't supply `mat=`.
   856→   856→
   857→   857→Beyond geometry, `dungeon` embeds **points of interest** as empty marker nodes
   858→   858→(`role`/`tags` in glTF extras) under a `points_of_interest` group: `entrance`
   859→   859→(the exterior doorway, oriented facing out), `spawn` (the room the entrance
   860→   860→leads into), `treasure_room` (other dead-end rooms), `stair_top` /
   861→   861→`stair_bottom` (staircase landings), and `prop_spot` (scattered room-floor
   862→   862→slots). An engine reads these to place the player, loot, transitions and props.
   863→   863→
   864→   864→```
   865→   865→dungeon "keep" (seed=7, size=[56, 4, 56], cell=4,
   866→   866→                levels=3, stairs=1,
   867→   867→                rooms=7, room_min=2, room_max=5, spacing=1,
   868→   868→                corridor_width=1, loops=1,
   869→   869→                prop_spots=8, colliders="all")
   870→   870→```

   874→   874→## Materials
   875→   875→
   876→   876→```
   877→   877→material "wood"  (color=[0.55, 0.35, 0.18], metallic=0.0, roughness=0.8)
   878→   878→material "glass" (color=[0.9, 0.95, 1.0], alpha=0.3, roughness=0.05, transmission=0.9)
   879→   879→material "neon"  (color=[1, 0.2, 1], emissive=[1, 0.2, 1], emissive_strength=8.0)
   880→   880→material "leaf"  (color=[0.25, 0.6, 0.2], alpha_mode="mask", alpha_cutoff=0.5)
   881→   881→```
   882→   882→
   883→   883→Declared at the top of the file or inside `scene { ... }`. Attributes:
   884→   884→
   885→   885→- `color` — vec3 `[r, g, b]` in linear space; alpha defaults to `1.0`.
   886→   886→- `alpha` — optional alpha override for transparency. Setting `alpha < 1`
   887→   887→  without an explicit `alpha_mode` auto-selects `"blend"`.
   888→   888→- `metallic` — `0.0`–`1.0`, default `0.0`.
   889→   889→- `roughness` — `0.0`–`1.0`, default `0.9`.
   890→   890→- `normal_strength` — slope multiplier baked into the *derived* normal
   891→   891→  map by `mogen textures`. `~0..8`, default `1.5`. No effect when
   892→   892→  `normal_texture` is authored directly.
   893→   893→- `occlusion_strength` — `0.0`–`1.0` ceiling on the *derived* AO darkness
   894→   894→  (`0` flat white, `1` cavities reach black). Default `0.7`. No effect
   895→   895→  when `occlusion_texture` is authored directly.
   896→   896→- `alpha_mode` — `"opaque"` (default), `"blend"` (translucent), or `"mask"`
   897→   897→  (1-bit cutout, e.g. foliage).
   898→   898→- `alpha_cutoff` — threshold for `alpha_mode="mask"`, default `0.5`.
   899→   899→- `emissive` — vec3 glow added on top of PBR. Screens, embers, lava.
   900→   900→  Default `[0, 0, 0]`.
   901→   901→- `emissive_strength` — HDR multiplier on `emissive`
   902→   902→  (`KHR_materials_emissive_strength`); `> 1.0` drives bloom. Default `1.0`.
   903→   903→- `transmission` — `0.0`–`1.0` light through the surface
   904→   904→  (`KHR_materials_transmission`); `1` is clear glass. Orthogonal to
   905→   905→  `alpha_mode` — glass/water use this, gels/tints/smoke use `alpha`.
   906→   906→- `double_sided` — `0` (default) or `1`. When `1`, draws both triangle
   907→   907→  faces (glTF `doubleSided`). Use for leaves, fins, flags, cloth, and thin
   908→   908→  `curved_plane`/`plane`/`disc`/`quad` whose underside is visible.
   909→   909→- `uv_mode` — `"tile"` (default) or `"fit"`. `"tile"` emits world-space
   910→   910→  UVs (1 unit = 1 tile, scaled by `uv_scale`) — repeating surfaces like
   911→   911→  walls, planks, fabric. `"fit"` uses per-face `[0, 1]²` UVs so each face
   912→   912→  shows the full image once — image-as-texture (signs, paintings, decals).
   913→   913→- `uv_scale` — scalar or vec2; default `1.0`. In `tile` mode: tiles per
   914→   914→  world unit (`2` = denser, `0.5` = bigger). In `fit` mode: multiplies
   915→   915→  `[0, 1]` coords. Vec2 stretches asymmetrically.
   916→   916→- `base_color_texture` — string path to a `.png`/`.jpg`/`.svg` file on disk,
   917→   917→  resolved relative to the `.mog` file. Multiplied against `color`. sRGB.
   918→   918→  See [SVG textures](#svg-textures) for how `.svg` is handled.
   919→   919→- `metallic_roughness_texture` — packed metal/rough map (glTF convention:
   920→   920→  green = roughness, blue = metallic). Linear.
   921→   921→- `normal_texture` — tangent-space normal map. Linear.
   922→   922→- `occlusion_texture` — ambient occlusion (red channel). Linear.
   923→   923→- `emissive_texture` — emissive colour map, multiplied against `emissive`.
   924→   924→  sRGB.
   925→   925→- `texture_size` — positive whole number; default `1024`. Pixel edge length
   926→   926→  that `.svg` texture slots on this material rasterize to. Ignored by
   927→   927→  `.png`/`.jpg` slots, which embed at their authored size.
   928→   928→- `texture_wrap` — `0` (default) or `1`. Rasterize `.svg` slots with
   929→   929→  wrap-around so artwork crossing the tile boundary reappears on the opposite
   930→   930→  edge instead of being clipped. No effect on art that stays inside the
   931→   931→  viewBox, so it is always safe to enable on a tile.
   932→   932→- `prompt` — free-form subject hint for `mogen textures` when generating
   933→   933→  albedo (e.g. `prompt="navy nylon ripstop weave"`). Steers Gemini away
   934→   934→  from the default "material name + colour" framing; auto-rephrased on
   935→   935→  recitation rejection.
   936→   936→- `shader` — `"standard"`/`"pbr"` (default, the regular PBR path), the
   937→   937→  built-in `"water"` preset, or the name of a user-declared `shader "<name>"`
   938→   938→  (see [Shaders](#shaders) below). Studio-preview only — the exported `.glb`
   939→   939→  always uses standard PBR scalars; the shader name + `shader_params` ride
   940→   940→  along as `node.extras.shader` metadata for downstream consumers. `"water"`
   941→   941→  reinterprets the standard knobs as a procedural water shader: `color` is
   942→   942→  the body tint, `uv_scale` is ripple density, `roughness` controls
   943→   943→  chop/foam (`0.05` glassy → `1.0` whitecaps), `metallic` lerps toward
   944→   944→  liquid-metal Fresnel, `transmission` + `alpha_mode="blend"` lets the floor
   945→   945→  show through, and `normal_texture`/`base_color_texture` blend into the
   946→   946→  procedural waves. It also declares one parameter of its own,
   947→   947→  `absorption` (float, default `1.5`) — the depth in world units over which
   948→   948→  transmitted radiance falls to `1/e`, set via `shader_params (absorption=…)`
   949→   949→  like any other. `0` is clear glass, so the default is deliberately not zero.
   950→   950→- `gradient` — optional ramp baked into per-vertex `COLOR_0` at export
   951→   951→  time. Four surface forms, all colours are vec3 in sRGB `[0..1]`:
   952→   952→  - `linear(from=[…], to=[…], axis=x|y|z)` — interpolates between two
   953→   953→    colours along the named local axis (default `y`).
   954→   954→  - `vertical(from=[…], to=[…])` — sugar for `linear(axis=y)`. No `axis=`.
   955→   955→  - `radial(center=[…], edge=[…])` — centre-to-corner falloff in the
   956→   956→    mesh's local AABB. No `axis=`.
   957→   957→  - `stops(colors=[[…], …], positions=[…], axis=…, kind=linear|radial)` —
   958→   958→    multi-stop ramp. `positions` defaults to even spacing across `[0, 1]`
   959→   959→    if omitted; `kind` defaults to `linear`.
   960→   960→
   961→   961→  `COLOR_0` multiplies `baseColorFactor` per the glTF spec, so pair the
   962→   962→  gradient with `color=[1, 1, 1]` to get the ramp unaltered, or with a
   963→   963→  tinted `color=` to tint the whole ramp. Vertex colours need vertices to
   964→   964→  interpolate between — bump primitive `segments`/`rings`/`segments_u/v`
   965→   965→  for smoother ramps; a default 6-vert box reads as a hard step, not a
   966→   966→  gradient.
   967→   967→
   968→   968→Example:
   969→   969→
   970→   970→```
   971→   971→material "oak" (
   972→   972→  color=[1, 1, 1],
   973→   973→  roughness=0.8,
   974→   974→  base_color_texture="textures/oak_albedo.png",
   975→   975→  normal_texture="textures/oak_normal.png"
   976→   976→)
   977→   977→
   978→   978→material "lake" (color=[0.05, 0.32, 0.45], shader="water")
   979→   979→```
   980→   980→
   981→   981→Texture files are embedded in the output GLB (self-contained, movable
   982→   982→without sources); missing files are a hard error at export. Reference a
   983→   983→material via `mat="wood"`; unknown names are a hard error at lowering.
   984→   984→
   985→   985→### SVG textures
   986→   986→
   987→   987→Any texture slot accepts a `.svg` path. glTF 2.0 has no vector image type —
   988→   988→its core spec defines only `image/png` and `image/jpeg` — so mogen rasterizes
   989→   989→SVG to PNG at build time and embeds that. This happens before anything else
   990→   990→inspects the scene, so the GLB, the FBX exporter, Studio's preview, and the
   991→   991→derived-PBR pipeline all see raster only; nothing downstream ever encounters a
   992→   992→`.svg` path.
   993→   993→
   994→   994→```
   995→   995→material "tiles" (
   996→   996→  color=[1, 1, 1],
   997→   997→  uv_mode="fit",
   998→   998→  base_color_texture="textures/hex.svg",
   999→   999→  texture_size=2048,
  1000→  1000→  texture_wrap=1
  1001→  1001→)
  1002→  1002→```
  1003→  1003→
  1004→  1004→Notes:
  1005→  1005→
  1006→  1006→- **Size is yours to choose.** SVG carries no intrinsic pixel size, so
  1007→  1007→  `texture_size` (default `1024`) decides it. The viewBox is scaled to fill
  1008→  1008→  the square exactly — a non-square viewBox is stretched rather than
  1009→  1009→  letterboxed, since these are UV-space tiles where aspect correction belongs
  1010→  1010→  to `uv_scale`.
  1011→  1011→- **Text must be converted to paths first.** The rasterizer is built without
  1012→  1012→  font support on purpose: resolving font names would make output depend on
  1013→  1013→  which fonts the build machine happens to have installed, and identical
  1014→  1014→  sources must produce identical bytes.
  1015→  1015→- **Rasterization is deterministic and uncached.** The same SVG at the same
  1016→  1016→  size yields byte-identical output every build, so there is nothing to
  1017→  1017→  invalidate. One SVG used at two `texture_size` values embeds twice, as it
  1018→  1018→  must.
  1019→  1019→- **`texture_wrap=1` synthesises a seamless tile.** The art is drawn on a 3×3
  1020→  1020→  lattice and the centre cell kept, so shapes overhanging the viewBox reappear
  1021→  1021→  on the opposite edge instead of being clipped. This is the one thing a
  1022→  1022→  vector source buys that a supplied PNG cannot — the renderer is ours, so the
  1023→  1023→  wrap can be manufactured rather than hand-authored. The nine draws composite
  1024→  1024→  normally, which makes the result exactly what painting the art across an
  1025→  1025→  endless field of adjacent tiles would give. Art contained by the viewBox is
  1026→  1026→  untouched, and overhang narrower than the tile only lands where the centre
  1027→  1027→  drew nothing — but a *translucent* shape wider than the whole tile overlaps
  1028→  1028→  itself, and reads darker in a band at each edge. The bands match across the
  1029→  1029→  join, so the tiling stays seamless; split such a shape if the frame shows.
  1030→  1030→
  1031→  1031→Seamlessness on a **curved** surface is a separate matter, and `.svg` does not
  1032→  1032→by itself fix it: it is a property of the UV layout, not the image format. A
  1033→  1033→sphere's equirectangular mapping pinches at the poles no matter what feeds it,
  1034→  1034→and `uv_mode="tile"` scales U by world arc length, which lands mid-tile at the
  1035→  1035→wrap for most radii. For a seamless sphere, pair a wrap-authored tile with
  1036→  1036→`uv_mode="fit"`.
  1037→  1037→
  1038→  1038→**Not yet compatible with `bundle_lods_and_imposter`.** That export option's
  1039→  1039→imposter bake reads texture files straight off disk through its own headless
  1040→  1040→GL renderer, independent of the rasterization pass described above, and can't
  1041→  1041→decode `.svg` either. Combining the two is a hard error at export time.
  1042→  1042→Pre-rasterize the texture to `.png` if you need both.
  1043→  1043→
  1044→  1044→---
  1045→  1045→
  1046→  1046→## Shaders
  1047→  1047→
  1048→  1048→A `shader "<name>" { ... }` declaration names an on-disk GLSL fragment
  1049→  1049→snippet and the parameters materials may feed it. mogen never compiles or
  1050→  1050→runs the GLSL — it only carries the path + resolved parameter values as
  1051→  1051→`node.extras.shader` metadata on the glTF nodes bound to a referencing
  1052→  1052→material. MoGen Studio is the one component that actually compiles a
  1053→  1053→declared shader, for live preview. The built-in `water` preset (see
  1054→  1054→`shader=` above) is just the first client of this system — it declares an
  1055→  1055→`absorption` param and resolves it through the same path a user shader's
  1056→  1056→params take, and declaring your own `shader "water" { ... }` shadows it.
  1057→  1057→
  1058→  1058→```
  1059→  1059→shader "ripple" (source="shaders/ripple.glsl") {
  1060→  1060→  param "speed" (type=float, default=2.0)
  1061→  1061→  param "tint"  (type=color, default=[0.0, 0.3, 0.5])
  1062→  1062→}
  1063→  1063→
  1064→  1064→material "pond" (color=[0.1, 0.2, 0.3], shader="ripple") {
  1065→  1065→  shader_params (speed=3.5, tint=[0.0, 0.4, 0.6])
  1066→  1066→}
  1067→  1067→```
  1068→  1068→
  1069→  1069→`shader` attributes:
  1070→  1070→
  1071→  1071→- `source` — path to the GLSL fragment snippet, resolved relative to the
  1072→  1072→  `.mog` file the same way texture paths are.
  1073→  1073→
  1074→  1074→Each `param "<name>" { ... }` child declares one uniform the snippet may
  1075→  1075→use:
  1076→  1076→
  1077→  1077→- `type` — `float`, `vec2`, `vec3`, `vec4`, or `color` (an RGB `vec3`
  1078→  1078→  authored as `[r, g, b]`).
  1079→  1079→- `default` — value used when a referencing material supplies no override
  1080→  1080→  via `shader_params`. Must match the declared `type`.
  1081→  1081→
  1082→  1082→A material opts in with `shader="<name>"` (built-in `water`, or a declared
  1083→  1083→name) and overrides individual parameter values with a `shader_params (...)`
  1084→  1084→child block — any attribute name matching a declared `param` name; names
  1085→  1085→that don't match warn (`W0108`) but don't fail the build. Referencing an
  1086→  1086→undeclared, non-built-in shader name is a hard error (`E0106`) at
  1087→  1087→validation time. Shaders declared in an imported file aren't currently
  1088→  1088→visible to the importing file's materials — declare shaders in the file
  1089→  1089→that uses them.
  1090→  1090→

  1093→  1093→## Physics
  1094→  1094→
  1095→  1095→A `physics` substance is the *feel* of an object, the counterpart to
  1096→  1096→`material`'s *look*. Declared once and referenced with `phys=`, it lets an
  1097→  1097→engine reconstruct a rigid body — and because mogen builds real watertight
  1098→  1098→geometry, it **computes the weight and centre of gravity for you** from the
  1099→  1099→mesh. mogen runs no simulation; this is metadata written to `node.extras`.
  1100→  1100→
  1101→  1101→```
  1102→  1102→material "wood" (color=[0.55, 0.35, 0.18])            // look
  1103→  1103→physics  "oak"  (weight=700kg/m3, friction=0.55, bounce=0.15)  // feel
  1104→  1104→
  1105→  1105→scene {
  1106→  1106→  box "crate" (size=[1, 1, 1], mat="wood", phys="oak")   // → weighs 700 kg
  1107→  1107→}
  1108→  1108→```
  1109→  1109→
  1110→  1110→Attributes: `weight` (a weight **per cubic metre**, e.g. `700kg/m3` — density in
  1111→  1111→human words, not the jargon "density"), `friction` (`0` ice … `1` rubber), and
  1112→  1112→`bounce` (`0` dead thud … `1` superball). A geometry node references a substance
  1113→  1113→with `phys="oak"`; the object's weight is `weight_per_m3 × volume` and its
  1114→  1114→centre of gravity is the mesh centroid, both auto-computed and written into
  1115→  1115→`node.extras.physics`. A flat per-node `weight=5kg` overrides the computed value
  1116→  1116→for props whose weight shouldn't follow from their size.
  1117→  1117→
  1118→  1118→`phys=` **inherits** down the hierarchy like `mat=`: set it on a `group` and
  1119→  1119→every child without its own `phys=` inherits it and weighs itself. A group that
  1120→  1120→carries a substance but no mesh of its own reports the **compound** weight and
  1121→  1121→mass-weighted centre of gravity of its whole subtree, so an engine can treat the
  1122→  1122→assembly as one rigid body. Weight units carry a dimension — a mass literal
  1123→  1123→(`5kg`) is only valid on `weight=`; using one elsewhere (`size=[5kg,1,1]`) is a
  1124→  1124→parse error.
  1125→  1125→
  1126→  1126→See [`physics.md`](./physics.md) for the full spec: weight units, the `extras`
  1127→  1127→shape engines read, validation codes, and current limitations.
  1128→  1128→

  1130→  1130→
  1131→  1131→## Decals
  1132→  1132→
  1133→  1133→A `decal` is a transparent image (logo, label, sticker, seal) projected
  1134→  1134→onto a surface. It lowers to a thin double-sided quad floating slightly
  1135→  1135→off the parent, with an auto-synthesised `alpha_mode="blend"` material
  1136→  1136→whose albedo is an RGBA PNG.
  1137→  1137→
  1138→  1138→```
  1139→  1139→decal "logo" (
  1140→  1140→  pos = [0, 0.1, 0.101],
  1141→  1141→  size = [0.25, 0.12],
  1142→  1142→  prompt = "embroidered MoGen logo, white thread on dark fabric"
  1143→  1143→)
  1144→  1144→```
  1145→  1145→
  1146→  1146→Attributes:
  1147→  1147→
  1148→  1148→- `size` — `[w, h]` in local units. Default `[0.5, 0.5]`. The decal is a
  1149→  1149→  flat XY quad whose normal points along its local +Z; rotate the decal
  1150→  1150→  with `rot=` / `rx`/`ry`/`rz` to point its face wherever you need.
  1151→  1151→- `prompt` — image description handed to Gemini when running
  1152→  1152→  `mogen textures`. Asks for an RGBA PNG with a fully transparent
  1153→  1153→  background; the resolved file path is spliced back into the source as
  1154→  1154→  `image="…"` for reproducibility.
  1155→  1155→- `image` — explicit path to an existing RGBA PNG (relative to the `.mog`
  1156→  1156→  file). Wins over `prompt=`; skips the LLM call entirely.
  1157→  1157→- `tint` — vec3 `[r, g, b]` multiplied against the decal's albedo.
  1158→  1158→  Default `[1, 1, 1]` (no tint).
  1159→  1159→- `roughness` — `0.0`–`1.0`. Default `0.6`.
  1160→  1160→- `offset` — `+Z` gap from the surface (avoids z-fighting); default
  1161→  1161→  `0.001`. Raise on coarse geometry.
  1162→  1162→
  1163→  1163→### Curved surfaces: `on=` / `at=`
  1164→  1164→
  1165→  1165→For flat surfaces, parent the decal under the surface and use `pos=`. For
  1166→  1166→curved surfaces, `on=`/`at=` synthesise a `conform` patch so the decal
  1167→  1167→hugs the curvature.
  1168→  1168→
  1169→  1169→```
  1170→  1170→ellipsoid "bag" (size=[1.0, 0.5, 0.5], mat="leather") {
  1171→  1171→  connector "front_spot" (at=[0.0, 0.0, 0.25], dir=[0, 0, 1])
  1172→  1172→}
  1173→  1173→decal "bag_logo" (
  1174→  1174→  size = [0.18, 0.10],
  1175→  1175→  on   = "bag",
  1176→  1176→  at   = "front_spot",
  1177→  1177→  prompt = "embroidered MoGen wordmark, cream thread on dark leather"
  1178→  1178→)
  1179→  1179→```
  1180→  1180→
  1181→  1181→- `on` — name of the target node to conform onto. Triggers the shortcut.
  1182→  1182→- `at` — required when `on=` is set; names the connector on the target that
  1183→  1183→  acts as the patch anchor.
  1184→  1184→- `up` — optional `x|y|z`; which local axis points along the surface normal.
  1185→  1185→  Defaults to `z` (the decal quad's face direction).
  1186→  1186→- `lift` — optional outward offset along the surface normal, applied during
  1187→  1187→  conform. Layered on top of the per-mesh `offset=` value, so use `lift=`
  1188→  1188→  on coarse target geometry where you need extra separation. Defaults to 0.
  1189→  1189→
  1190→  1190→When `on=` is set the decal is reparented under the target. Its `pos=` is
  1191→  1191→dropped (positioning comes from `at=`), but `rot=` and `scale=` are baked
  1192→  1192→into the artwork before projection — so `rz=90` spins the logo in the
  1193→  1193→tangent plane, `scale=[2, 1, 1]` widens it. Off-plane rotations work but
  1194→  1194→rarely produce what authors want; reach for `rz=` for "spin the logo."
  1195→  1195→
  1196→  1196→If neither `prompt=` nor `image=` is set, the decal's name is used as the
  1197→  1197→prompt. Rules:
  1198→  1198→
  1199→  1199→- `mat=` is rejected — decals own their material. Use `tint`/`roughness`.
  1200→  1200→- Each decal gets its own auto-named material (`__decal_<name>`) and is
  1201→  1201→  never merged into same-material siblings by the export merge pass.
  1202→  1202→- `mogen textures` asks Gemini for transparent-background RGBA directly;
  1203→  1203→  there is no chroma-key step.
  1204→  1204→- `at=`, `up=`, `lift=` are validation errors without `on=`.
  1205→  1205→

  1207→  1207→
  1208→  1208→## Connectors
  1209→  1209→
  1210→  1210→Connectors are oriented frames that a node exposes so other nodes can attach
  1211→  1211→to it. They do not produce geometry.
  1212→  1212→
  1213→  1213→```
  1214→  1214→box "seat" (pos=[0, 0.5, 0], size=[1.0, 0.1, 1.0]) {
  1215→  1215→  connector "top"    (at=[0,  0.05, 0], dir=[0,  1, 0], tag=seat_top)
  1216→  1216→  connector "bottom" (at=[0, -0.05, 0], dir=[0, -1, 0], tag=seat_bottom)
  1217→  1217→}
  1218→  1218→```
  1219→  1219→
  1220→  1220→Attributes:
  1221→  1221→
  1222→  1222→| attribute | value | default |
  1223→  1223→|---|---|---|
  1224→  1224→| `at` | `vec3` | `[0, 0, 0]` |
  1225→  1225→| `dir` | `vec3` (any nonzero) | `[0, 1, 0]` |
  1226→  1226→| `tag` | string or ident | empty |
  1227→  1227→| `radius` | number | — (unset) |
  1228→  1228→
  1229→  1229→Stored as a position + quaternion (rotates `+Y` onto `dir`). `tag` groups
  1230→  1230→compatible attach points (e.g. every leg top shares `tag=leg_top`) so
  1231→  1231→fitting logic can pair them. When a node is the `child` of an `attach`,
  1232→  1232→its `pos`/`rot` apply as a local offset on top of the alignment (so
  1233→  1233→Studio gizmo drags persist).
  1234→  1234→
  1235→  1235→---
  1236→  1236→
  1237→  1237→## Attach: rigid alignment of two connector frames
  1238→  1238→
  1239→  1239→`attach` aligns a child's `plug` connector with a parent's `socket`,
  1240→  1240→then reparents the child under the parent. Rigid alignment with optional
  1241→  1241→offset + roll.
  1242→  1242→
  1243→  1243→```
  1244→  1244→scene {
  1245→  1245→  cylinder "trunk"  (radius=0.2, height=1.0) {
  1246→  1246→    connector "top" (at=[0, 0.5, 0], dir=[0, 1, 0], tag=trunk_top)
  1247→  1247→  }
  1248→  1248→  sphere   "canopy" (radius=0.5) {
  1249→  1249→    connector "stem" (at=[0, -0.5, 0], dir=[0, -1, 0], tag=canopy_stem)
  1250→  1250→  }
  1251→  1251→  attach (parent="trunk", child="canopy", socket="top", plug="stem")
  1252→  1252→}
  1253→  1253→```
  1254→  1254→
  1255→  1255→| attribute | required | default | effect |
  1256→  1256→|---|---|---|---|
  1257→  1257→| `parent` | yes | — | name of the node carrying the `socket` connector |
  1258→  1258→| `child`  | yes | — | name of the node carrying the `plug` connector |
  1259→  1259→| `socket` | no  | `"top"` | connector name on `parent` |
  1260→  1260→| `plug`   | no  | `"bottom"` | connector name on `child` |
  1261→  1261→| `offset` | no  | `0.0` | gap (m) along the socket's outward direction; positive lifts the child away from the parent |
  1262→  1262→| `twist`  | no  | `0.0` | roll (degrees) around the socket's axis after alignment |
  1263→  1263→
  1264→  1264→The child is reparented under the parent and its local TRS recomputed so
  1265→  1265→the two connector frames coincide (`+offset` along the socket normal,
  1266→  1266→`twist` around it). Author `pos=`/`rot=` on the child remain additive
  1267→  1267→offsets on top of the alignment (so Studio gizmo drags survive rebuilds).
  1268→  1268→
  1269→  1269→`attach` runs per-instance inside `array`/`mirror` — one declaration glues
  1270→  1270→every replicated copy.
  1271→  1271→
  1272→  1272→---
  1273→  1273→
  1274→  1274→## Conform: moulding a primitive onto a target surface
  1275→  1275→
  1276→  1276→`conform` deforms a child primitive's *vertex positions* so it lies on a
  1277→  1277→target mesh's surface. It has two modes:
  1278→  1278→
  1279→  1279→- **Path mode (`from=`/`to=`)** — stretches a strip or tube between two
  1280→  1280→  connectors. Zips, labels, trim, hoses, ribbons, seams.
  1281→  1281→- **Patch mode (`at=`)** — bends a flat/disc child onto the local surface
  1282→  1282→  curvature at one anchor connector. Pockets, decals, plates, eye spots.
  1283→  1283→
  1284→  1284→Conform deforms vertices where `attach` would only align rigidly. The mode
  1285→  1285→is picked by the attrs supplied; mixing or omitting both is an error.
  1286→  1286→
  1287→  1287→```
  1288→  1288→// Path mode — strip stretched along a curve.
  1289→  1289→conform (target="bag", child="zip", from="zip_a", to="zip_b",
  1290→  1290→         along=x, lift=0.005)
  1291→  1291→
  1292→  1292→// Patch mode — disc anchored at a single point.
  1293→  1293→conform (target="bag", child="pocket", at="pocket_spot", lift=0.002)
  1294→  1294→```
  1295→  1295→
  1296→  1296→### Shared attributes
  1297→  1297→
  1298→  1298→| attribute | required | default | effect |
  1299→  1299→|---|---|---|---|
  1300→  1300→| `target` | yes | — | name of the surface mesh node to mould onto |
  1301→  1301→| `child` | yes | — | name of the primitive whose vertices get deformed |
  1302→  1302→| `lift` | no | `0.0` | outward offset along the surface normal (m) — typically a fraction of a millimetre to avoid z-fighting |
  1303→  1303→| `reparent` | no | `1` | reparent child under target after conform; pass `0` to keep its original parent |
  1304→  1304→
  1305→  1305→### Path mode — `from=` / `to=`
  1306→  1306→
  1307→  1307→Each child vertex's coordinate on the `along` axis becomes a position along
  1308→  1308→the surface path; the perpendicular axes lie tangent / normal to the surface
  1309→  1309→at each sample.
  1310→  1310→
  1311→  1311→| attribute | required | default | effect |
  1312→  1312→|---|---|---|---|
  1313→  1313→| `from` | yes | — | connector name on `target` — start of the path |
  1314→  1314→| `to` | yes | — | connector name on `target` — end of the path |
  1315→  1315→| `along` | no | `x` (flat strips) / `y` (tubes) | which child-local axis is the path axis |
  1316→  1316→| `width` | no | inferred from `along` | child-local axis perpendicular to path, tangent to surface |
  1317→  1317→| `height` | no | inferred from `along` | child-local "thickness" axis (along surface normal) |
  1318→  1318→| `samples` | no | `64` | path subdivisions (clamped to ≥ 2). Increase for high-curvature surfaces |
  1319→  1319→| `twist` | no | `0` | total roll (degrees) around the path tangent across the strip |
  1320→  1320→
  1321→  1321→**Compatible primitives** (path mode):
  1322→  1322→
  1323→  1323→- **Flat strips**: `box`, `plane`, `quad`, `curved_plane`, `slab`, `post`, `panel`, `wall`, `spline_ribbon`
  1324→  1324→- **Tubes**: `cylinder`, `capsule`, `tube`, `spline_tube` (cross-section ring rotates with the surface frame)
  1325→  1325→- **Imported meshes** via `mesh "..." (src="...")`: accepted, but `along=` is required
  1326→  1326→
  1327→  1327→### Patch mode — `at=`
  1328→  1328→
  1329→  1329→Each child vertex is independently snapped to its closest point on the target
  1330→  1330→surface; the child's `up` axis becomes the surface-outward direction at every
  1331→  1331→vertex. This makes flat decals (a disc, a quad) bend to follow curvature
  1332→  1332→locally without forcing the author to pick a path or supply two endpoints.
  1333→  1333→
  1334→  1334→| attribute | required | default | effect |
  1335→  1335→|---|---|---|---|
  1336→  1336→| `at` | yes | — | connector name on `target` — patch centre |
  1337→  1337→| `up` | no | `y` (most flat primitives) / `z` (`quad`, `leaf_card`) | which child-local axis aligns with the surface outward normal |
  1338→  1338→
  1339→  1339→**Compatible primitives** (patch mode):
  1340→  1340→
  1341→  1341→- **Flat decals**: `disc`, `plane`, `quad`, `curved_plane`, `leaf_card`
  1342→  1342→- **Box-likes used as thin patches**: `box`, `slab`, `panel`, `wall` — give them a small extent on the `up` axis
  1343→  1343→- **Round primitives with a flat side**: `cylinder`, `hemisphere`, `half_cylinder` (a thin cylinder makes a perfect round disc)
  1344→  1344→- **Imported meshes**: accepted, but `up=` is required
  1345→  1345→
  1346→  1346→### Rejected primitives
  1347→  1347→
  1348→  1348→Closed shapes with no canonical surface axis (`sphere`, `ellipsoid`,
  1349→  1349→`icosphere`, `torus`, `torus_arc`, `superellipsoid`, `pyramid`, `cone`,
  1350→  1350→`frustum`, `lathe`, `prism`, `rounded_box`, `wedge`) and CSG result nodes
  1351→  1351→are rejected in both modes. The error message suggests the other mode if
  1352→  1352→it would have worked.
  1353→  1353→
  1354→  1354→### Tessellation
  1355→  1355→
  1356→  1356→The deformation reads each child vertex's `along`-axis coordinate as its
  1357→  1357→path position, so a bare `box` (only two distinct values per axis) can't
  1358→  1358→bend. `conform` auto-inserts planar cuts perpendicular to `along` when the
  1359→  1359→child is coarser than `samples / 4` segments (clamped 8–64). Author
  1360→  1360→subdivision (`curved_plane (segments_u=48)`, etc.) overrides.
  1361→  1361→
  1362→  1362→### Examples
  1363→  1363→
  1364→  1364→```
  1365→  1365→// Path mode — zip stretched between two connectors on a curved bag.
  1366→  1366→scene {
  1367→  1367→  ellipsoid "bag" (size=[1.0, 0.5, 0.5], mat="leather") {
  1368→  1368→    connector "zip_a" (at=[-0.4, 0.20, 0.22], dir=[0, 0, 1])
  1369→  1369→    connector "zip_b" (at=[ 0.4, 0.20, 0.22], dir=[0, 0, 1])
  1370→  1370→  }
  1371→  1371→  box "zip" (size=[0.8, 0.012, 0.04], mat="rubber")
  1372→  1372→  conform (target="bag", child="zip", from="zip_a", to="zip_b",
  1373→  1373→           along=x, lift=0.005)
  1374→  1374→}
  1375→  1375→```
  1376→  1376→
  1377→  1377→```
  1378→  1378→// Patch mode — round pocket bent onto the bag's side.
  1379→  1379→scene {
  1380→  1380→  superellipsoid "body" (size=[0.6, 0.3, 0.3], ew=1.5, ns=1.2, mat="fabric") {
  1381→  1381→    connector "spot" (at=[0.3, 0, 0], dir=[1, 0, 0])
  1382→  1382→  }
  1383→  1383→  disc "pocket" (radius=0.08, segments=32, mat="accent")
  1384→  1384→  conform (target="body", child="pocket", at="spot", lift=0.002)
  1385→  1385→}
  1386→  1386→```
  1387→  1387→
  1388→  1388→Tube children use `along=y` (the cylinder's long axis). Wrap-around paths
  1389→  1389→(e.g. a label around a bottle) use `along=x` on a `curved_plane`.
  1390→  1390→
  1391→  1391→### Pass ordering and reparenting
  1392→  1392→
  1393→  1393→Conform runs after `attach` and before skin binding. With `reparent=1`
  1394→  1394→(default) the child is moved under the target with identity local
  1395→  1395→transform; the child's user `pos=`/`rot=` is discarded. `reparent=0` keeps
  1396→  1396→the original parent and transforms the deformed mesh back into the child's
  1397→  1397→local frame.
  1398→  1398→
  1399→  1399→### Path generation
  1400→  1400→
  1401→  1401→Built by chord-and-snap: each sample's chord-interpolated point is
  1402→  1402→projected onto the target via closest-point query. Not a true geodesic;
  1403→  1403→crank `samples=` for high-curvature paths. `twist` ramps roll around the
  1404→  1404→path tangent from 0 at the start to `twist°` at the end.
  1405→  1405→
  1406→  1406→### Reserved (not yet implemented)
  1407→  1407→
  1408→  1408→Lowering rejects with a clear message: `direction` (projection-mode decal
  1409→  1409→splat), `curve` (only `"geodesic_lerp"` in v1), `via` (multi-segment paths).
  1410→  1410→
  1411→  1411→---
  1412→  1412→
  1413→  1413→## Replicators: `mirror`, `array`, `stack`, `grid`
  1414→  1414→
  1415→  1415→Wrapper nodes that create one parent group and either replicate or lay out
  1416→  1416→their children. All four accept the usual transform attributes so the whole
  1417→  1417→cluster can be positioned as a unit.
  1418→  1418→
  1419→  1419→### `mirror`
  1420→  1420→
  1421→  1421→```
  1422→  1422→mirror "pair" (axis=x) {
  1423→  1423→  sphere "ball" (pos=[0.5, 0.5, 0], radius=0.25)
  1424→  1424→}
  1425→  1425→```
  1426→  1426→
  1427→  1427→`axis` is `x`, `y`, or `z` (ident or string). The body is emitted twice —
  1428→  1428→once unchanged and once with the named axis negated. Use it for left/right
  1429→  1429→symmetry where only one side is authored by hand.
  1430→  1430→
  1431→  1431→Both copies share the body's node names, and both bind when the mesh
  1432→  1432→carries `skin="…"`.
  1433→  1433→
  1434→  1434→#### `flip_bind=1`: rebind the mirrored copy to the symmetric bone
  1435→  1435→
  1436→  1436→Module parameters are numeric-only, so skin-bound limb pairs that differ
  1437→  1437→**only** in their bone suffix (`shoulder_l` ↔ `shoulder_r`) can't be
  1438→  1438→DRY'd via a module. `flip_bind=1` solves it on `mirror`:
  1439→  1439→
  1440→  1440→```
  1441→  1441→mirror "sleeves" (axis=x, flip_bind=1) {
  1442→  1442→  chamfered_box "sleeve" (
  1443→  1443→    pos=[0.135, 0.695, 0], size=[0.052, 0.158, 0.052],
  1444→  1444→    skin="rig", bind="shoulder_l", faceted=1
  1445→  1445→  )
  1446→  1446→}
  1447→  1447→```
  1448→  1448→
  1449→  1449→emits the authored copy bound to `shoulder_l` AND a mirrored copy bound
  1450→  1450→to `shoulder_r`. The flip swaps a trailing `_l`/`_r` on the AST-resolved
  1451→  1451→`bind=` of every mesh-bearing descendant (authored locally or inherited
  1452→  1452→from a wrapping `group (bind=…)`). Binds without an `_l`/`_r` suffix pass
  1453→  1453→through unchanged. Defaults to `0`; ignored on `array`/`stack`/`grid`.
  1454→  1454→
  1455→  1455→### `array`
  1456→  1456→
  1457→  1457→```
  1458→  1458→array "legs" (count=4, around=y) {
  1459→  1459→  group "offset" (pos=[0.45, 0, 0.45]) {
  1460→  1460→    cylinder "leg" (radius=0.05, height=0.5)
  1461→  1461→  }
  1462→  1462→}
  1463→  1463→```
  1464→  1464→
  1465→  1465→Attributes:
  1466→  1466→
  1467→  1467→- `count` — number of copies (integer); default `1`.
  1468→  1468→- `around` — `x` / `y` / `z` ident; the rotation axis. Default `y`.
  1469→  1469→- `start_angle` — degrees offset of the first copy; default `0`.
  1470→  1470→
  1471→  1471→Children are cloned `count` times; the i-th copy is rotated by
  1472→  1472→`start_angle + 360° * i / count` around `around`. Wrap in an offset
  1473→  1473→`group` to place the first copy off-axis.
  1474→  1474→
  1475→  1475→### `stack`
  1476→  1476→
  1477→  1477→Lays children out along one axis using each child's computed AABB as its
  1478→  1478→slot — no manual half-size math.
  1479→  1479→
  1480→  1480→```
  1481→  1481→stack "cake" (axis=y, gap=0.02) {
  1482→  1482→  slab "tier_a" (size=[1.4, 0.25, 1.4])
  1483→  1483→  slab "tier_b" (size=[1.0, 0.20, 1.0])
  1484→  1484→  slab "tier_c" (size=[0.6, 0.15, 0.6])
  1485→  1485→}
  1486→  1486→```
  1487→  1487→
  1488→  1488→Attributes:
  1489→  1489→
  1490→  1490→| attribute | value | default | effect |
  1491→  1491→|---|---|---|---|
  1492→  1492→| `axis` | `x`, `y`, `z` | `y` | stacking direction |
  1493→  1493→| `gap` | number | `0` | spacing between consecutive children |
  1494→  1494→| `align` | `center`, `start`, `end` | `center` | alignment on the two perpendicular axes |
  1495→  1495→| `pack` | `start`, `center`, `end` | `start` | where the whole stack sits along `axis`: `start` keeps the first child at origin; `center` centres the stack; `end` puts the last child's far face at origin |
  1496→  1496→
  1497→  1497→Each child's `pos`/`x`/`y`/`z` is **additive** inside its slot.
  1498→  1498→
  1499→  1499→### `grid`
  1500→  1500→
  1501→  1501→N-dimensional replicator. Creates `count[0] × count[1] × count[2]` copies of
  1502→  1502→the body, each offset by `step[0..3] * [i, j, k]`:
  1503→  1503→
  1504→  1504→```
  1505→  1505→grid "tiles" (count=[5, 1, 3], step=[0.6, 0, 0.6], center=1) {
  1506→  1506→  slab "tile" (size=[0.55, 0.05, 0.55])
  1507→  1507→}
  1508→  1508→```
  1509→  1509→
  1510→  1510→Attributes:
  1511→  1511→
  1512→  1512→| attribute | value | default |
  1513→  1513→|---|---|---|
  1514→  1514→| `count` | vec3, list, or scalar | `[1, 1, 1]` |
  1515→  1515→| `step` | vec3, list, or scalar | `[0, 0, 0]` |
  1516→  1516→| `center` | `0` / `1` | `0` — when `1`, the grid is centred on the wrapper origin |
  1517→  1517→
  1518→  1518→A scalar `count`/`step` applies to X (1D rows); a 2-element list to X/Z
  1519→  1519→(floor patterns); a vec3 for 3D.
  1520→  1520→
  1521→  1521→---
  1522→  1522→
  1523→  1523→## CSG: `union` / `difference` / `intersect`
  1524→  1524→
  1525→  1525→CSG ops fold their children into a single mesh that hangs off the op node
  1526→  1526→itself — the operand children do not become separate scene nodes.
  1527→  1527→
  1528→  1528→```
  1529→  1529→difference "wall_with_door" (mat="concrete") {
  1530→  1530→  box "wall"    (size=[4.0, 3.0, 0.2])
  1531→  1531→  box "doorway" (pos=[0, -0.5, 0], size=[0.9, 2.0, 0.5])
  1532→  1532→}
  1533→  1533→```
  1534→  1534→
  1535→  1535→- `union` — N ≥ 1 operands. Optional `smooth=<radius>` swaps boolean union
  1536→  1536→  for an `smin` blend (used by humanoid stdlib for limb-to-torso fillets;
  1537→  1537→  a few cm at human scale). `smooth=0` (default) is the hard boolean.
  1538→  1538→- `difference` — first operand minus every subsequent operand.
  1539→  1539→- `intersect` — N ≥ 2 operands; the shared volume.
  1540→  1540→
  1541→  1541→Operand transforms bake into vertices at eval time. Connectors / `material`
  1542→  1542→children on the CSG node apply; those on operands are ignored. Output is
  1543→  1543→cleaned (weld, degen-tri cull, normal recompute) for a watertight mesh.
  1544→  1544→
  1545→  1545→---
  1546→  1546→
  1547→  1547→## Implicit-field blob: `blob`
  1548→  1548→
  1549→  1549→`blob { … }` meshes its children as a true SDF field via surface nets —
  1550→  1550→distinct from both `metaball` (sphere-cluster on a vertex-fillet approximate
  1551→  1551→union) and `union(smooth=k)` (vertex-fillet pull applied to a sharp mesh
  1552→  1552→CSG). Use `blob` whenever you want **smooth concave junctions** —
  1553→  1553→eye sockets melted into a cranium, the cleft of a heart, a nostril dipping
  1554→  1554→into a snout. The vertex-fillet path breaks down on concave junctions and
  1555→  1555→large blend radii; `blob` does not.
  1556→  1556→
  1557→  1557→```
  1558→  1558→blob "heart" (blend=0.22, resolution=80, subdivide=1, mat="heart") {
  1559→  1559→  sphere    (radius=0.45, pos=[-0.30, 0.32, 0])      // left lobe
  1560→  1560→  sphere    (radius=0.45, pos=[ 0.30, 0.32, 0])      // right lobe
  1561→  1561→  ellipsoid (size=[0.85, 1.00, 0.85], pos=[0, -0.25, 0])   // apex
  1562→  1562→  sphere    (radius=0.20, pos=[0, 0.58, 0], op=subtract)   // cleft
  1563→  1563→}
  1564→  1564→```
  1565→  1565→
  1566→  1566→### Attributes
  1567→  1567→
  1568→  1568→- `blend` — smooth-min radius in scene units. `0` collapses to a sharp
  1569→  1569→  union. Typical organic values: `0.05–0.25`. Higher = more melt.
  1570→  1570→- `resolution` — voxels along the longest world-space axis of the AABB
  1571→  1571→  enclosing every additive child (plus padding). Default `96`; clamped to
  1572→  1572→  `[16, 256]`. Cost scales O(N³); `128` is usually plenty. Scales with the
  1573→  1573→  active `lod_scale` (linear) and per-node `lod=`.
  1574→  1574→- `subdivide` — optional Loop subdivision count applied to the surface-nets
  1575→  1575→  output. Default `0` (surface nets is already clean enough for most uses);
  1576→  1576→  bump to `1` only when you need extra shading smoothness. Stepped by
  1577→  1577→  `round(log2(lod_scale))`, capped at 3. See
  1578→  1578→  [Mesh subdivision](#mesh-subdivision-subdivide).
  1579→  1579→- `mat`, `pos`, `rot`, `scale`, `role`, `tags` — same as any other mesh node.
  1580→  1580→
  1581→  1581→### Children
  1582→  1582→
  1583→  1583→Only implicit-field primitives are allowed inside a `blob`:
  1584→  1584→
  1585→  1585→| kind | attrs | SDF |
  1586→  1586→|---|---|---|
  1587→  1587→| `sphere` | `radius` | sphere |
  1588→  1588→| `ellipsoid` | `size=[x,y,z]` | axis-aligned ellipsoid (radii are `size/2`) |
  1589→  1589→| `box` | `size=[x,y,z]` | axis-aligned box |
  1590→  1590→| `rounded_box` | `size`, `radius` | box with rounded edges |
  1591→  1591→| `capsule` | `radius`, `height` | Y-axis capsule (caps at `±height/2 + radius`) |
  1592→  1592→| `cylinder` | `radius`, `height` | Y-axis closed cylinder |
  1593→  1593→| `torus` | `major`, `minor` | torus in XZ plane |
  1594→  1594→
  1595→  1595→Each child accepts `pos` / `rot` / `scale`, which set the local-to-blob
  1596→  1596→transform applied before SDF evaluation. Non-uniform `scale` is allowed
  1597→  1597→(distances are compressed by the smallest scale axis as a conservative
  1598→  1598→Lipschitz fix); for elongated shapes prefer `ellipsoid` over a scaled
  1599→  1599→`sphere`.
  1600→  1600→
  1601→  1601→The optional `op="subtract"` (synonyms: `"sub"`, `"carve"`) makes the child
  1602→  1602→a smooth carver instead of an additive mass. At least one additive child
  1603→  1603→is required — a blob of only subtracts has nothing to carve into.
  1604→  1604→
  1605→  1605→### Notes
  1606→  1606→
  1607→  1607→- Output is one mesh, one node. Children do not become separate scene nodes.
  1608→  1608→- The mesh is always watertight (surface nets closes any iso it extracts).
  1609→  1609→- UVs are bbox-projected (XZ planar). Pair with `uv_mode="tile"` for
  1610→  1610→  tileable surface textures; fitted image textures will project from above.
  1611→  1611→- A `blob` without `subdivide` shows mild stairstepping from the voxel
  1612→  1612→  grid; one round of Loop subdivision polishes it. Two rounds is glassy
  1613→  1613→  but quadruples tri count.
  1614→  1614→
  1615→  1615→See [`examples/nature/skull.mog`](../examples/nature/skull.mog) and
  1616→  1616→[`examples/nature/heart.mog`](../examples/nature/heart.mog) for full
  1617→  1617→worked examples.
  1618→  1618→
  1619→  1619→---
  1620→  1620→
  1621→  1621→## Mesh subdivision: `subdivide`
  1622→  1622→
  1623→  1623→Add `subdivide = N` to any mesh-producing node — primitives (`sphere`,
  1624→  1624→`box`, `lathe`, …), CSG ops (`union` / `difference` / `intersect`), or
  1625→  1625→`blob` — to run `N` rounds of Loop subdivision on the resulting mesh
  1626→  1626→before it is attached to the scene graph. Each round splits every
  1627→  1627→triangle into four; `N` is clamped to `[0, 3]` so the cap is `64×` the
  1628→  1628→input triangles.
  1629→  1629→
  1630→  1630→```
  1631→  1631→union (subdivide=1, mat="bone") {
  1632→  1632→  sphere    (radius=0.5)
  1633→  1633→  ellipsoid (size=[0.6, 0.4, 0.8], pos=[0, -0.3, 0])
  1634→  1634→}
  1635→  1635→```
  1636→  1636→
  1637→  1637→Use `subdivide` to polish staircased blob outputs, smooth a low-poly
  1638→  1638→primitive without re-tessellating it (`icosphere(radius=1, subdivide=2)`
  1639→  1639→is often nicer than `icosphere(subdivisions=4)` because Loop smooths
  1640→  1640→existing topology), or refine a CSG output for shading. It is a no-op on
  1641→  1641→container kinds with no own mesh (`group`, `scene`, `mirror`, `array`,
  1642→  1642→`stack`, `grid`).
  1643→  1643→
  1644→  1644→---
  1645→  1645→
  1646→  1646→## Solid groups: `solid`
  1647→  1647→
  1648→  1648→`solid { … }` is a group-like container that defers CSG union to export time.
  1649→  1649→Its same-material, non-skinned leaf children are merged into a single mesh,
  1650→  1650→so overlapping or touching primitives of the same material read as one hollow
  1651→  1651→shape — interior faces where pieces meet get eliminated.
  1652→  1652→
  1653→  1653→```
  1654→  1654→solid "shell" (mat="stone", cleanup="coplanar") {
  1655→  1655→  box "floor"   (pos=[0, 0.1, 0],   size=[6.2, 0.2, 4.2])
  1656→  1656→  box "north"   (pos=[0, 1.7, 2.0], size=[6.0, 3.0, 0.2])
  1657→  1657→  box "south"   (pos=[0, 1.7,-2.0], size=[6.0, 3.0, 0.2])
  1658→  1658→  box "east"    (pos=[ 3.0, 1.7, 0], size=[0.2, 3.0, 4.0])
  1659→  1659→  box "west"    (pos=[-3.0, 1.7, 0], size=[0.2, 3.0, 4.0])
  1660→  1660→}
  1661→  1661→```
  1662→  1662→
  1663→  1663→- Children lower as normal scene nodes (still `attach`-able, still
  1664→  1664→  editable); the merge is export-time only.
  1665→  1665→- Only same-material leaf siblings merge. Different-material children stay
  1666→  1666→  separate so textures/PBR factors are preserved.
  1667→  1667→- Skinned meshes, joint-referenced nodes, and groups pass through unchanged.
  1668→  1668→
  1669→  1669→### `cleanup="coplanar"`
  1670→  1670→
  1671→  1671→Drops triangle pairs that share a plane with opposite normals — fixes the
  1672→  1672→"two boxes touch but don't overlap" case (perpendicular walls at a corner)
  1673→  1673→that CSG union alone can't resolve. Values: `"coplanar"` or `"none"`
  1674→  1674→(default).
  1675→  1675→
  1676→  1676→---
  1677→  1677→
  1678→  1678→## Modules: `module` and `use`
  1679→  1679→
  1680→  1680→Modules are parametric sub-graphs. A declaration lives at the top level of
  1681→  1681→the file:
  1682→  1682→
  1683→  1683→```
  1684→  1684→module "leg" (height=0.5, radius=0.05) {
  1685→  1685→  cylinder "leg" (pos=[0, $height * 0.5, 0],
  1686→  1686→                  radius=$radius, height=$height, mat="wood") {
  1687→  1687→    connector "top" (at=[0, $height * 0.5, 0], dir=[0, 1, 0], tag=leg_top)
  1688→  1688→  }
  1689→  1689→}
  1690→  1690→```
  1691→  1691→
  1692→  1692→Parameters:
  1693→  1693→
  1694→  1694→- Defaults are either scalars (number or `$param`-expression) or constant
  1695→  1695→  `vec3`s. vec3 defaults must be fully constant (no cross-param refs).
  1696→  1696→  `list`/string/ident defaults are rejected.
  1697→  1697→- Reference inside the body as `$name`, including nested vec3 expressions
  1698→  1698→  like `[0, $h * 0.5, 0]`.
  1699→  1699→
  1700→  1700→Invoke with `use`:
  1701→  1701→
  1702→  1702→```
  1703→  1703→scene {
  1704→  1704→  array "legs" (count=4, around=y) {
  1705→  1705→    group "offset" (pos=[0.45, 0, 0.45]) {
  1706→  1706→      use "leg" (height=0.5, radius=0.05)
  1707→  1707→    }
  1708→  1708→  }
  1709→  1709→}
  1710→  1710→```
  1711→  1711→
  1712→  1712→Rules: `use` takes the **declared** name (unknowns error); omitted args
  1713→  1713→fall back to defaults (unknown arg names error); modules can call modules
  1714→  1714→(recursion rejected); `$param` outside a module body is rejected.
  1715→  1715→
  1716→  1716→## Control flow: `if`, `else`, `for`, string interpolation
  1717→  1717→
  1718→  1718→Inside any `{ … }` body, three control-flow constructs branch/repeat at
  1719→  1719→module-expansion time. They run before lowering, so the resulting scene
  1720→  1720→graph never sees `if` or `for`; only the geometry they emit.
  1721→  1721→
  1722→  1722→### `if (cond=…)` and `else`
  1723→  1723→
  1724→  1724→`cond=` accepts any expression; comparisons evaluate to `1.0`/`0.0`. An
  1725→  1725→immediately-following sibling `else { … }` covers the false branch; a
  1726→  1726→standalone `else` is rejected.
  1727→  1727→
  1728→  1728→```
  1729→  1729→if (cond=$is_glass) {
  1730→  1730→  box "pane" (size=[0.6, 1.0, 0.01], mat="glass")
  1731→  1731→}
  1732→  1732→else {
  1733→  1733→  box "panel" (size=[0.6, 1.0, 0.04], mat="oak")
  1734→  1734→}
  1735→  1735→```
  1736→  1736→
  1737→  1737→### `for (var=…, from=…, to=…[, step=…])`
  1738→  1738→
  1739→  1739→```
  1740→  1740→for (var="i", from=0, to=4) {
  1741→  1741→  box "fence_post_$i" (size=[0.04, 0.6, 0.04],
  1742→  1742→                       pos=[$i * 0.30, 0, 0], mat="oak")
  1743→  1743→}
  1744→  1744→```
  1745→  1745→
  1746→  1746→- `var` is a string or bare ident; `$<var>` resolves to the loop value.
  1747→  1747→- Iteration covers `[from, to)` (Python-style); `from == to` is empty.
  1748→  1748→- `step` defaults to `1.0`, must be non-zero; negative walks downward.
  1749→  1749→- Module parameters and the loop var coexist; nested `for`s compose.
  1750→  1750→
  1751→  1751→### String interpolation
  1752→  1752→
  1753→  1753→Inside any string literal (including node names), `$name`/`${name}` are
  1754→  1754→replaced with the binding's value at expansion time. Integer bindings
  1755→  1755→render without a decimal (`leg_$i` → `leg_3`, not `leg_3.0`). `${name}`
  1756→  1756→disambiguates when followed by `_` etc. A `$` with no identifier or
  1757→  1757→unbound name is left literal.
  1758→  1758→
  1759→  1759→```
  1760→  1760→for (var="i", from=0, to=3) {
  1761→  1761→  cylinder "leg_$i" (radius=0.05, height=0.6, pos=[$i * 0.4, 0, 0])
  1762→  1762→}
  1763→  1763→// Names: leg_0, leg_1, leg_2
  1764→  1764→```
  1765→  1765→
  1766→  1766→Limitations: no chained comparisons (use `*` for AND, `+` for OR), no
  1767→  1767→boolean `&&`/`||`/`!`, no string concat beyond interpolation.
  1768→  1768→
  1769→  1769→---
  1770→  1770→
  1771→  1771→## Imports: `import`
  1772→  1772→
  1773→  1773→Pull `module` declarations, `material` declarations, and the top-level
  1774→  1774→`scene { … }` of another `.mog` file into the current file. The imported
  1775→  1775→scene becomes an implicit module named after the file stem, so
  1776→  1776→`import "chair.mog"` lets you `use "chair" ()`.
  1777→  1777→
  1778→  1778→```
  1779→  1779→import "shared/legs.mog"
  1780→  1780→import "objects/chair.mog"
  1781→  1781→
  1782→  1782→scene {
  1783→  1783→  use "leg"   (h=0.6)
  1784→  1784→  use "chair" (pos=[ 1, 0, 0])
  1785→  1785→  use "chair" (pos=[-1, 0, 0], rot=[0, 180, 0])
  1786→  1786→}
  1787→  1787→```
  1788→  1788→
  1789→  1789→`use` accepts the standard transform shortcuts (`pos`, `rot`, `scale`,
  1790→  1790→`x`/`y`/`z`, `rx`/`ry`/`rz`, `from`/`to`) and applies them as an implicit
  1791→  1791→wrapping group. If the module declares a parameter with one of those
  1792→  1792→names, the caller's value binds to the parameter instead.
  1793→  1793→
  1794→  1794→`import` is a top-level directive. Takes a quoted file path and an
  1795→  1795→optional `(as=<ident>)` to override the synthesised module name.
  1796→  1796→
  1797→  1797→Path resolution: relative paths join onto the importing file's directory;
  1798→  1798→absolute paths are used verbatim; paths are canonicalised before
  1799→  1799→deduplication (so `"lib.mog"` and `"./lib.mog"` load once).
  1800→  1800→
  1801→  1801→What gets lifted:
  1802→  1802→
  1803→  1803→- **`module` declarations** — added to the importer's module registry.
  1804→  1804→- **`material` declarations** (top-level or inside the imported scene) —
  1805→  1805→  added to the material registry. Texture paths are rooted at the
  1806→  1806→  *defining* file's directory.
  1807→  1807→- **Top-level `scene { … }`** — synthesised as `module "<stem>" () { … }`.
  1808→  1808→
  1809→  1809→Rules:
  1810→  1810→
  1811→  1811→- Imports are transitive; cycles are rejected with the chain in the error;
  1812→  1812→  double-import is a no-op.
  1813→  1813→- Module shadowing: **stdlib < imports < user declarations**.
  1814→  1814→- Synthesised scene-as-module name collisions across imports are a hard
  1815→  1815→  error — rename one with `(as=chair_a)`.
  1816→  1816→- Material name collisions across imports are a hard error — re-declare
  1817→  1817→  the material in the importer to shadow.
  1818→  1818→- Imported files may contain only `import`, `module`, `material`, and one
  1819→  1819→  top-level `scene { … }`. Joints, clips, skeletons aren't composable yet.
  1820→  1820→
  1821→  1821→---
  1822→  1822→
  1823→  1823→## Animation: `joint`, `clip`, templates
  1824→  1824→
  1825→  1825→Animation lowers to glTF node-transform tracks. Every clip animates scene
  1826→  1826→nodes (or joints — scene-node aliases with a typed DOF). Clips are
  1827→  1827→top-level alongside `material`/`module`/`joint`. Skinning is additive
  1828→  1828→(see [Skeletons](#skeletons-and-skinning-skeleton-bone-skin-bind)).
  1829→  1829→
  1830→  1830→### Joints
  1831→  1831→
  1832→  1832→A `joint` names an articulation, picks a DOF type, and points at the scene
  1833→  1833→node it drives.
  1834→  1834→
  1835→  1835→```
  1836→  1836→joint "door_hinge" (type=hinge, axis=[0, 1, 0], limits=[0, 100], pivot="door")
  1837→  1837→```
  1838→  1838→
  1839→  1839→| attribute | value | notes |
  1840→  1840→|---|---|---|
  1841→  1841→| `type` | `hinge`, `slider`, `ball`, `rotor` | DOF kind |
  1842→  1842→| `pivot` | string — a node name | required |
  1843→  1843→| `axis` | vec3 | default `[0, 1, 0]` |
  1844→  1844→| `limits` | `[lo, hi]` list | optional; degrees (rotary) or meters (slider) |
  1845→  1845→
  1846→  1846→### Authored clips
  1847→  1847→
  1848→  1848→```
  1849→  1849→clip "open" (seconds=1.0) {
  1850→  1850→  track "door_hinge" (from=0, to=90)
  1851→  1851→}
  1852→  1852→```
  1853→  1853→
  1854→  1854→- `clip` holds a single `seconds=` duration and an ordered list of `track`s.
  1855→  1855→- `track` targets a joint (by name) or a scene node. For nodes, set
  1856→  1856→  `prop="translation"|"rotation"|"scale"` (`pos`/`rot` aliases accepted).
  1857→  1857→- `from`/`to` are scalars: degrees for rotation (around the joint's `axis`
  1858→  1858→  or the track's `axis=`), distance for translation, factor for scale.
  1859→  1859→  Emits two keyframes at `0` and `seconds`, linearly interpolated.
  1860→  1860→- For multi-keyframe curves, pass `keys=[[t, v], …]` (strictly ascending
  1861→  1861→  times in `[0, seconds]`). One glTF keyframe per pair, linear between.
  1862→  1862→
  1863→  1863→### Easing
  1864→  1864→
  1865→  1865→`track` and procedural templates accept `easing=` for non-linear curves.
  1866→  1866→glTF samplers only support LINEAR/STEP/CUBICSPLINE, so MoGen bakes the
  1867→  1867→easing into dense LINEAR samples at lower time. For authored tracks,
  1868→  1868→easing applies between consecutive keys; for templates, it warps the
  1869→  1869→procedural phase.
  1870→  1870→
  1871→  1871→| name | shape |
  1872→  1872→|---|---|
  1873→  1873→| `linear` (default) | t |
  1874→  1874→| `ease_in` / `ease_out` / `ease_in_out` | quadratic |
  1875→  1875→| `ease_in_cubic` / `ease_out_cubic` / `ease_in_out_cubic` | cubic |
  1876→  1876→| `ease_in_sine` / `ease_out_sine` / `ease_in_out_sine` | half-cosine |
  1877→  1877→| `ease_in_back` / `ease_out_back` / `ease_in_out_back` | overshoots the endpoint |
  1878→  1878→| `ease_in_bounce` / `ease_out_bounce` / `ease_in_out_bounce` | multi-stage bounce |
  1879→  1879→
  1880→  1880→```
  1881→  1881→clip "hop" (seconds=0.6) {
  1882→  1882→  track "body" (prop=translation, axis=[0, 1, 0],
  1883→  1883→                easing=ease_out_bounce, from=0, to=0.4)
  1884→  1884→}
  1885→  1885→spin "fan" (target="rotor", rpm=120, easing=ease_in_out_sine)
  1886→  1886→```
  1887→  1887→
  1888→  1888→### Procedural templates
  1889→  1889→
  1890→  1890→One-line declarations that expand into a full clip. They all take a
  1891→  1891→`target="name"` pointing at a joint or a scene node.
  1892→  1892→
  1893→  1893→| template | extra attrs | effect |
  1894→  1894→|---|---|---|
  1895→  1895→| `spin` | `axis`, `rpm` (60), `easing` | continuous rotation |
  1896→  1896→| `open_close` | `axis`, `angle` (90), `seconds` (1.0), `easing` | 0° → angle → 0° swing |
  1897→  1897→| `wave` | `axis`, `amplitude` (15°), `hz` (1.0), `easing` | sinusoidal wobble |
  1898→  1898→| `flap` | `axis`, `amplitude` (30°), `hz` (2.0), `easing` | faster wobble, bigger amplitude |
  1899→  1899→| `idle` | `amplitude` (0.02 m), `hz` (0.5), `easing` | tiny translation breathe |
  1900→  1900→
  1901→  1901→When the target is a joint, its `axis` is used by default; when it's a node,
  1902→  1902→pass `axis` explicitly.
  1903→  1903→
  1904→  1904→```
  1905→  1905→spin "rotor_spin" (target="rotor", axis=[0, 0, 1], rpm=30)
  1906→  1906→open_close "door_swing" (target="door_hinge", angle=90, seconds=1.2)
  1907→  1907→```

  1911→  1911→## Skeletons and skinning: `skeleton`, `bone`, `skin=`, `bind=`
  1912→  1912→
  1913→  1913→A `skeleton` is a hierarchy of named `bone` nodes that drives skinning
  1914→  1914→weights on procedural meshes. Bones are ordinary scene nodes (`kind="bone"`);
  1915→  1915→the skeleton block produces a `Skin` whose `joints` list captures every
  1916→  1916→descendant bone in depth-first order. Bind-pose inverse matrices are
  1917→  1917→computed automatically from the bones' world transforms at lower time, so
  1918→  1918→the author never writes a `Mat4`.
  1919→  1919→
  1920→  1920→```
  1921→  1921→scene {
  1922→  1922→  skeleton "rig" {
  1923→  1923→    bone "hip"      (pos=[0, 0.95, 0], envelope=0.25) {
  1924→  1924→      bone "spine"  (pos=[0, 0.30, 0], envelope=0.25) {
  1925→  1925→        bone "neck" (pos=[0, 0.30, 0], envelope=0.10)
  1926→  1926→      }
  1927→  1927→      bone "thigh_l" (pos=[ 0.10, -0.05, 0], envelope=0.25)
  1928→  1928→      bone "thigh_r" (pos=[-0.10, -0.05, 0], envelope=0.25)
  1929→  1929→    }
  1930→  1930→  }
  1931→  1931→
  1932→  1932→  capsule "torso" (pos=[0, 1.25, 0], radius=0.18, height=0.6,
  1933→  1933→                   mat="cloth", skin="rig")
  1934→  1934→  sphere  "head"  (pos=[0, 1.7,  0], radius=0.12, mat="skin",
  1935→  1935→                   skin="rig", bind="neck")
  1936→  1936→}
  1937→  1937→```
  1938→  1938→
  1939→  1939→### `skeleton` and `bone`
  1940→  1940→
  1941→  1941→- `skeleton "name" { … }` — declares the rig. Every child must be a
  1942→  1942→  `bone`. Bones nest arbitrarily; `pos`/`rot`/`scale` are parent-relative.
  1943→  1943→- `bone "name" (pos, rot, scale, envelope)` — declares a joint.
  1944→  1944→  `envelope=` (default `0.75`) is the auto-skinner's influence radius;
  1945→  1945→  smaller = tighter, larger = blends across more joints. Adjacent bones
  1946→  1946→  should overlap in envelope.
  1947→  1947→
  1948→  1948→Skeletons are top-level or scene-level; they place themselves in the
  1949→  1949→scene tree but carry no geometry.
  1950→  1950→
  1951→  1951→### Binding meshes: `skin="rig"`
  1952→  1952→
  1953→  1953→Any mesh-bearing node with `skin="<skel name>"` becomes skinned: lowering
  1954→  1954→walks the skeleton, computes weights against the four nearest bones
  1955→  1955→(capped by `envelope`), and writes `JOINTS_0`/`WEIGHTS_0` accessors.
  1956→  1956→Group-like containers (`group`, `solid`, `stack`, `grid`, `array`,
  1957→  1957→`mirror`, `module`, `use`) propagate `skin=` to every mesh descendant.
  1958→  1958→
  1959→  1959→### Rigid pinning: `bind="bone_name"`
  1960→  1960→
  1961→  1961→`bind="bone"` alongside `skin=` pins every vertex rigidly to a single
  1962→  1962→bone (weight 1.0, no envelope blend) — accessories that track a joint
  1963→  1963→without deforming: heads, helmets, backpacks, hand-held props. Propagates
  1964→  1964→through groups like `skin=`. For `_l`/`_r` pairs, wrap one side in
  1965→  1965→`mirror (axis=x, flip_bind=1)` (see [`mirror`](#mirror)).
  1966→  1966→
  1967→  1967→### Animating bones
  1968→  1968→
  1969→  1969→Bones are scene nodes — drive them with regular `clip { track … }`:
  1970→  1970→`track "thigh_l" (prop=rotation, axis=[1, 0, 0], keys=[…])`. Stdlib
  1971→  1971→`humanoid_walk`/`humanoid_run`/`humanoid_idle`/`humanoid_jump` expand
  1972→  1972→into this shape against `humanoid_full`'s bones.
  1973→  1973→
  1974→  1974→`skin=` on a CSG operand is lost (operands are fused into the parent's
  1975→  1975→mesh); put it on the CSG node or a wrapping group.
  1976→  1976→
  1977→  1977→---
  1978→  1978→
  1979→  1979→## Lights: `light`
  1980→  1980→
  1981→  1981→Exported via glTF `KHR_lights_punctual`. A `light` is a transform-only
  1982→  1982→scene node — no mesh, no children. Direction is implicit (along local `-Z`).
  1983→  1983→
  1984→  1984→```
  1985→  1985→light "sun"  (kind=directional, dir=[-0.4, -1, -0.3], color=[1, 0.95, 0.85], intensity=3)
  1986→  1986→light "lamp" (kind=point, pos=[0, 2, 0], color=[1, 0.9, 0.7], intensity=10, range=8)
  1987→  1987→light "spot" (kind=spot,  pos=[0, 3, 0], dir=[0, -1, 0], intensity=20,
  1988→  1988→              range=10, inner_cone=20, outer_cone=35)
  1989→  1989→```
  1990→  1990→
  1991→  1991→| attribute | value | notes |
  1992→  1992→|---|---|---|
  1993→  1993→| `kind` | `directional`, `point`, `spot` | required |
  1994→  1994→| `color` | vec3 | linear-space RGB; default `[1, 1, 1]` |
  1995→  1995→| `intensity` | number | **candela** for point/spot, **lux** for directional; default `1.0` |
  1996→  1996→| `range` | number | distance cutoff for point/spot; rejected on directional |
  1997→  1997→| `dir` | vec3 | optional shortcut: rotates the node so `-Z` points along `dir` (overrides `rot=`) |
  1998→  1998→| `inner_cone` | number | spot only; degrees, default `0` |
  1999→  1999→| `outer_cone` | number | spot only; degrees, default `45` |
  2000→  2000→
